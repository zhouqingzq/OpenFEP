# OpenFEP M18.3 Work Prompt

## Milestone

M18.3: Group Transcript Ownership And Durable Replay

## Goal

Make the transcript itself a reliable multi-party artifact instead of a mostly
single-interlocutor conversation log.

This milestone owns row schema, persistence, replay, and compatibility
migration. It does not own participant inference policy or reply selection.

## Required Work

### 1. Add first-class speaker ownership to transcript rows

Every human turn must preserve:

```text
speaker identity
reply target if known
thread linkage if known
turn-local participant set
```

At minimum, the persisted row contract should have stable references to M18.1
participants and M18.2 bindings, for example:

```text
speaker_participant_id
addressed_participant_ids?
mentioned_participant_ids?
reply_to_turn_id?
binding_snapshot_ref?
```

### 2. Make prompt-safe replay preserve that ownership

Conscious loop, memory guidance, and replay consumers must receive structured
speaker ownership, not only raw text.

### 3. Persist and restore the same structure

After restart, replaying the stored transcript must recover the same group turn
ownership.

### 4. Keep old single-user sessions loadable

Compatibility migration is required.

Older rows that only know `user` or `interlocutor` may be loaded through a
compatibility adapter, but the adapter must mark ownership certainty honestly
and must not masquerade as native multi-party evidence.

## Acceptance

This milestone is complete only if:

- transcript storage no longer flattens all human turns into one generic role
- replay consumers can see speaker ownership
- restart preserves multi-party structure
- at least one test covers loading legacy single-user rows into the new schema
  without falsely claiming native group ownership
- migration from old transcript rows is covered by tests
