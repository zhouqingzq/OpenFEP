# OpenFEP M14.4 Work Prompt

## Milestone

M14.4: Streamlit Implicit Idle Proactive Delivery

## Goal

Ship the product behavior the Hu Tao MVP chat page is still missing:

```text
User keeps the Streamlit chat page open
+ no new user message for idle_threshold_seconds
+ MVP chat path active
-> one bounded proactive assistant message may appear
-> without pressing "让胡桃继续"
-> without requiring M14.2 daemon or overnight outbox
```

This milestone closes the **integration gap**, not a new cognition module. M13.3
already implements `evaluate_proactive_initiative(..., implicit_idle_request=True)`
and `run_proactive_turn`. Today nothing in `app.py` calls that path on Streamlit
reruns; only `manual_continue=True` and queued-outreach drain are wired.

Target posture for the current product experiment (explicitly **not** the final
production safety posture):

```text
implicit_idle_delivery defaults to true when bounded proactive is enabled
proactive policy profile "streamlit_open_chat" relaxes:
  - session proactive cap
  - turn cooldown
  - cooldown_until_timestamp gate
while still enforcing:
  - delivery assessor
  - reply validation
  - safety / opponent-strength pre-block
  - user_typing / pending_user_message / turn-in-progress guards
```

M14.4 does **not** require M13.6 memory-EFE outreach or M14.3 traceability
alignment to land first. Those milestones refine *why* outreach fires; M14.4
wires *that it can fire at all* on an open chat page after silence.

## Architecture Position

```text
Streamlit rerun (chat page open, no pending user send)
-> compute idle_seconds from temporal_state.last_user_turn_at
-> evaluate_proactive_initiative(implicit_idle_request=True, idle_seconds=...)
   [policy profile may bypass session/cooldown caps]
-> if proposal: run_proactive_turn -> append assistant bubble
-> audit M13Proactive* events + compact UI diagnostics
```

Remain Path B. Do not add a second generation stack. Do not bypass M13.3
`run_proactive_turn` or delivery assessor.

```text
NOT in scope for M14.4:
  - push notifications when browser closed (M14.2 outbox path stays separate)
  - M13.6 memory-backed expectation requirement for every proactive message
  - removing safety or delivery assessor gates
```

## Dependencies

M14.4 builds on:

- M13.3 bounded initiative (`maybe_propose_proactive_turn`, `run_proactive_turn`)
- M13.4 idle tick helpers (temporal idle elapsed; optional, not required for outreach)
- existing Streamlit `ChatInterface` + `MVPDialogueRuntime`
- M14.2 `OutboxDeliverySurfaceAvailableEvent` drain (keep; run before implicit idle)

Optional but not blocking:

- M14.0 idle introspection (decouple from M14.4; introspection must not be the
  only path that can trigger implicit delivery)
- M13.6 / M14.3 (improve targeting later; M14.4 may still fire on
  `open_item_next_check` / `boredom_exploration_target` when structural pick succeeds)

## Non-Goals

- Do not implement always-on daemon outreach (M14.2 remains separate).
- Do not remove delivery assessor or reply validation.
- Do not claim subjective loneliness/need in engineering audit fields.
- Do not wire `implicit_idle_request` only inside M14.0 LLM outreach recommendation
  (that leaves the common case where reflector returns `reflection_only`).
- Do not increase boredom or social PE from `silence_seconds` alone.
- Do not unify Path A and Path B.

## M14.6 Addendum: Multi-Motive No-Agreement Proactive

No-agreement proactive delivery is a Path B M13 synthesis, not a single
boredom gate and not a pure silence timer. Silence only opens the idle phase:
the runtime must refresh persisted M13 state, bounded recall, idle
`evaluate_memory_efe`, and compact drive bands before `select_proactive_target`.

Allowed no-agreement target kinds must remain traceable and flow through the
existing M13.3 proposal and delivery path:

```text
memory_efe_outreach              # memory dynamics / prediction tension
relationship_reconnect_pull      # relationship value memory + relation/path pull
affective_path_stale_proactive   # stale or unsettled affective path with refs
boredom_exploration_target       # M13.1 exploration target with evidence refs
```

Each target records `source_kind`, `selection_reason_codes`, and evidence refs.
Engineering fields use operational language such as
`relationship_reconnect_pull` and `path_feels_stale_proxy`; visible persona
wording is generated later by the LLM and remains subject to delivery assessor,
reply validation, and opponent-strength pre-block.

## Required Work

### 1. Add Proactive Policy Profile

Extend `m13_drive_state.initiative` with:

```text
proactive_policy_profile: "bounded_default" | "streamlit_open_chat"
```

Behavior:

```text
bounded_default:
  existing M13.3 caps (max_proactive_per_session, cooldown_turns, cooldown_until)

streamlit_open_chat:
  skip session_limit_reached check
  skip cooldown_active check (both timestamp and turn-index forms)
  still apply all safety, assessor, user_active, implicit_idle_delivery,
  idle_time_too_short, and structural-target gates
```

Profile is selected by:

- explicit UI dev toggle in sidebar (recommended), and/or
- environment flag `SEGMENTUM_PROACTIVE_PROFILE=streamlit_open_chat` for local demos

Default for new sessions in local MVP chat:

```text
user_opt_in = true
enabled = true
implicit_idle_delivery = true
proactive_policy_profile = "streamlit_open_chat"
```

Persist profile in `m13_drive_state`; normalize on load. Document that production
deployments should revert to `bounded_default`.

### 2. Change Initiative Defaults (Initiative State Only)

Update `default_initiative_state()` / `normalize_initiative_state()`:

```text
implicit_idle_delivery = true   # was false
```

When `set_initiative_user_opt_in(False)`:

```text
implicit_idle_delivery = false
proactive_policy_profile resets to "bounded_default" (or unchanged but inactive)
```

Do **not** globally set `user_opt_in=true` in code defaults without UI sync;
instead, on first MVP chat load with LLM active, Streamlit should call
`set_bounded_proactive_opt_in(True)` and `set_implicit_idle_delivery(True)` once
per session bootstrap (see §4).

### 3. Streamlit Implicit Idle Proactive Tick

Add `segmentum/dialogue/runtime/m14_4_implicit_idle.py` (or equivalent) with:

```text
compute_idle_seconds(state, *, now) -> float
should_attempt_implicit_idle_proactive(session_state, *, now_mono) -> bool
run_streamlit_implicit_idle_proactive(chat_iface, ...) -> ImplicitIdleProactiveResult
```

`compute_idle_seconds`:

```text
idle_seconds = max(0, now - last_user_turn_at)
last_user_turn_at from temporal_state; fallback last_turn_at if needed
```

`should_attempt_implicit_idle_proactive` guards:

```text
MVP runtime active
initiative.user_opt_in and initiative.enabled
initiative.implicit_idle_delivery
not pending_user_message
not pending_proactive_continue
not m13_ui_turn_in_progress
throttle: min interval between attempts (default 45s monotonic)
idle_seconds >= initiative.idle_threshold_seconds (default 120; configurable in UI)
```

Wire into `app.py` chat render path **after** queued-outreach drain and **before
or after** `_maybe_run_streamlit_idle_introspection`, but **independent** of
`m13_idle_introspection_opt_in`.

On success path:

```text
check = chat_iface.maybe_propose_proactive_turn(
    implicit_idle_request=True,
    idle_seconds=idle_seconds,
    user_typing=bool(pending_text),
)
if proposal:
    resp = chat_iface.run_proactive_turn(proposal_id, speaker_name=...)
    append_assistant_response_messages(messages, resp)
    st.rerun()
```

On suppression:

```text
append compact engineering-only row to inner-world / sidebar expander optional
do not spam chat with "未发送主动消息" every rerun; throttle suppression UI notes
```

### 6. Throttle And Rerun Safety

Streamlit reruns are not a clock. Requirements:

```text
_use monotonic throttle for implicit idle proactive attempts (45s default)
_do not call run_proactive_turn more than once per successful proposal per throttle window
_if rerun occurs during run_proactive_turn, m13_ui_turn_in_progress must block re-entry
```

Separate throttle keys from M13.4 idle introspection (`_idle_intro_last_attempt_mono`).

### 8. Structural Target Gate (Honest Product Note)

Implicit idle proactive may still suppress with `no_high_value_target` when no
open item, boredom target, or context trigger exists. M14.4 acceptance must
include **one fixture** where a minimal structural target exists (open item with
concrete `next_check`, or boredom band medium+ with exploration target).

Document in `reports/m14_4_streamlit_implicit_idle.md`:

```text
Silence alone is insufficient today; user-visible auto-message still needs a
structural proactive target unless M13.6/M14.3 later tightens eligibility.
```

## Acceptance Criteria

M14.4 is complete when:

1. With Streamlit chat open, `implicit_idle_delivery=true`, policy profile
   `streamlit_open_chat`, and idle time above threshold, a proactive message can
   appear **without** pressing manual continue.
2. `implicit_idle_delivery` defaults to **true** when initiative is enabled via
   MVP chat bootstrap (and in normalized defaults).
3. Under `streamlit_open_chat`, session cap and cooldown checks do not suppress
   a second proactive attempt solely due to count/turn cooldown (safety gates still apply).
4. Idle introspection opt-in is **not** required for §1 behavior.
5. Queued-outreach drain still runs; implicit idle does not bypass delivery assessor.
6. Suppression and proposal attempts emit auditable events with `reason_code`.
7. Inner-world panel fields document last idle check and suppression.
8. M11/M12 ledgers, Path A, and M10 untouched.
9. All listed tests pass with deterministic stubs and fake clocks.
