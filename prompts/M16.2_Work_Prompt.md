# OpenFEP M16.2 Work Prompt

## Milestone

M16.2: TypeScript Consciousness Client SDK

## Goal

Ship a shared TypeScript library that Web and TUI clients use to talk to the
M16.1 gateway. The SDK owns transport, reconnect, schema validation, and event
typing; it owns **no cognition**.

Target developer experience:

```text
const client = createConsciousnessClient({ baseUrl, personaId, sessionId })
await client.connectStream()
client.on('assistantMessage', renderBubble)
await client.sendUserInput(text)
```

## Architecture Position

```text
ui/packages/consciousness-client
  -> HTTP helpers (session, snapshot, runner control)
  -> WebSocket stream with auto-resubscribe
  -> runtime validation against schemas/m16/*.json
  -> typed event emitter

ui/web          (M16.3) imports consciousness-client
ui/tui          (M16.4) imports consciousness-client
```

The SDK is a perception/actuation adapter only:

- it never computes idle seconds for scheduling,
- it never decides proactive eligibility,
- it may display server-provided suppression codes but not interpret them with
  keyword heuristics.

## Dependencies

Hard:

- M16.0 JSON/OpenAPI schemas (source of truth)
- M16.1 running gateway for integration tests (optional dev dependency)

Soft:

- none

## Non-Goals

- Do not embed chat UI components beyond minimal examples.
- Do not duplicate Python cognition helpers in TS.
- Do not add semantic parsing of user text in the SDK.
- Do not require a frontend framework inside the package.

## Required Work

### 1. Package Setup

Implement:

```text
ui/packages/consciousness-client/
  package.json
  tsconfig.json
  src/
    index.ts
    http.ts
    ws.ts
    types.ts
    validate.ts
    reconnect.ts
    errors.ts
  tests/
```

Tooling:

- TypeScript 5.x strict mode,
- test runner: `vitest` or project-standard equivalent,
- schema validation: `ajv` against checked-in JSON schemas copied or referenced
  from `schemas/m16/`,
- build output: ESM + type declarations.

Package name suggestion:

```text
@segments/consciousness-client
```

### 2. HTTP Client

Implement typed wrappers for M16.0 routes:

```text
health()
createSession(...)
getSession(...)
getSnapshot(...)
postInput(text, metadata?)
startRunner()
stopRunner()
getRunnerStatus()
```

Rules:

- `postInput` treats `202 Accepted` as success,
- include client-generated `correlation_id` on mutating calls,
- surface structured `GatewayError` with HTTP status + server `reason_code`.

### 3. WebSocket Client

Implement:

```text
connectStream(options): ConsciousnessStream
```

Behavior:

- send `Subscribe` on open,
- respond to server `Ping` if added later; client may send `Ping`,
- emit `DeliverySurfaceReady` after successful subscribe,
- auto-resubscribe with exponential backoff capped at 30s,
- on reconnect, fetch REST snapshot and emit `resync` event,
- send `DeliveryAck` when UI displays proactive/assistant actuation with id,
- clean shutdown sends `Unsubscribe` and closes the socket; the gateway records
  `DeliverySurfaceDisconnectedEvent` from WS lifecycle.

Typed server events must mirror M16.0 kinds exactly.

### 4. Validation Layer

`validate.ts` must:

- validate outbound client messages before send,
- validate inbound server messages before emit,
- reject messages missing `schema_version`, `message_id`, or `kind`,
- reject forbidden internal keys in inbound actuation payloads in strict mode;
  lenient mode may drop the event and surface a structured validation warning.

Add a CI-friendly script:

```text
npm run validate-schemas
```

that compiles schemas and runs fixture roundtrips.

### 5. Developer Ergonomics

Export:

```text
createConsciousnessClient
ConsciousnessClient
ConsciousnessStream
types for every WS kind
isAssistantMessage
isProactiveMessage
isSuppressionEvent
```

Provide `examples/minimal-node.ts` that:

- connects to localhost gateway,
- prints audit events,
- sends one stdin line as user input.

No browser DOM in the example.

### 6. Tests

Add SDK unit tests:


## Acceptance Criteria

M16.2 is complete when:

1. SDK publishes typed HTTP + WS APIs covering the M16.0 contract.
2. All client/server messages are schema-validated in tests.
3. Reconnect + snapshot resync behavior is implemented and tested.
4. Package builds with `.d.ts` outputs for Web/TUI consumers.
5. Example script can drive a local M16.1 session end-to-end.
6. SDK contains no cognition scheduling or semantic keyword logic.
7. SDK never fabricates server-owned lifecycle events such as delivery-surface
   disconnection.

## Roadmap Note

M16.3 and M16.4 must import this package instead of reimplementing WS framing.
