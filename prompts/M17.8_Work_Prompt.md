# OpenFEP M17.8 Work Prompt

## Milestone

M17.8: Path-First Memory Substrate

## Goal

Move the core runtime from an episode-first memory surface toward a path-first
memory surface.

Target contract:

```text
episodes remain evidence sources
  -> bounded path objects are extracted from repeated reuse and outcome history
  -> path objects become first-class inputs to prediction, retention, and sleep
```

This milestone does not yet build a full continuous field. It creates the
intermediate object that a field can later be built from.

The structural rule is:

```text
episode stores what happened
path stores what tends to work, fail, or destabilize
```

## Architecture Position

```text
episodic entries + verification history + consolidation history
  -> MemoryPath extraction / maintenance
  -> path quality and attractor summary
  -> decision-time path context
  -> sleep-time path consolidation
```

Recommended landing points:

```text
segmentum/memory_store.py
segmentum/memory_model.py
segmentum/memory_consolidation.py
segmentum/agent.py
segmentum/world_model.py
```

Existing placeholder surfaces such as `reusable_cognitive_paths` should be used
or retired explicitly rather than left as a parallel dead path.

## Dependencies

Hard:

- M17.6 memory credit assignment
- M17.7 surprise-gated reconsolidation
- Existing episode and semantic consolidation infrastructure

Soft:

- Existing cluster, centroid, and support-id metadata
- Existing path-pattern helpers in the agent

Compatibility-sensitive:

- Existing episode readers and semantic-summary readers
- Existing snapshot or artifact formats that assume episode-first operation
- Existing path-like placeholders that may conflict with the new owner

## Non-Goals

- Do not delete episodic memory.
- Do not claim continuous field dynamics yet.
- Do not create unconstrained graph search over all memories.
- Do not let path objects become prompt-visible natural-language fiction.
- Do not touch Path A or M10.

## Required Work

### 1. Define a first-class path object and owner

Add a bounded model such as:

```text
MemoryPath:
  path_id
  source_episode_ids
  source_memory_ids
  dominant_action
  cue_projection
  predicted_effect_profile
  risk_profile
  expected_surprise_profile
  support_count
  confirmation_count
  violation_count
  path_quality
  path_polarity
  last_updated_cycle
```

Rules:

- A path is not a single episode alias.
- A path must summarize repeated adaptive tendency, not arbitrary theme
  clustering.
- Paths may be positive, negative, or cautionary.
- Path state must be derived from structured reuse, verification, and
  consolidation history rather than from free-form LLM summaries.

Recommended companion summaries:

```text
PathCueSignature
PathOutcomeProfile
PathRiskProfile
```

The implementation may choose different names, but it must create one bounded
owner for path-level state rather than scattering path fragments across episode
metadata.

### 2. Extract and update paths from repeated structured evidence

Sleep or replay should be able to create/update paths from:

```text
shared cue structure
shared action tendency
shared outcome tendency
verification history
```

Path extraction must use bounded structured signals, not raw-text thematic
guessing.

Requirements:

- path creation must require repeated evidence, not a single flashy episode
- confirmation and violation history must move path quality in opposite
  directions
- path updates must preserve source episode ids and memory ids for auditability
- the runtime must define when an existing path is updated versus when a new
  path is created

### 3. Make at least one live runtime consumer path-first

At least one live decision-time component must consume path objects directly,
for example:

```text
world-model action refinement
memory context assembly
pattern bias replacement
retention / forgetting prioritization
```

The accepted behavior must not require reading a single raw episode when a
usable path object is already available.

First shipped version should pick one primary consumer and make it reachable in
the ordinary runner path rather than in debug-only tooling.

### 4. Distinguish path quality from episode salience and semantic mass

Path quality should reflect:

```text
repeated confirmation
error reduction
future-path utility
contradiction burden
maintenance cost
```

It must not just inherit the salience of its loudest source episode.

Rules:

- one dramatic episode cannot alone dominate path quality without repeated
  structured support
- a high-salience but repeatedly contradicted episode must not yield a strong
  positive path by default
- cautionary paths are allowed and should remain first-class rather than being
  represented only as "bad positive paths"

### 5. Add path-level audit and compatibility surfaces

Required outputs:

```text
which path was active
why it was active
which episodes supported it
whether it overruled a stronger single episode
```

Recommended event family:

```text
MemoryPathCreatedEvent
MemoryPathUpdatedEvent
MemoryPathActivatedEvent
```

### 6. Keep bounded migration compatibility

Old artifact readers may still rely on episodes and semantic entries. M17.8 may
add path objects, but it must not make old snapshots unreadable.

Compatibility rules:

- episodes remain the underlying evidence records
- semantic summaries may continue to exist, but path objects own adaptive
  tendency state
- old snapshots without paths must still load and operate without corruption

## Acceptance Criteria

M17.8 is complete when:

1. The runtime has a first-class bounded path object separate from single
   episodes.
2. Paths are built from repeated structured evidence, not from free-form prose
   summaries alone.
3. At least one live runtime consumer uses path objects directly.
4. Path quality is driven by repeated predictive utility and contradiction
   history, not merely by source salience.
5. Decision or sleep traces can name the active path and its support set.
6. Episode storage remains intact as evidence, but it is no longer the only
   operational memory unit.
7. Path A and M10 remain untouched.

## Verification Standard

Use one fixture where:

```text
multiple episodes share a cue structure
they support a repeated action tendency
later verification confirms the tendency more than once
```

Expected:

```text
a MemoryPath or equivalent first-class path object is created or updated
path_quality rises due to repeated predictive utility rather than one episode's salience
a live runtime consumer can use the path directly
```

Use a second fixture where:

```text
a vivid or high-salience episode is not repeatedly confirmed
later evidence contradicts its implied tendency
```

Expected:

```text
the system does not promote that episode into a dominant positive path
path audit, if present, names the contradiction burden
```
