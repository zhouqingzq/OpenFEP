# OpenFEP M15.1 Work Prompt

## Milestone

M15.1: Consolidation And Forgetting Loop

## Goal

Path B today has only a thin "idle consolidation" step: M14.0 reflector can
propose memory writes through `MemoryConsolidationOwner`, but there is no
slow loop that:

- merges near-duplicate `pending_expectations` and `open_items` produced
  across many turns,
- decays low-value LTM beyond the per-tick bound from M14.7,
- promotes high-confidence STM entries that have survived recall into LTM,
- abstracts repeated path patterns into reusable habit rows,
- audits all of the above with a single closed enum of operations.

M15.1 ships this slow loop as a **bounded, opt-in background owner** that
consumes the M15.0 episode ledger and the M14.7 memory state. It runs on
top of the existing M14.1 / M14.2 schedulers and on top of M13.5 idle
ticks; it does not introduce a new scheduler.

Target chain:

```text
M14.1 background tick OR M13.5 idle tick (when budget allows)
-> ConsolidationOwner.maybe_run(state, ledger)
-> deterministic ops over candidate sets:
     merge_duplicate_expectations
     merge_duplicate_open_items
     promote_stm_to_ltm
     decay_low_value_ltm           (extension of M14.7 decay)
     archive_archivable_ltm
     abstract_repeated_paths       (write habit row through M14.7 gate)
-> ConsolidationOpEvent per op, with evidence_refs + retained_ids
```

Each op is small, idempotent, and gated by budgets. The owner never
generates persona text and never edits self-cognition directly.

## Architecture Position

```text
M14.1 BackgroundSelfRunner          ──┐
M13.5 IdleCognitiveTickOwner        ──┼──► may invoke ConsolidationOwner.maybe_run
M14.0 reflector (read-only consumer) ─┘

segmentum/dialogue/runtime/m14_7_memory_decay.py       (M14.7; extended decay scope)
segmentum/dialogue/runtime/mvp_loop.py              (wire-in only)
```

Consolidation writes that produce new memory rows must go through the
M14.7 gate. Decay extensions live in `m14_7_memory_decay.py`. M15.1 does not
introduce a parallel write path.

## Dependencies

Hard:

- M14.7 memory gate, decay channel, recall scoring
- M13.5 idle cognitive tick (one of the invocation points)
- M14.1 background continuity (the other invocation point, when opted in)
- M15.0 episode ledger (input for path abstraction)

Soft:

- M14.0 reflector (consumers may read consolidation outputs)
- M14.2 self-loop daemon (may surface ops over the environment event log)

## Non-Goals

- Do not implement sleep / dream subjective wording in audits or UI.
  Operational language only.
- Do not introduce a new scheduler. Reuse M14.1 / M13.5 entries.
- Do not run consolidation while a user message is being processed
  (`m13_ui_turn_in_progress`).
- Do not exceed daily / session caps from M14.1 budgets. When budget
  would be exceeded, emit a `ConsolidationDeferredEvent` instead.
- Do not delete memory content. "Forget" means archive + lowered salience
  via M14.7 decay, not row deletion.
- Do not extend Path A or M10. Do not import Path A consolidator
  (`segmentum/sleep_consolidator.py`).
- Do not use keyword/regex cue lists. Duplicate detection uses
  deterministic structural fields (id, evidence_refs overlap, bound
  memory id overlap) and recall scoring; not content substring match.

## Required Work

### 1. ConsolidationOwner contract

```text
class ConsolidationOwner:
    def maybe_run(state, *, now, turn_index, ledger, budget) -> ConsolidationRunResult
```

`maybe_run` is the only entry point. It:

1. Checks the budget; if exceeded, emit `ConsolidationDeferredEvent` and
   return.
2. Computes a small candidate set per op (max sizes below).
3. Runs ops in fixed order; each op is independent and returns a list of
   `ConsolidationOpResult`.
4. Aggregates results and emits one `ConsolidationRunEvent` summary +
   per-op `ConsolidationOpEvent`s.

Fixed op order:

```text
1. merge_duplicate_expectations
2. merge_duplicate_open_items
3. promote_stm_to_ltm
4. abstract_repeated_paths
5. decay_low_value_ltm
6. archive_archivable_ltm
```

Per-op caps per run:

```text
MAX_MERGES_PER_RUN                     = 4
MAX_PROMOTIONS_PER_RUN                 = 4
MAX_PATH_ABSTRACTIONS_PER_RUN          = 2
MAX_DECAY_DELTA_PER_RUN                = inherits MAX_DECAY_DELTA_PER_TICK
MAX_ARCHIVE_FLIPS_PER_RUN              = inherits MAX_ARCHIVE_FLIPS_PER_TICK
```

Per-day cap:

```text
MAX_CONSOLIDATION_RUNS_PER_DAY = 6
```

### 2. Duplicate detection (structural, not content)

Two expectation rows are duplicates iff **all** of:

```text
- same status family ("pending" / "open")
- evidence_refs ∩ evidence_refs nonempty
- bound_memory_ids ∩ bound_memory_ids nonempty
- content stance similarity proxy
    (deterministic: shared evidence_refs count / max(len_evidence_refs))
    >= 0.5
- both confidences >= 0.4
```

The "content stance similarity proxy" is **structural**, not content
substring. M15.1 must not implement a keyword overlap matcher on free
text content. If structural overlap is insufficient, the rows are not
considered duplicates and remain separate.

Same rule for `open_items`, using `evidence_refs` and `bound_memory_ids`
(the latter may be empty for items not bound to memory; then they are
never merged at this milestone).

Merge result: one canonical row keeps:

```text
- the lower `created_at` (older row's id and creation timestamp)
- union of evidence_refs (capped)
- union of bound_memory_ids (capped)
- the higher confidence
- a new field `merged_from: [old_ids...]` (capped, FIFO)
```

The non-canonical row is marked `status="merged_into:<canonical_id>"` and
retained for audit. M15.1 must not delete the row.

### 3. STM → LTM promotion

A short-term memory row is eligible for promotion iff:

```text
- recall_count_session >= 2
- mean recall_score across recalls >= LTM_PROMOTION_RECALL_FLOOR (default 0.4)
- written_at >= now - MAX_STM_AGE_SECONDS_FOR_PROMOTION (default 7 days)
- gate factors when last touched recorded >= LTM threshold from M14.7
```

Promotion produces a new LTM intent through `MemoryGate.evaluate`. The new
LTM row keeps:

```text
- a new id (different from STM id)
- evidence_refs from the STM row
- promoted_from: <stm_id>
- value_proxy and identity_relevance carried over
```

The original STM row stays put; recall continues to consider both during a
transition window (default 1 day) before STM row's recency factor naturally
decays its score.

### 4. Path abstraction

Read the M15.0 ledger:

```text
For each (state_fingerprint_class, action) bucket with at least
N_PATH_OCCURRENCES_FOR_ABSTRACTION (default 4) episodes and mean
delta_fe_proxy <= -0.05 (consistently improved):
  build a "habit" candidate intent:
    kind = "habit"
    content (short, structural): action under <band summary>
    confidence = bounded function of (mean -delta_fe_proxy, count)
    evidence_refs = union of evidence_refs from the source episodes (capped)
  route through MemoryGate.evaluate (M14.7)
  if commit: write LTM row, mark source episodes consumed_for_abstraction=true
```

`fingerprint_class` clusters near-fingerprints by ignoring `top_3_traction`
ordering (so similar drive bands cluster). M15.0 specifies the canonical
fingerprint; M15.1 specifies a **class** function that maps a fingerprint
to a class string. Both are deterministic and tested.

Habit rows do not change M13 traction directly; M13 action pull reads
ledger episodes (M15.0) for runtime bonus. The habit row is the durable
LTM representation that survives ledger truncation and feeds future
recall.

### 5. Extended decay scope

M14.7 decay touches LTM salience on idle ticks. M15.1 extends the same
decay channel with:

```text
- a slower per-run decrement (configurable, default 0.02) applied to LTM
  rows with recall_count_session == 0 over LAST_RECALL_GRACE_SECONDS
- archive flip uses the same threshold as M14.7
- consolidation's `abstract_repeated_paths` may mark source episodes
  consumed; consumed episodes do not re-trigger abstraction
```

Decay still cannot touch:

```text
- open_items
- pending_expectations
- self_cognition fields
- M11 / M12 ledgers
- merged_into rows (they are not subject to decay; their canonical row is)
```

### 6. Audit events

Closed enum for `ConsolidationOpEvent.op`:

```text
merge_expectation
merge_open_item
promote_stm_to_ltm
abstract_path
decay_ltm_salience
archive_ltm
```

Each `ConsolidationOpEvent` includes:

```text
at, turn_index, run_id
op
inputs:
  source_ids
outputs:
  retained_id (if applicable)
  new_id (if applicable)
violation_codes
engineering_proxy_label = "mvp_local_consolidation"
```

Aggregate event:

```text
ConsolidationRunEvent
  at, turn_index, run_id
  triggered_by: "background_tick" | "idle_cognitive_tick"
  ops_attempted, ops_committed, ops_rejected
  budget_remaining_runs_today
```

Deferred:

```text
ConsolidationDeferredEvent
  at, turn_index
  reason_code in {budget_exceeded, user_turn_in_progress,
                  ledger_empty, recently_ran_within_min_interval}
```

`MIN_RUN_INTERVAL_SECONDS` default 600 (10 minutes). M15.1 must not run
twice in the same minute regardless of scheduler.

### 7. UI surface (diagnostics only)

Add a compact "Slow loop" block in the mind panel showing:

```text

ops this run:                merges=N, promote=N, abstract=N,
                             decay_touched=N, archived=N

```

No subjective wording. No raw merged content.

## Acceptance Criteria

M15.1 is complete when:

1. Consolidation runs only from M14.1 background ticks or M13.5 idle
   cognitive ticks, never from user-turn paths.
2. Every op uses deterministic structural overlap (evidence_refs,
   bound_memory_ids, fingerprint classes, recall scores). No keyword cue
   lists. No LLM call inside consolidation.
3. Merge, promote, and abstract all route through M14.7 `MemoryGate` for
   new writes; rejected proposals emit gate audit events.
4. Decay extension stays in M14.7 module; M15.1 only widens its eligibility
   set and adds an additional bounded decrement.
5. Source rows are never deleted; merged rows carry `status="merged_into:..."`
   and remain readable.
6. Budgets and intervals (per-run caps, per-day cap, min run interval) are
   enforced and audited.
7. Diagnostics block uses operational language only.
8. No write to M11/M12 ledgers. No Path A consolidator import.
9. All listed tests pass; previously green M9/M13/M14/M15.0 tests still pass.
