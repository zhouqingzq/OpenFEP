# OpenFEP M18.4 Work Prompt

## Milestone

M18.4: Group-Safe Memory, Privacy, And Cross-User Recall Boundaries

## Goal

Make multi-party recall safe and auditable so Path B does not casually leak one
participant's information into another participant's thread.

## Required Work

### 1. Scope memory evidence by source and audience

At minimum, recalled memory must remain able to answer:

```text
who originally said this
who is hearing this now
whether cross-user reuse is allowed
why this recall is allowed
```

### 2. Preserve privacy/shareability rules in group conditions

Cross-user recall may be allowed, abstracted, blocked, or refusal-triggering,
but it must not silently drift.

At minimum, this milestone must define a policy matrix over:

- origin audience: self-only, prior small group, current whole-group, hearsay
- current audience: same participant, subset, different participant, whole group
- sensitivity: default-social, soft-boundary, explicit-secret
- disclosure mode: direct quote, attributed summary, unattributed abstraction,
  refusal / deny-knowledge

The matrix does not need arbitrary social nuance, but it must make default
behavior explicit instead of relying on ad hoc judgment alone.

### 3. Distinguish group-common context from private participant context

Do not flatten all remembered facts into one shared pool.

At minimum, memory evidence should be able to distinguish:

- said in the current visible group and therefore group-common
- said earlier in a different audience and therefore not automatically reusable
- inferred or hearsay claims about a third party
- assistant commitments made publicly vs privately

### 4. Keep diagnostics auditable

Every cross-user memory use must leave a traceable reason.

Diagnostics should preserve fields equivalent to:

```text
source_participant_id
source_audience_scope
current_audience_scope
shareability_class
selected_disclosure_mode
policy_reason
```

## Acceptance

This milestone is complete only if:

- at least one regression blocks an impermissible cross-user leak
- at least one regression allows a bounded permissible cross-user reuse
- the policy matrix is covered by at least one direct-share case and one
  abstract-or-block case
- retrieved memory diagnostics preserve source/audience ownership
- group-common and participant-private contexts are not conflated
