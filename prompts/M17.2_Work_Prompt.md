# OpenFEP M17.2 Work Prompt

## Milestone

M17.2: Type Precision EMA And Memory Gate Integration

## Goal

Make prediction error shape memory dynamics without returning to heuristic
salience:

```text
settled prediction outcomes
-> update per-prediction_type precision and calibration stats
-> feed measured error / repeated confirmation / novelty as separate gate factors
-> keep open-world novelty distinct from prediction error
```

M17.2 should make the memory gate a prior revision / prior consolidation gate:

```text
high-confidence violation     -> revise stale prior or write corrective episode
repeated confirmed prediction -> consolidate stable prior
novel observation             -> explore/create new prediction target
```

This is still an MVP-local engineering loop. It is not a claim of full active
inference or subjective surprise.

## Architecture Position

```text
M17.1 settlements
  -> PredictionCalibrationState by prediction_type
  -> type precision EMA + Brier / calibration bins
  -> M14.7 MemoryGate factor adapter
  -> M15.0 episode ledger records measured error factors
  -> M15.1 consolidation and M14.7 decay read objective signals
```

`calibration_need_band` must stop acting as a post-hoc LLM surprise proxy for
new M17 paths. It may remain as legacy compatibility, but new gate decisions
should prefer measured error, measured confirmation, and novelty distance.

## Dependencies

Hard:

- M17.0 committed confidence
- M17.1 settlement and deterministic error
- M14.7 MemoryGate
- M15.0 episode ledger
- M15.1 consolidation/forgetting loop

Soft:

- Existing embedding or similarity helpers for novelty
- M13.6 memory-EFE as read-only context

## Non-Goals

- Do not build offline replay/ablation in M17.2.
- Do not delete legacy salience fields yet; de-weight or mark advisory.
- Do not create more than six top-level prediction types.
- Do not update calibration from `unclear` or default expiration outcomes.
- Do not merge novelty and prediction error into one scalar.
- Do not let LLM assign precision, novelty, or memory write scores.
- Do not touch Path A or M10.

## Required Work

### 1. Add prediction calibration state

Add a compact durable state under the existing user model or `m13_drive_state`
owner. Prefer a dedicated module:

```text
segmentum/dialogue/runtime/m17_calibration.py
```

State shape:

```text
PredictionTypeCalibration:
  prediction_type
  precision_ema
  hit_rate_ema
  brier_ema
  sample_count
  confirmed_count
  violated_count
  last_updated_turn
  confidence_bins:
    0.50-0.60: {count, confirmed, brier_sum}
    0.60-0.75: {count, confirmed, brier_sum}
    0.75-0.85: {count, confirmed, brier_sum}
    0.85-0.90: {count, confirmed, brier_sum}
```

Initial values:

```text
precision_ema = 0.60
hit_rate_ema = 0.60
brier_ema = 0.25
sample_count = 0
```

Update rules:

```text
confirmed -> hit = 1
violated  -> hit = 0
unclear / expired -> no update

hit_rate_ema = EMA(previous, hit)
brier_ema = EMA(previous, brier)
precision_ema = clamp(1 - brier_ema, 0.35, 0.90)
```

Use conservative alpha:

```text
alpha = 0.10 normally
alpha = 0.20 for cold start sample_count < 20
```

### 2. Feed type precision back into confidence normalization

Update M17.0 `ConfidenceNormalizer` so future committed confidence can be
corrected by type calibration:

```text
if type sample_count < 20:
  max confidence <= 0.78
if raw confidence exceeds precision_ema + 0.15:
  shrink toward precision_ema + 0.15
```

Do not retroactively change old committed confidences.

### 3. Extend MemoryWriteIntent factors

Update `segmentum/dialogue/runtime/m14_7_memory_gate.py` with backward-compatible
fields:

```text
prediction_error_signal: float
confirmation_signal: float
novelty_signal: float
recurrence_signal: float
maintenance_cost: float
contradiction_risk: float
linked_prediction_ids: list[str]
```

The existing fields may remain:

```text
surprise_proxy
value_proxy
identity_relevance
evidence_factor
confidence
```

But new score calculation should prefer measured signals:

```text
write_score =
  w_error * prediction_error_signal
  + w_confirm * confirmation_signal
  + w_novelty * novelty_signal
  + w_recur * recurrence_signal
  + w_evidence * evidence_factor
  + w_identity * identity_relevance
  + w_confidence * confidence
  - w_cost * maintenance_cost
  - w_contradiction * contradiction_risk
```

First-version weights must be constants, documented, and covered by tests. Keep
thresholds conservative. Existing callers without new fields must still behave
as before or through a clearly tested compatibility adapter.

### 4. Map settlement outcomes to gate signals

Add helper:

```text
memory_gate_signals_from_prediction_settlement(...)
```

Rules:

- High-confidence violation produces high `prediction_error_signal`.
- Repeated confirmations of the same prediction type/claim produce
  `confirmation_signal`.
- Single low-confidence confirmation should not force long-term memory.
- `unclear` produces no error or confirmation signal.
- The linked prediction ids must be present in the gate decision/event.

Confirmed predictions are not "boring": repeated confirmation is evidence for
prior consolidation.

### 5. Keep novelty separate

Add a small novelty channel, preferably in:

```text
segmentum/dialogue/runtime/m17_novelty.py
```

Definition:

```text
novelty = 1 - max_similarity(new_observation_embedding, existing_memory_embeddings)
```

First-version constraints:

- If embeddings are unavailable, emit `novelty_unavailable` and do not fake it
  with keyword salience.
- Novelty must be stored separately from prediction error.
- Novelty may propose exploration/new-memory candidates, but must not update
  prediction-type precision.
- Audit events must distinguish `PredictionErrorSignalEvent` from
  `NoveltySignalEvent`.

### 6. Update episode ledger factors

Extend M15 episode records/addenda with bounded fields:

```text
measured_user_prediction_error
measured_user_prediction_brier
prediction_type_precision
memory_gate_prediction_error_signal
memory_gate_confirmation_signal
novelty_signal
linked_prediction_ids
```

Keep legacy `expectation_prediction_error_proxy` for comparison until M17.3.

## Acceptance Criteria

M17.2 is complete when:

1. Each prediction type has durable EMA calibration stats.
2. Future confidence normalization uses type precision without changing old rows.
3. MemoryGate decisions can cite linked prediction ids and measured factors.
4. Prediction error and novelty are audited as separate channels.
5. `unclear` outcomes do not update precision or write scores.
6. M15 episode records expose measured prediction-error fields alongside legacy
   proxies.
7. New and existing M14.7/M15 tests pass.
8. Path A and M10 remain untouched.

## Verification Standard

Use a fixture with repeated `preference_prediction` outcomes:

```text
8 confirmed at conf around 0.70
2 violated at conf around 0.70
```

Expected:

```text
sample_count == 10
hit_rate_ema moves upward from the initial prior
brier_ema improves relative to 0.25
future committed confidence for preference_prediction is not allowed to exceed
  precision_ema + 0.15
```

Use a second fixture with high-confidence violations. It must create a high
prediction-error gate factor without writing a novelty signal.
