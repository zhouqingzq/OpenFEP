# OpenFEP M17.2 Work Prompt

## Milestone

M17.2: Type Precision EMA And Memory Gate Integration

## Goal

Make prediction error shape memory dynamics without returning to heuristic
salience:

```text
settled prediction outcomes
-> update per-prediction_type precision and calibration stats
-> feed measured error / repeated confirmation / novelty as separate gate factors
-> keep open-world novelty distinct from prediction error
```

M17.2 should make the memory gate a prior revision / prior consolidation gate:

```text
high-confidence violation     -> revise stale prior or write corrective episode
repeated confirmed prediction -> consolidate stable prior
novel observation             -> explore/create new prediction target
```

This is still an MVP-local engineering loop. It is not a claim of full active
inference or subjective surprise.

Rollout principle:

```text
Phase A: record measured M17 gate factors beside existing gate decisions.
Phase B: allow an opt-in policy profile to blend M17 factors into write_score.
Default: legacy MemoryGate caller scores remain byte-stable until M17.3 replay
         shows that error-driven selection is useful enough to enable.
```

M17.2 must not silently replace production memory dynamics with an unproven
formula.

To be worth enabling later, M17 factors must support a behavior that cannot be
explained as "the best single memory happened to rank first." M17.2 therefore
adds bundle-ready support accounting so later milestones can require:

```text
single memory support < single_trigger_threshold
bundle aggregated support >= bundle_trigger_threshold
```

M17.2 may ship those bundle fields in observe-only mode before any production
bundle-triggered policy is enabled.

## Architecture Position

```text
M17.1 settlements
  -> PredictionCalibrationState by prediction_type
  -> type precision EMA + Brier / calibration bins
  -> M14.7 MemoryGate factor adapter
  -> bundle-ready support accounting (member ids, max single support,
     aggregated support, synergy margin)
  -> M15.0 episode ledger records measured error factors
  -> M15.1 consolidation and M14.7 decay read objective signals
```

`calibration_need_band` must stop acting as a post-hoc LLM surprise proxy for
new M17 paths. It may remain as legacy compatibility, but new gate decisions
should prefer measured error, measured confirmation, and novelty distance.

## Dependencies

Hard:

- M17.0 committed confidence
- M17.1 settlement and deterministic error
- M14.7 MemoryGate
- M15.0 episode ledger
- M15.1 consolidation/forgetting loop

Soft:

- Existing embedding or similarity helpers for novelty
- M13.6 memory-EFE as read-only context

## Non-Goals

- Do not build offline replay/ablation in M17.2.
- Do not delete legacy salience fields yet; de-weight or mark advisory.
- Do not create more than six top-level prediction types.
- Do not update calibration from `unclear` or default expiration outcomes.
- Do not merge novelty and prediction error into one scalar.
- Do not let LLM assign precision, novelty, or memory write scores.
- Do not change legacy MemoryGate write scores for callers that do not opt into
  M17 factor blending.
- Do not feed raw `-log(confidence)` error directly into a gate score without
  bounded normalization.
- Do not claim non-top-k behavior merely because more factors were added to a
  single-item score. Any future bundle claim must expose `max_single_support`
  and `synergy_margin`.
- Do not ship production bundle-triggered policy in M17.2; that owner lands in
  M17.4 after replay baselines are in place.
- Do not touch Path A or M10.

## Required Work

### 1. Add prediction calibration state

Add a compact durable state under the existing user model or `m13_drive_state`
owner. Prefer a dedicated module:

```text
segmentum/dialogue/runtime/m17_calibration.py
```

The state owner must be explicit. Recommended ownership:

```text
PredictionCalibrationOwner -> durable per-user prediction_type calibration
MVPDialogueRuntime         -> load/save owner and turn ordering
ConfidenceNormalizer       -> read-only consumer for future confidence caps
```

Do not split the same calibration state between user-model JSON and
`m13_drive_state` without a single read/write owner.

State shape:

```text
PredictionTypeCalibration:
  prediction_type
  precision_ema
  hit_rate_ema
  brier_ema
  sample_count
  confirmed_count
  violated_count
  last_updated_turn
  confidence_bins:
    0.50-0.60: {count, confirmed, brier_sum}
    0.60-0.75: {count, confirmed, brier_sum}
    0.75-0.85: {count, confirmed, brier_sum}
    0.85-0.90: {count, confirmed, brier_sum}
```

Initial values:

```text
precision_ema = 0.60
hit_rate_ema = 0.60
brier_ema = 0.25
sample_count = 0
```

Update rules:

```text
confirmed -> hit = 1
violated  -> hit = 0
unclear / expired -> no update

hit_rate_ema = EMA(previous, hit)
brier_ema = EMA(previous, brier)
precision_ema = clamp(1 - brier_ema, 0.35, 0.90)
```

Use conservative alpha:

```text
alpha = 0.10 normally
alpha = 0.20 for cold start sample_count < 20
```

### 2. Feed type precision back into confidence normalization

Update M17.0 `ConfidenceNormalizer` so future committed confidence can be
corrected by type calibration:

```text
if type sample_count < 20:
  max confidence <= 0.78
if raw confidence exceeds precision_ema + 0.15:
  shrink toward precision_ema + 0.15
```

Do not retroactively change old committed confidences.

### 3. Extend MemoryWriteIntent factors

Update `segmentum/dialogue/runtime/m14_7_memory_gate.py` with backward-compatible
fields, but keep M17 factor blending feature-gated:

```text
prediction_error_signal: float
confirmation_signal: float
novelty_signal: float
recurrence_signal: float
maintenance_cost: float
contradiction_risk: float
linked_prediction_ids: list[str]
bundle_id: str
member_memory_ids: list[str]
member_evidence_refs: list[str]
aggregated_support: float
max_single_support: float
synergy_margin: float
bundle_required: bool
unique_memory_count: int
unique_evidence_ref_count: int
```

The existing fields may remain:

```text
surprise_proxy
value_proxy
identity_relevance
evidence_factor
confidence
```

But new score calculation should prefer measured signals:
for callers that explicitly opt into the M17 policy profile:

```text
write_score =
  w_error * prediction_error_signal
  + w_confirm * confirmation_signal
  + w_novelty * novelty_signal
  + w_recur * recurrence_signal
  + w_evidence * evidence_factor
  + w_identity * identity_relevance
  + w_confidence * confidence
  - w_cost * maintenance_cost
  - w_contradiction * contradiction_risk
```

First-version weights must be constants, documented, normalized, and covered by
tests. Requirements:

```text
legacy policy:
  score == pre-M17 score for the same MemoryWriteIntent inputs

m17_observe_only policy:
  write_score == legacy score
  event.factors includes M17 sidecar factors for diagnostics

m17_blended policy:
  positive weights are normalized so score remains comparable to thresholds
  negative weights are bounded penalties
  thresholds stay conservative or are policy-specific constants
```

Existing callers without new fields must behave exactly as before. Add a
byte-stable regression test for representative legacy callers before enabling
M17 blended scoring.

Bundle-sidecar semantics:

```text
aggregated_support      -> bounded support after combining multiple linked memories
max_single_support      -> strongest member under the same scoring regime
synergy_margin          -> aggregated_support - max_single_support
bundle_required         -> true only when:
                           aggregated_support >= bundle_trigger_threshold
                           AND max_single_support < single_trigger_threshold
                           AND unique_memory_count >= 2
                           AND unique_evidence_ref_count >= 2
```

Rules:

- These fields may be populated in observe-only mode before any bundle policy
  changes a production write decision.
- Near-duplicate memories or duplicate evidence refs must not linearly inflate
  `aggregated_support`; redundancy penalties are required.
- A dominant single memory crossing `single_trigger_threshold` must force
  `bundle_required = false` even if the linked set also crosses the bundle
  threshold.

### 4. Map settlement outcomes to gate signals

Add helper:

```text
memory_gate_signals_from_prediction_settlement(...)
```

and bundle-preparation helper:

```text
aggregate_memory_gate_bundle_support(...)
```

Rules:

- High-confidence violation produces high `prediction_error_signal`.
- Repeated confirmations of the same prediction type/claim produce
  `confirmation_signal`.
- Single low-confidence confirmation should not force long-term memory.
- `unclear` produces no error or confirmation signal.
- The linked prediction ids must be present in the gate decision/event.
- Normalize `prediction_error_signal` into `[0, 1]`, for example by clipping a
  scaled deterministic error or by using a Brier-derived bounded signal. Do not
  pass raw `-log(1 - confidence)` values directly into `write_score`.
- Define a deterministic repeated-confirmation accumulator so confirmations do
  not disappear beside violation signals.
- Bundle aggregation must operate on bounded linked memory sets defined by
  prediction ids, episode ids, expectation ids, or bounded evidence refs, not
  arbitrary free-text semantic clustering.
- If the linked set has fewer than two unique memories or two unique evidence
  refs, it may still produce diagnostics but must not set `bundle_required`.

Confirmed predictions are not "boring": repeated confirmation is evidence for
prior consolidation.

### 5. Keep novelty separate

Add a small novelty channel, preferably in:

```text
segmentum/dialogue/runtime/m17_novelty.py
```

Definition:

```text
novelty = 1 - max_similarity(new_observation_embedding, existing_memory_embeddings)
```

First-version constraints:

- If embeddings are unavailable, emit `novelty_unavailable` and do not fake it
  with keyword salience.
- Novelty must be stored separately from prediction error.
- Novelty may propose exploration/new-memory candidates, but must not update
  prediction-type precision.
- Audit events must distinguish `PredictionErrorSignalEvent` from
  `NoveltySignalEvent`.
- M17.2 may pass without enabling embedding-backed novelty if the deployment has
  no stable embedding infrastructure, provided `novelty_unavailable` is audited
  and M17.3 reports novelty coverage separately.
- When novelty is unavailable, do not re-normalize scores in a way that changes
  legacy caller decisions. The novelty term is absent in observe-only mode and
  zero or policy-specifically redistributed only in explicit blended mode.

## Acceptance Criteria

M17.2 is complete when:

1. Each prediction type has durable EMA calibration stats.
2. Future confidence normalization uses type precision without changing old rows.
3. MemoryGate decisions can cite linked prediction ids and measured factors in
   observe-only mode without changing legacy write scores.
4. Observe-only diagnostics expose `aggregated_support`, `max_single_support`,
   `synergy_margin`, and `bundle_required` when linked memory sets exist.
5. Prediction error and novelty are audited as separate channels.
6. `unclear` outcomes do not update precision or write scores.
7. M15 episode records expose measured prediction-error fields alongside legacy
   proxies.
8. Any opt-in blended MemoryGate policy uses normalized bounded factors and has
   policy-specific tests.
9. M17.2 alone does not claim production non-top-k behavior; bundle-triggered
   decisions remain deferred until M17.4 plus M17.3 replay evidence.
10. New and existing M14.7/M15 tests pass, including byte-stable legacy gate
   behavior.
11. Path A and M10 remain untouched.

## Verification Standard

Use a fixture with repeated `preference_prediction` outcomes:

```text
8 confirmed at conf around 0.70
2 violated at conf around 0.70
```

Expected:

```text
sample_count == 10
hit_rate_ema moves upward from the initial prior
brier_ema improves relative to 0.25
future committed confidence for preference_prediction is not allowed to exceed
  precision_ema + 0.15
```

Use a second fixture with high-confidence violations. It must create a high
prediction-error gate factor without writing a novelty signal. In default
observe-only mode, this factor must not change the legacy write decision; in an
explicit blended-mode fixture, the changed decision must be attributable to
bounded M17 factors and linked prediction ids.

Use a third fixture with three linked weak memories where:

```text
each single memory support < single_trigger_threshold
bundle aggregated_support >= bundle_trigger_threshold
unique_memory_count >= 2
unique_evidence_ref_count >= 2
```

Expected:

```text
bundle_required == true
synergy_margin > 0
observe-only mode still leaves the legacy write decision unchanged
```
