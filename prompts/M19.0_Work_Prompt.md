# OpenFEP M19.0 Work Prompt

## Milestone

M19.0: Self-Expectation Formation, Indirect Observation, And Fast Mismatch Memory

## Goal

Teach Path B to form bounded expectations about Hu Tao's own replies, detect when
indirect conversation outcomes diverge from those expectations, and accumulate
fast revocable mismatch memory — without directly rewriting `self_cognition` and
without treating external correction as the primary truth source.

This milestone creates the fast layer of an active-inference self-correction
loop:

```text
conscious loop / thinking / idle reflector
-> self_response_expectation
-> indirect outcome observation (next-turn structure, dialogue tension, recall)
-> self_expectation_mismatch
-> weighted mismatch_memory_fast
-> active_mismatch_focus_topk
-> prediction_error_proxy (advisory only in M19.0)
```

M19.0 does not create durable identity conclusions. It only creates bounded,
auditable fast memory about recurring self-expectation failures.

Primary correction signal is **internal prediction mismatch**, not outside
intervention. User correction, `reply_validation`, and enforcement traces may
appear only as auxiliary `evidence_refs`, never as the sole reason to create or
strengthen a mismatch row.

## Architecture Position

M19.0 is MVP-local and lives inside the existing Path B turn path:

```text
MVPDialogueRuntime.run_turn / run_idle_introspection_turn
-> conscious plan (may emit self_response_expectation proposals)
-> memory_dynamics / M13.2 / M13.6 (read-only inputs for indirect observation)
-> M19 self-expectation adapter
-> self_expectation_state patch (named owner)
-> audit events on conversation_log.jsonl
```

M19.0 may read M13.6 `f_memory`, M13.2 `prediction_error_proxy`, and
`memory_dynamics.control_guidance`, but it must not duplicate their ownership.
It records self-specific expectation tension; later milestones wire that tension
into behavioral pull.

## Non-Goals

- Do not treat explicit user scolding or correction text as the primary mismatch
  trigger.
- Do not let `reply_validation` rewrites alone prove that Hu Tao "was wrong"; at
  most they are shadow evidence attached to an already-formed self-expectation.
- Do not hard-force visible apology or self-blame text.
- Do not write `self_cognition`, `m13_drive_state.path_patterns`, or memory
  precision directly in M19.0.
- Do not claim subjective remorse, consciousness, or emotional punishment.

## Required Work

### 1. Add self-response expectation objects

Define a normalized `self_response_expectation` shape with fields equivalent to:

```text
expectation_id
target_context
expected_outcome
expected_reply_quality
confidence
turn_index
at
evidence_refs
reason_codes
engineering_proxy_label
```

`expected_outcome` must be a bounded operational prediction about how the reply
should land, not persona poetry. Examples:

- `casual_turn_stays_light_and_short`
- `group_boundary_handled_without_template_leak`
- `direct_answer_without_over_explaining`
- `initiative_timing_matches_recent_silence_structure`

Minimum `target_context` set:

- `short_casual_reply`
- `group_privacy_boundary`
- `user_requests_directness`
- `high_stakes_clarification`
- `initiative_after_silence`
- `repair_after_prior_tension`

Expectations must be created from conscious-loop or idle-reflector structured
output. Engineering code may validate and clamp them; it must not invent them
from keyword cues.

### 2. Add self-expectation mismatch observations

Define a normalized `self_expectation_mismatch` shape with fields equivalent to:

```text
mismatch_id
source_expectation_id
mismatch_type
mismatch_summary
severity
confidence
prediction_error_proxy
recurrence_key
turn_index
at
evidence_refs
reason_codes
engineering_proxy_label
```

Minimum `mismatch_type` set:

- `outcome_too_heavy_for_context`
- `outcome_too_thin_for_context`
- `pacing_mismatch`
- `privacy_boundary_miss`
- `initiative_mistiming`
- `repair_insufficient`
- `persona_drift`
- `memory_use_misaligned`

### 3. Define primary indirect observation sources

A mismatch may be recorded only when at least one primary indirect signal is
present:

- next-turn `conscious_plan.expectation_results` with `violated` or `uncertain`
  aligned to the same `target_context`
- `memory_dynamics.control_guidance` showing elevated `repair_bias` or
  `conflict_level` without a user-correction turn being required
- M13.2 settlement producing a rising `prediction_error_proxy` for the linked
  self-expectation context
- structural dialogue signals such as topic stall, silence-after-heavy-reply, or
  repeated clarification pressure in matching context
- idle reflector re-evaluating a prior self-expectation and marking it stale or
  unsupported

Allowed auxiliary evidence only (must not be sole trigger):

- `reply_validation` audit row
- `post_reply_observer` audit row
- user correction turn id
- policy enforcement event id

If only auxiliary evidence exists and no primary indirect signal is present, the
mismatch must be rejected or stored as `observations_tail` only without
accumulating weighted support.

### 4. Make evidence anchoring mandatory

Every expectation and mismatch must carry non-empty `evidence_refs`.

For M19.0, `evidence_refs` means compact references to concrete evidence rows or
turn-local artifacts, such as equivalents of:

- originating `self_response_expectation` id
- current or prior turn memory id
- conscious-plan expectation result id
- memory-dynamics guidance audit handle
- M13.2 settlement row id
- idle reflector audit row id

If a source has no durable id yet, create a bounded local reference handle from
turn id plus source slot. Rows without traceable evidence must be rejected.

### 5. Add fast mismatch memory accumulation

Create a fast-layer state bucket, for example:

```text
self_expectation_state:
  expectations_tail
  mismatches_tail
  mismatch_memory_fast
  active_mismatch_focus_topk
  last_prediction_error_proxy
```

`mismatch_memory_fast` must accumulate repeated support by `recurrence_key`,
using weighted support rather than raw count alone.

Minimum accumulated fields:

```text
mismatch_key
mismatch_type
target_context
support_count
weighted_support
recent_support
last_prediction_error_proxy
last_seen_at
last_seen_turn
evidence_refs_tail
status
```

Allowed statuses:

- `active`
- `cooling`
- `resolved`
- `revoked`

### 6. Bound active focus with deterministic top-k selection

Only the highest-value fast mismatches should influence future reflection.

Add deterministic top-k selection over active mismatches using factors
equivalent to:

- weighted support
- recency
- `prediction_error_proxy`
- testability in natural recurrence

This top-k output and `last_prediction_error_proxy` are advisory context only.
They must not mutate reply behavior, `m13_drive_state`, or `self_cognition` in
M19.0.

### 7. Keep the fast layer revocable and decaying

Fast mismatch memory must decay when not re-supported and must be revocable when
later indirect evidence contradicts the earlier pattern.

One-off mismatches may enter `mismatches_tail` but must not immediately become
durable fast-memory conclusions.

Confirmed indirect outcomes that match the original self-expectation should cool
or resolve the corresponding mismatch key rather than strengthening it.

### 8. Preserve ownership boundaries

M19.0 may consume read-only signals from:

- conscious loop structured output
- `build_memory_dynamics_guidance`
- M13.2 reward / settlement evaluation
- M13.6 memory EFE evaluation
- M14 idle reflector outputs

But M19.0 must not directly write:

- `self_cognition.current_self_view`
- `self_cognition.identity_tensions`
- `self_cognition.known_limits`
- `m13_drive_state.path_patterns_by_action`
- `m13_drive_state.traction_by_action`
- memory precision or episode ledger entries

## Acceptance Criteria

M19.0 is complete only if:

- Hu Tao can form bounded `self_response_expectation` objects from conscious or
  idle structured output
- mismatches are created from primary indirect observation, not from user
  correction or `reply_validation` alone
- a single isolated awkward turn does not directly modify `self_cognition`
- repeated similar mismatches accumulate into one `mismatch_memory_fast` row
- expectations and mismatches without `evidence_refs` are rejected
- active mismatch focus is bounded by deterministic top-k selection
- contradicted or stale fast mismatches can cool down or revoke instead of
  living forever
- confirmed self-expectations can reduce support on the corresponding mismatch
  key without external intervention
