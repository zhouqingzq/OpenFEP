# OpenFEP M19.0 Work Prompt

## Milestone

M19.0: Self-Issue Observation, Evidence Anchoring, And Weak Memory

## Goal

Teach Path B to notice its own recurring response problems without directly
rewriting `self_cognition`.

This milestone creates a fast, revocable self-issue layer:

```text
turn outcome / reply validation / post-reply observer / user correction
-> self_issue_observation
-> repeated weighted support
-> self_issue_memory_fast
-> active_issue_focus_topk
```

M19.0 does not create durable identity conclusions. It only creates bounded,
auditable weak memory about recurring self-problems.

## Required Work

### 1. Add self-issue observation objects

Define a normalized `self_issue_observation` shape with fields equivalent to:

```text
observation_id
issue_type
issue_summary
layer
severity
confidence
user_cost
recurrence_key
turn_index
at
evidence_refs
reason_codes
engineering_proxy_label
```

Minimum `issue_type` set:

- `surface_naturalness`
- `over_explaining`
- `privacy_overblocking`
- `pacing_mismatch`
- `initiative_mistiming`
- `repair_afterthought`
- `policy_template_leak`
- `memory_misalignment`

Minimum `layer` set:

- `thinking`
- `reply_repair`
- `reply_validation`
- `policy`
- `initiative`
- `observer`

### 2. Make evidence anchoring mandatory

Every observation must carry non-empty `evidence_refs`.

For M19.0, `evidence_refs` means compact references to concrete evidence rows or
turn-local artifacts, such as equivalents of:

- current turn memory id
- prior turn memory id
- reply validation audit row id or turn-local handle
- post-reply observer audit row id or turn-local handle
- user correction turn id
- policy enforcement event id

If a source has no durable id yet, create a bounded local reference handle from
turn id plus source slot. Observations without traceable evidence must be
rejected.

### 3. Add weak issue memory accumulation

Create a fast-layer state bucket, for example:

```text
self_issue_state:
  observations_tail
  issue_memory_fast
  active_issue_focus_topk
```

`issue_memory_fast` must accumulate repeated support by `recurrence_key`, using
weighted support rather than raw count alone.

Minimum accumulated fields:

```text
issue_key
issue_type
support_count
weighted_support
recent_support
last_seen_at
last_seen_turn
evidence_refs_tail
status
```

Allowed statuses:

- `active`
- `cooling`
- `resolved`
- `revoked`

### 4. Bound active focus with deterministic top-k selection

Only the highest-value fast issues should influence future reflection.

Add deterministic top-k selection over active issues using factors equivalent
to:

- weighted support
- recency
- user cost
- testability

This top-k output is advisory context only. It must not mutate reply behavior
in M19.0.

### 5. Keep the fast layer revocable and decaying

Weak issue memory must decay when not re-supported and must be revocable when
later evidence contradicts the earlier pattern.

One-off observations may enter `observations_tail` but must not immediately
become durable issue conclusions.

### 6. Integrate with existing Path B observers without direct self rewrite

M19.0 may consume signals from:

- `reply_validation`
- `post_reply_observer`
- next-turn user correction
- privacy or pacing enforcement traces

But M19.0 must not directly write `self_cognition.current_self_view`,
`identity_tensions`, or `known_limits`.

## Acceptance Criteria

M19.0 is complete only if:

- a single isolated awkward turn does not directly modify `self_cognition`
- repeated similar observations accumulate into one fast issue memory row
- issue observations without `evidence_refs` are rejected
- active issue focus is bounded by deterministic top-k selection
- contradicted or stale fast issues can cool down or revoke instead of living
  forever
