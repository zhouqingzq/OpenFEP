# OpenFEP M14.6 Work Prompt

## Milestone

M14.6: Idle Plan And Structural Selector Alignment, Diagnose Observability

## Goal

Remove the silent disagreement between three idle subsystems on Path B:

```text
M14.0 reflector idle plan      says: should_outreach = true
M14.3 select_proactive_target  says: no target
M14.4 implicit-idle audit       says: throttled / no_traceable_proactive_target
diagnose_idle_reflection CLI    says: daemon never ran (false, M14.2 audits exist)
mind / M14.3 panel             says: stale snapshot from last user turn
```

After M14.6, exactly one **structural selector** decides outreach eligibility,
and every subsystem either consumes that decision or emits a structured
mismatch event so the contradiction is visible and actionable.

Target invariants:

```text
INVARIANT A: idle_plan.outreach_recommendation.should_outreach == true
             ==> select_proactive_target(state, m13, memory_efe_eval=..., ...) != None
             OR  idle_plan_rejected event emitted with structured reason

INVARIANT B: no proactive proposal ever ships without:
             - a ProactiveTarget produced by select_proactive_target
             - evidence_refs that exist in retrieved_ids or durable state

INVARIANT C: diagnose tool verdict is consistent with conversation_log.jsonl
             event counts (m14_2_audit, m14_4_implicit_idle_audit,
             m13_idle_audit, m14_1_background_audit, IdleCognitiveTickEvent)
```

M14.6 also fixes the diagnose CLI and the mind panel so operators get a
truthful view of what just happened, not a stale slice.

## Architecture Position

```text
M14.0 reflector  ──► outreach_recommendation
                     │
                     ▼  (cross-check, never an alternate path)
M14.3 select_proactive_target  ──► ProactiveTarget | None
                     │
                     ▼
M13.3 run_proactive_turn (delivery gates unchanged)

M13.5 IdleCognitiveTickEvent
M14.0 IdleIntrospectionPlanEvent      ──► consumed by diagnose + panel
M14.4 M14ImplicitIdleProactiveCheckEvent
M14.2 m14_2_audit (daemon health, scheduled intents)
```

M14.6 is **structural observability**. It does not add a new cognitive
module. It tightens contracts already promised by M14.0, M14.3, M14.4.

## Dependencies

Hard:

- M13.4, M13.6, M14.0, M14.3, M14.4 already shipped
- M13.5 idle cognitive tick (consume `IdleCognitiveTickEvent`)
- existing `diagnose_idle_reflection` CLI

Soft:

- M14.1 background runner, M14.2 self-loop daemon (read-only; M14.6 must
  understand their audit channels)

## Non-Goals

- Do not change the M14.0 reflector prompt schema in any user-visible way.
- Do not change M14.3 selection rules. Alignment is verified, not rewritten.
- Do not extend `select_proactive_target` to call the LLM.
- Do not add a new LLM "judge" to arbitrate disagreements.
- Do not add autonomous self-healing of mismatches; M14.6 only surfaces them.
- Do not break diagnose CLI for sessions without M13.5 events yet (graceful
  fallback).
- Do not extend Path A or M10.

## Required Work

### 1. Reflector / selector cross-check

In the runtime point where `IdleIntrospectionPlanEvent` is emitted (M14.0),
after the plan is normalized, call `select_proactive_target` using:

- the same `state` snapshot used to build idle context
- the latest `m13_drive_state`
- the latest `memory_efe_evaluation` snapshot (idle phase)
- the latest `structural_signals` (queued outreach included)

Cases:

```text
plan.should_outreach == true  AND  target is None
  -> emit IdlePlanStructuralMismatchEvent
     reason_code in:
       generic_self_only_open_item
       no_eligible_expectation
       memory_efe_below_outreach_margin
       no_high_value_target
       missing_evidence_refs
       unknown
  -> downgrade plan.should_outreach to false BEFORE running
     translate_outreach_recommendation_to_proposal
  -> do NOT block patch commits; reflection patches still apply

plan.should_outreach == true  AND  target is not None
  -> emit IdlePlanStructuralAgreementEvent (compact)
  -> proceed with existing M13.3 path; target overrides plan's
     suggested_intent only for evidence_refs / source_kind /
     traceable_expectation_id (intent text from plan is still allowed
     subject to delivery assessor and reply validation)

plan.should_outreach == false  AND  target is not None
  -> emit IdlePlanStructuralAgreementEvent with reason = "reflect_only_preferred"
  -> respect the plan; do not auto-outreach. Target is recorded for
     diagnostics only.
```

`select_proactive_target` is **deterministic and side-effect free**. Calling
it twice (once during M13.5 tick, once during reflector cross-check) is
acceptable; both calls must read the same snapshot.

### 2. Single source of truth for selection_reason_codes

When the reflector plan and the selector disagree, the suppression event
that reaches the dashboard must carry **both** views:

```text
selection_reason_codes:        [from selector or empty]
plan_recommendation_reason:    [from plan.outreach_recommendation.reason]
mismatch_reason_code:          [from §1 enum]
```

Never collapse these into a single `reason_code: "no_traceable_proactive_target"`
when the underlying cause is a plan-vs-selector mismatch.

### 3. Fix `diagnose_idle_reflection`

Required changes:

- Read all `conversation_log.jsonl` rows for the session, not only the
  tail 60 lines. Stream-read; do not load multi-MB content into memory.
- Recognize all idle/background channels:

  ```text
  m13_idle_audit
  m14_idle_audit
  m14_4_implicit_idle_audit
  m14_1_background_audit
  m14_2_audit
  IdleCognitiveTickEvent   (M13.5)
  ```

- Distinguish between **stale last_skip_reason in state** and **the most
  recent skip reason emitted in the log**. Print both with timestamps.
- Differentiate **process alive** (`runner.lock + PID alive`),
  **background ticks recorded** (`bg.ticks_today`), and **daemon emits
  health events** (`SelfLoopDaemonHealthEvent` in `m14_2_audit`). Do not
  conflate them in a single verdict.
- Verdicts must use closed enum codes; free-text is for detail only.

New verdict enum (closed):

```text
PROACTIVE_PIPELINE_NEVER_TICKED
PROACTIVE_PIPELINE_TICKING_BUT_NO_TARGET
PROACTIVE_PIPELINE_TICKING_NEEDS_TRACEABILITY
PROACTIVE_PIPELINE_DELIVERED_RECENTLY
IDLE_INTRO_NEVER_RAN
IDLE_INTRO_PLAN_SELECTOR_MISMATCH
DAEMON_PROCESS_DEAD
DAEMON_PROCESS_ALIVE_NO_BACKGROUND_TICKS
DAEMON_PROCESS_ALIVE_HEALTHY
SESSION_ROOT_MISMATCH
CONFIG_OPT_IN_OFF
USER_NOT_IDLE_LONG_ENOUGH
```

### 4. Mind panel synchronization

In `app.py` panel rendering:

- Read `last IdleCognitiveTickEvent` (M13.5) for `idle_seconds`, bands,
  selected_target / reject_reason. Show its `at` timestamp; flag as stale
  if older than 2 minutes.
- Read `last IdlePlanStructuralMismatchEvent` (this milestone) and render
  a small mismatch panel only when present.
- Stop reading `idle_seconds` from `st.session_state` that is not updated by
  the 5s fragment. Use the audit event timestamp instead.

The panel still does not auto-rerun. M14.6 only changes what is **read**,
not how often.

### 5. Suppression event enrichment

`M13ProactiveSuppressionEvent` already exists. Add optional fields:

```text
linked_idle_plan_event_id        # so dashboard can correlate
linked_structural_tick_event_id  # so dashboard can correlate
```

These are diagnostic; missing fields must not break any consumer. Do not
remove or rename existing fields.

### 6. Test fixtures

Add fixture session generators that produce:

- a plan saying `should_outreach=true` with vague generic open-item; assert
  `IdlePlanStructuralMismatchEvent` emitted with
  `mismatch_reason_code="generic_self_only_open_item"` and dashboard
  rendering shows both `plan_recommendation_reason` and `mismatch_reason_code`.
- a session with daemon alive, ticks=0, but health events present; assert
  `diagnose_idle_reflection` verdict is `DAEMON_PROCESS_ALIVE_NO_BACKGROUND_TICKS`,
  not `PROACTIVE_PIPELINE_NEVER_TICKED`.
- a session whose log has only M14.4 audits and 1 M13.4 audit; assert
  diagnose recognizes M14.4 ticking activity (not "Streamlit idle hook not firing").

## Acceptance Criteria

M14.6 is complete when:

1. Every idle introspection turn that recommends outreach is cross-checked
   against `select_proactive_target` and emits either an agreement event or a
   structured mismatch event before delivery is attempted.
2. The mind panel's reported `idle_seconds`, drive bands, and last outreach
   reason are all sourced from audit events (M13.5 tick, M14.0 plan, M14.3
   selector), not from stale `session_state` fields.
3. `diagnose_idle_reflection` reads the full log, recognizes all five idle
   audit channels, and emits one of the closed-enum verdicts above.
4. No silent disagreements remain: in every test fixture, the cause of a
   proactive failure is identifiable from a single audit row, either a
   selector reject, a delivery assessor reject, a mismatch event, or a
   structural daemon/state issue.
5. M14.0 patch commit behavior is unchanged. Reflection patches still apply
   even when the plan's outreach recommendation is downgraded by mismatch.
6. No new LLM call is added. No Path A or M10 wiring is added.
7. All listed tests pass.
