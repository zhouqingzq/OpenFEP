# OpenFEP M19.1 Work Prompt

## Milestone

M19.1: Traceable Self-Repair Expectations And Guidance Bridge

## Goal

Turn stable fast-layer self-issues into bounded, falsifiable repair
expectations that can gently bias future behavior without becoming visible
self-talk.

This milestone owns the bridge:

```text
self_issue_memory_fast
-> self_repair_expectation
-> context-matched guidance bias
-> thinking / reply_repair / validation strategy pressure
```

The expectation is not "I will do better". It must define:

- where it applies
- what intervention it prefers
- what counts as success
- what counts as failure
- when it should be checked

## Required Work

### 1. Add self-repair expectation objects

Define a normalized `self_repair_expectation` shape with fields equivalent to:

```text
expectation_id
source_issue_key
target_context
intervention
success_criteria
failure_criteria
verify_on
opportunity_window
expires_after_opportunities
priority
status
created_at
created_turn_index
evidence_refs
reason_codes
engineering_proxy_label
```

Minimum `verify_on` set:

- `next_similar_turn`
- `natural_idle_shadow_eval`

Allowed statuses:

- `pending`
- `active`
- `confirmed`
- `violated`
- `uncertain`
- `expired`
- `superseded`

### 2. Require falsifiable expectation structure

A self-repair expectation is valid only if all of the following are present:

- a concrete `target_context`
- a bounded `intervention`
- at least one success criterion
- at least one failure criterion
- non-empty `evidence_refs`

Examples of valid target contexts:

- `group_privacy_boundary`
- `short_casual_reply`
- `user_requests_directness`
- `high_repair_bias_after_validation`
- `initiative_candidate_after_recent_silence`

Expectations like "be more natural next time" must be rejected because they are
not scoped and have no failure condition.

### 3. Generate expectations only from stable fast issues

Do not generate repair expectations from one isolated observation.

An expectation may be created only when the source fast issue crosses a
stability threshold based on repeated weighted support and remains inside the
active top-k set.

### 4. Add guidance bridge into future behavior

Self-repair expectations may influence future behavior only as bounded
guidance.

Allowed influence surfaces:

- thinking prompt control guidance
- reply repair semantic requirements
- reply validation strategy choice
- idle reflection focus priority

This guidance must be advisory. It must not hard-force visible text.

### 5. Keep guidance context-specific

The expectation should activate only when a natural context match is present.

A `group_privacy_boundary` expectation must not distort unrelated direct-message
conversation. A `short_casual_reply` expectation must not override serious
analysis mode.

### 6. Preserve the fast/slow separation

M19.1 may generate expectations from `self_issue_memory_fast`, but it must not
promote those expectations directly into `self_cognition`.

This milestone owns repair expectations and behavior guidance, not slow
identity consolidation.

## Acceptance Criteria

M19.1 is complete only if:

- vague self-promises are rejected as invalid expectations
- valid expectations must include explicit failure criteria
- expectations are created only from stable fast issues, not one-offs
- active expectations can influence future behavior only in matching contexts
- expectation guidance remains advisory and bounded
