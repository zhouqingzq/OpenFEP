# OpenFEP M19.1 Work Prompt

## Milestone

M19.1: Traceable Self-Repair Expectations And Free-Energy Guidance Bridge

## Goal

Turn stable fast-layer self-expectation mismatches into bounded, falsifiable
repair expectations that reduce internal prediction error through existing Path B
free-energy and memory-dynamics surfaces — without becoming visible self-talk
and without external correction as the driver.

This milestone owns the bridge:

```text
mismatch_memory_fast
-> self_repair_expectation
-> prediction_error_proxy / repair_bias / behavioral_pull pressure
-> memory_dynamics.control_guidance
-> M13 traction update proposal
-> thinking / reply_repair guidance
```

The expectation is not "I will do better" and not "the user said I was wrong".
It must define:

- where it applies
- what lower-free-energy intervention it prefers
- what counts as success
- what counts as failure
- when it should be checked

## Architecture Position

M19.1 sits between M19.0 fast mismatch memory and the existing M13 / memory
dynamics stack:

```text
self_expectation_state.mismatch_memory_fast
-> self_repair_expectation owner
-> build_memory_dynamics_guidance inputs (repair_bias, conflict_level)
-> M13DriveEvaluator behavioral_pull inputs
-> M13.6 memory EFE eligible expectation registration (self-local only)
-> conscious / thinking control_guidance patch
```

M19.1 calculates and proposes traction and guidance changes. Durable writes must
still use named owners, `source`, `reason`, `confidence`, and audit events.

## Non-Goals

- Do not bypass M13.0 ownership of `m13_drive_state` patches.
- Do not let self-repair expectations directly rewrite visible replies.
- Do not promote expectations into `self_cognition`.
- Do not create outreach merely because self-expectation error is high.
- Do not use user correction text as the generation trigger for repair
  expectations.

## Required Work

### 1. Add self-repair expectation objects

Define a normalized `self_repair_expectation` shape with fields equivalent to:

```text
expectation_id
source_mismatch_key
target_context
intervention
success_criteria
failure_criteria
verify_on
opportunity_window
expires_after_opportunities
priority
prediction_error_reduction_target
status
created_at
created_turn_index
evidence_refs
reason_codes
engineering_proxy_label
```

Minimum `verify_on` set:

- `next_similar_turn`
- `natural_idle_shadow_eval`

Allowed statuses:

- `pending`
- `active`
- `confirmed`
- `violated`
- `uncertain`
- `expired`
- `superseded`

### 2. Require falsifiable expectation structure

A self-repair expectation is valid only if all of the following are present:

- a concrete `target_context`
- a bounded `intervention` that names a lower-FE repair strategy
- at least one success criterion based on indirect outcome match
- at least one failure criterion based on recurring prediction mismatch
- non-empty `evidence_refs`
- a numeric `prediction_error_reduction_target` in `[0, 1]`

Examples of valid interventions:

- `prefer_short_casual_surface_form`
- `prefer_semantic_only_group_boundary_repair`
- `reduce_assertion_strength_before_clarify`
- `delay_initiative_until_structural_silence_threshold`

Expectations like "be more natural next time" must be rejected because they are
not scoped, name no intervention, and have no failure condition.

### 3. Generate expectations only from stable fast mismatches

Do not generate repair expectations from one isolated mismatch.

An expectation may be created only when the source fast mismatch crosses a
stability threshold based on repeated weighted support and remains inside the
active top-k set.

### 4. Bridge into memory dynamics and free-energy surfaces

Active self-repair expectations must influence future turns through existing
Path B tension surfaces before they influence prompt text.

Required influence surfaces:

- `memory_dynamics.control_guidance.repair_bias`
- `memory_dynamics.control_guidance.conflict_level`
- `memory_dynamics.control_guidance.assertion_strength` when relevant
- M13.0 `behavioral_pull` estimate for the preferred alternative reply action
- M13.2 `prediction_error_proxy` advisory input for the linked context
- M13.6 eligible self-local expectation registration when the repair
  expectation creates unresolved outcome tension

Allowed secondary influence surfaces:

- thinking prompt `control_guidance`
- reply repair semantic requirements
- idle reflection focus priority

This guidance must be advisory. It must not hard-force visible text.

When a repair expectation is active in a matching context, the system should
prefer policies that are expected to reduce self-expectation prediction error,
not policies that merely satisfy an external validator.

### 5. Add traction proposals for confirmed-vs-violated paths

M19.1 must propose auditable M13 traction updates:

- when a repair expectation is `confirmed`, increase traction / path precision
  for the preferred intervention action in the matching context
- when a repair expectation is `violated`, decrease traction for the failed
  intervention and increase pull toward the named alternative action

These proposals must reference:

- `source_mismatch_key`
- `expectation_id`
- `evidence_refs`

They must not directly mutate `m13_drive_state` without the existing M13 patch
owner path.

### 6. Keep guidance context-specific

The expectation should activate only when a natural context match is present.

A `group_privacy_boundary` expectation must not distort unrelated direct-message
conversation. A `short_casual_reply` expectation must not override serious
analysis mode.

### 7. Preserve the fast/slow separation

M19.1 may generate expectations from `mismatch_memory_fast`, but it must not
promote those expectations directly into `self_cognition`.

This milestone owns repair expectations and free-energy guidance, not slow
identity consolidation.

## Acceptance Criteria

M19.1 is complete only if:

- vague self-promises are rejected as invalid expectations
- valid expectations must include explicit failure criteria and a named
  lower-FE intervention
- expectations are created only from stable fast mismatches, not one-offs
- active expectations influence `repair_bias` and `behavioral_pull` in matching
  contexts before they influence thinking text
- confirmed expectations can propose increased traction on the successful
  intervention path
- violated expectations can propose decreased traction and increased pull
  toward the alternative path
- expectation guidance remains advisory and bounded
- user correction alone cannot create an active self-repair expectation
