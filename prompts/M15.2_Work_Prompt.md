# OpenFEP M15.2 Work Prompt

## Milestone

M15.2: Meta-Control Intervention Layer (Engineering Scheduler Only)

## Goal

Detect, audit, and **bias** repeated failure paths and self-consistency
tensions on Path B without giving any module autonomous agency. M15.2 is an
engineering scheduler that reads the M15.0 episode ledger and the M14.7 +
M12.x state, produces structured `MetaControlInterventionIntent` rows, and
**routes the resulting bias signals through the same M13.3 / M14.0 owners
that already control proactive outreach and idle reflection focus.**

Target behaviors:

```text
PATTERN: same action_trigger has produced delta_fe_proxy >= 0 on >= K
         consecutive episodes
-> emit RepeatedFailurePathDetectedEvent
-> issue an intervention intent: "suppress_action_trigger_for_n_turns"
-> M13.3 reads the intent and adds a bounded suppression to its existing
   gate (not a new gate); the intent expires after a fixed TTL

PATTERN: M12.0 identity_tensions and M12.1 personality plain-language report
         disagree on a stable trait, with confidence above the M12 floor,
         for at least N idle ticks
-> emit SelfConsistencyTensionDetectedEvent
-> issue intervention intent: "request_reflection_focus" with evidence_refs
-> M14.0 reflector reads it as a focus hint for the next idle introspection

PATTERN: drive bands stuck at one corner (e.g. boredom=low, reward stale,
         relation low) for > T tick window with no user activity AND
         M13.5 keeps returning the same reject_reason
-> emit MetaControlStallDetectedEvent
-> issue intervention intent: "bias_idle_recall_breadth"
-> M13.5 / M14.0 widen recall top-k for one tick (within bounded caps)
```

All three pattern outputs are **bounded engineering biases**. They never
forcibly send a reply, never bypass safety gates, never edit memory or
self-cognition directly. The reflector and M13.3 owners are still the only
modules that act on these intents.

## Architecture Position

```text
M15.0 episode ledger      ──► pattern detectors (deterministic)
M12.0 / M12.1 ledgers     ──► self-consistency detector (read-only)
M14.7 gate audit history    ──► (optional) write-pressure stall detector

segmentum/dialogue/runtime/m15_meta_control.py    (NEW: detectors + intents)
segmentum/dialogue/runtime/m13_initiative.py      (consume suppression intent)
segmentum/dialogue/runtime/m14_idle_owners.py     (consume reflection focus intent)
segmentum/dialogue/runtime/m13_5_idle_owner.py    (consume recall breadth intent;
                                                   placeholder location per M13.5)
segmentum/dialogue/runtime/mvp_loop.py            (wire detectors into idle path)
```

M15.2 has **no autonomous tick of its own**. Detectors run inside:

- the M13.5 idle cognitive tick (cheap, bounded), and
- M14.1 background tick when budget allows.

This explicit shared-scheduler constraint is what keeps M15.2 from
sliding back into M10 / `MetaObserver` territory.

## Dependencies

Hard:

- M15.0 episode ledger (`delta_fe_proxy`, `action`, `action_trigger`,
  `state_fingerprint`)
- M14.7 memory gate audit events (for stall detector)
- M13.3 initiative state (consumes suppression intent)
- M13.5 idle cognitive tick (entry point)
- M14.0 reflector (consumes focus intent)

Soft:

- M12.0 / M12.1 / M12.2 outputs (used read-only; detectors degrade
  gracefully when these are missing)
- M14.1 background runner (alternate detector entry)

## Non-Goals

- Do not introduce `MetaObserver`, `SelfThoughtProducer`, or any M10-style
  self-thought event source. M15.2 is **not** the meta-observer described
  in early research notes; it is an engineering scheduler with bounded
  bias signals.
- Do not generate user-visible prose. Intervention intents have no reply
  text.
- Do not write to memory, self_cognition, M11, M12.0, M12.1, M12.2.
- Do not bypass M13.3 safety, delivery assessor, opponent_strength, or
  cooldown.
- Do not implement keyword/regex cue lists. All detectors are structural
  thresholds over numeric fields (counts, durations, deltas).
- Do not extend Path A.

## Required Work

### 1. Intervention intent schema

```text
@dataclass
class MetaControlInterventionIntent:
    intent_id
    at
    detector
    intent_kind in:
        suppress_action_trigger_for_n_turns
        request_reflection_focus
        bias_idle_recall_breadth
    payload:
        # for suppress_action_trigger_for_n_turns:
        action_trigger: str
        ttl_turns: int        (max 5)
        # for request_reflection_focus:
        focus_topic: str       (short, structural)
        evidence_refs: list[str]
        suggested_reflection_kind:
            open_item | user_model | self_consistency | habit_calibration
        # for bias_idle_recall_breadth:
        new_top_k: int         (capped: 5 <= new_top_k <= 12)
        ttl_ticks: int         (max 3)
    evidence_refs
    detector_evidence_event_ids
    expires_at
    engineering_proxy_label = "mvp_local_meta_control"
```

Persisted under M13 state in a small ring buffer:

```text
m13_drive_state.meta_control_intents
  active: list[MetaControlInterventionIntent]   (capped, FIFO 8)
  consumed: list[MetaControlInterventionIntent] (capped, FIFO 16)
```

Intents auto-expire by TTL; consumers mark them `consumed` after applying
their bounded effect.

### 2. RepeatedFailurePathDetector

Threshold:

```text
K_CONSECUTIVE_FAILURES = 3
LOOKBACK_EPISODES      = 16
DELTA_FE_FAILURE_FLOOR = 0.0   # delta_fe >= 0 counts as failure
```

Pattern:

- Take the last `LOOKBACK_EPISODES` ledger rows.
- Group by `action_trigger`.
- If any group has `>= K_CONSECUTIVE_FAILURES` consecutive episodes with
  `delta_fe_proxy >= DELTA_FE_FAILURE_FLOOR`, emit detection event and
  intent.

Emitted intent: `suppress_action_trigger_for_n_turns`, `ttl_turns=3` by
default.

Consumer: M13.3 `evaluate_proactive_initiative` reads
`m13_drive_state.meta_control_intents.active`. If a `ProactiveTarget`'s
trigger matches an active suppression intent, suppression event is
emitted with `reason_code="meta_control_trigger_suppressed"` and
`linked_intent_id`. After `ttl_turns` user turns pass (counted on user
turn boundaries), the intent expires.

This must **not** disable the trigger globally; it adds one row to the
existing M13.3 gate chain.

### 3. SelfConsistencyTensionDetector

Inputs (all read-only):

```text
m12_user_continuity.identity_tensions           (M12.0)
m12_1_user_personality.plain_language_report    (M12.1)
m12_2_reciprocal_role                           (M12.2)
```

Threshold:

```text
MIN_TENSION_CONFIDENCE       = 0.65
MIN_IDLE_TICKS_STABLE_TENSION = 2
```

Pattern:

- A tension entry whose `confidence >= MIN_TENSION_CONFIDENCE` persists
  across at least `MIN_IDLE_TICKS_STABLE_TENSION` consecutive
  `IdleCognitiveTickEvent`s (sampled by `at`, not by tick id).
- If the same tension is also referenced (by evidence_refs intersection)
  in a recent M12.1 plain-language report contradiction, the pattern
  fires.

Emitted intent: `request_reflection_focus`, `suggested_reflection_kind =
"self_consistency"`, with the tension's evidence_refs.

Consumer: M14.0 reflector. On the next idle introspection, if the plan
schema would otherwise emit `reflection_focus = null`, the runtime sets
`reflection_focus.topic` from the intent's `focus_topic` and
`reflection_focus.evidence_refs` from the intent. The LLM prompt itself
is unchanged. If the plan already has a focus, the intent is consumed
without modification (focus is suggestion, not override).

Reflector must never receive raw M12 data through this path; only
`focus_topic` and `evidence_refs` ids reach the prompt.

### 4. MetaControlStallDetector

Threshold:

```text
STALL_TICK_WINDOW          = 6
SAME_REJECT_REASON_RATIO   = 0.8   # >= 80% of ticks with same reject_reason
DRIVE_BAND_FLATNESS_RATIO  = 1.0   # all bands unchanged across window
```

Pattern:

- Over the last `STALL_TICK_WINDOW` `IdleCognitiveTickEvent`s, the same
  `reject_reason` (M13.5 closed enum) appears >= `SAME_REJECT_REASON_RATIO`
  fraction, AND boredom/reward/behavior/relation bands are all unchanged.

Emitted intent: `bias_idle_recall_breadth`, `new_top_k = min(current_top_k
+ 3, 12)`, `ttl_ticks=1`.

Consumer: M13.5 idle cognitive tick. For the next tick only, recall
`top_k` is widened to the intent's `new_top_k`. M13.6 eligibility filters
and M14.7 gate remain authoritative; broader recall just gives the
evaluator more candidates.

### 5. Detector orchestration

Single entry:

```text
def detect_and_emit_intents(state, ledger, *, now, turn_index, source)
    -> MetaControlDetectionResult
```

Called from:

- M13.5 `IdleCognitiveTickOwner.run` after `select_proactive_target` and
  before audit emission, **only if** no intent of that kind is already
  active.
- M14.1 background tick body, after consolidation (M15.1) returns, with
  the same active-intent dedup rule.

Detectors are stateless deterministic functions over `(state, ledger,
clock)`. They must not read or write self_cognition / M11 / M12 mutable
state.

### 6. Audit events

```text
RepeatedFailurePathDetectedEvent
  action_trigger, lookback_window, failure_count, mean_delta_fe
  emitted_intent_id

SelfConsistencyTensionDetectedEvent
  tension_id, confidence, stable_tick_count
  evidence_refs
  emitted_intent_id

MetaControlStallDetectedEvent
  reject_reason, window_size, ratio
  emitted_intent_id

MetaControlInterventionAppliedEvent
  intent_id, applied_to ("m13_initiative" | "m14_reflector" | "m13_5_tick")
  applied_at, applied_effect_summary

MetaControlInterventionExpiredEvent
  intent_id, expired_at, reason ("ttl" | "consumed" | "manual_clear")
```

All events use `engineering_proxy_label = "mvp_local_meta_control"`.

### 8. Demo and production posture

Local Streamlit MVP chat is a **demo surface**. M15.2 must make meta-control
effects visible there without extra toggles.

Default behavior:

```text
proactive_policy_profile == "streamlit_open_chat"
  (local MVP chat auto-enables this via app.py / M14.4)
-> detectors run AND intervention intents are applied within caps

proactive_policy_profile == "bounded_default"
-> detectors run and emit *DetectedEvent audits
-> intervention intents are NOT applied unless explicitly enabled via:
     SEGMENTUM_META_CONTROL_APPLY=1
   or a future M14.5 production-hardening toggle

SEGMENTUM_META_CONTROL_APPLY=1
-> apply intents regardless of profile (dev / staging only)
```

The mind-panel "Meta-control" block (§7) must show **applied** intents on the
local demo path so operators can see suppress / focus / recall-breadth effects
without reading raw JSONL.

M14.5 production hardening may revert demo defaults; M15.2 acceptance for
demo does not require changing M14.5's production contract.

Failure modes that must be safe:

- ledger empty → no intents emitted
- M12.x outputs missing or malformed → SelfConsistencyTensionDetector
  returns no detection, never raises
- detector raises → caught at orchestrator, emits
  `MetaControlDetectorErrorEvent` with detector name; runtime continues
  unaffected

## Acceptance Criteria

M15.2 is complete when:

1. Three detectors (RepeatedFailurePath, SelfConsistencyTension,
   MetaControlStall) run only inside M13.5 idle ticks or M14.1 background
   ticks; never during a user turn.
2. Each detector emits a `*DetectedEvent` and at most one
   `MetaControlInterventionIntent` of its kind; existing active intents of
   the same kind prevent duplicates.
3. Intents are consumed by exactly one named owner:
     suppress_action_trigger → M13.3 initiative gate
     request_reflection_focus → M14.0 reflector focus (suggestion only)
     bias_idle_recall_breadth → M13.5 next-tick top_k
4. All applied effects are bounded by explicit caps (TTL turns, TTL ticks,
   top_k ceiling) and are auditable per-intent.
5. No detector writes to memory, self_cognition, M11, M12.0, M12.1, or
   M12.2. No detector generates user-visible text.
6. On `streamlit_open_chat` (local MVP demo default), detection events are
   emitted and intents are applied within caps; the meta-control panel
   shows active intents. On `bounded_default`, intents apply only when
   `SEGMENTUM_META_CONTROL_APPLY=1`; otherwise detection audits only.
7. Detector failures are caught and audited; runtime never crashes from
   a malformed ledger or missing upstream state.
8. No Path A or M10 wiring is added. No `MetaObserver` or
   `SelfThoughtProducer` is introduced or referenced.
9. All listed tests pass; previously green M9/M13/M14/M15.0/M15.1 tests
   still pass.
