# OpenFEP M17.9 Work Prompt

## Milestone

M17.9: Local Field Potential And Non-TopK Recall

## Goal

Upgrade the path-first substrate into a bounded local field approximation so
the runtime can do something stronger than fixed top-k recall.

Target contract:

```text
coarse bounded retrieval proposes a local neighborhood
  -> local field owner builds a bounded potential surface from path objects
  -> decision follows basin / ridge / gradient summaries
  -> best-single and naive top-k counterfactuals are audited
```

This milestone must not merely add another ranking weight. It must establish a
new local decision object that can beat both:

```text
best single memory
naive additive top-k aggregate
```

when the local field geometry matters.

## Architecture Position

```text
coarse retrieval top-N
  -> local field neighborhood builder
  -> potential / gradient / basin summary
  -> world-model prediction refinement
  -> counterfactual audit against best-single and naive top-k
```

Recommended landing points:

```text
segmentum/memory_retrieval.py
segmentum/agent.py
segmentum/world_model.py
segmentum/memory_store.py
```

If a new owner module is introduced, prefer:

```text
segmentum/memory_field.py
```

## Dependencies

Hard:

- M17.8 path-first memory substrate
- M17.5 canonical FE vocabulary
- Existing retrieval and counterfactual audit surfaces

Soft:

- Existing M17.4 anti-top-k reasoning style as a design reference
- Existing bundle / recall diagnostics

## Non-Goals

- Do not run unbounded all-memory field simulation.
- Do not invent physics metaphors without measurable bounded outputs.
- Do not claim field behavior if best-single or naive top-k would already
  explain the same decision.
- Do not let the LLM define potential values or gradients.
- Do not touch Path A or M10.

## Required Work

### 1. Add a bounded local field contract

Define a compact object such as:

```text
LocalMemoryField:
  field_id
  member_path_ids
  member_memory_ids
  potential_by_channel
  gradient_by_channel
  basin_strength
  ridge_strength
  conflict_zones
  field_confidence
```

Rules:

- The field is local to a bounded neighborhood only.
- Members must come from coarse retrieval or path-neighborhood rules, not from
  arbitrary global search.
- The field must be derived from deterministic path and quality signals.

### 2. Make coarse retrieval a neighborhood proposal only

Current top-k retrieval may remain as stage 1, but only as:

```text
candidate neighborhood proposal
not final memory decision owner
```

The implementation must explicitly separate:

```text
coarse retrieval score
field potential summary
downstream chosen influence
```

### 3. Add at least one field-based downstream consumer

At least one live runtime path must consume field outputs such as:

```text
prediction refinement from basin pull
danger / safety channel adjustment from ridge and caution corridors
reply-policy or action-policy shift from local conflict zones
```

The consumer must read field summaries, not only the best single path.

### 4. Add explicit anti-top-k counterfactuals

For every field-triggered decision class, compute:

```text
best_single_counterfactual
naive_topk_counterfactual
field_enabled_decision
```

If either counterfactual would already trigger the same decision under the same
budget, the runtime must audit the case as top-k-equivalent.

### 5. Add bounded field metrics

The local field should expose measurable diagnostics such as:

```text
effective_member_count
dominant_path_share
synergy_margin
gradient_magnitude
field_flatness
conflict_density
```

These will be needed by M17.10 adaptive compute.

### 6. Add deterministic fixtures

There must be at least one fixture where:

```text
no single path crosses threshold
naive top-k is insufficient or contradictory
field summary changes the bounded downstream decision
```

## Acceptance Criteria

M17.9 is complete when:

1. The runtime has a bounded local field owner separate from coarse top-k
   retrieval.
2. Coarse retrieval is explicitly only a neighborhood proposal stage.
3. At least one live consumer uses field summaries rather than only the
   strongest single path.
4. Best-single and naive top-k counterfactuals are computed for field-triggered
   decisions.
5. The runtime only claims field-required behavior when both counterfactuals
   fail under the same budget.
6. The field exposes bounded geometry-style diagnostics such as gradient,
   flatness, or conflict density.
7. Path A and M10 remain untouched.
