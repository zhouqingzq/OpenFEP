## Milestone

M20.4: Attribution Commitment Bridge — read M18.7's structured
hypotheses, admit `ActiveCommitment` rows, settle via
LLM-judge, route graded correction to a real
`group_addressee_graph` write path, and feed a gated

## Goal

Plug the M18.7 conscious-loop fields into the M20 commitment
framework so the structured hypotheses become first-class
admission inputs. M20.4 is the **bridge** between M18.7
(structured input contract) and M18.5 (reply policy); without
M20.4, M18.7's hypotheses land in `state["m18_7_attribution_hypotheses"]`
and are never read.

## Why M20.4 Exists

The M20.3 follow-up review identified that
`group_addressee_graph` is in the v1 registry with
`graded_action_set: ["microadjust", "next_turn"]` but has
zero observables, zero producer, and a no-op write path
(`microadjust.py:7-8` self-documents the no-op). M20.3 cannot
fix this — M20.3 closes M20.0–M20.2 gaps, not M18.2 gaps.

M18.7 produces structured hypotheses (LLM's
`addressed_to_assistant` and `reaction_to_turn_id` judgments)
but the hypotheses are not consumed by anything that decides.
M20.4 closes the bridge:

- The M18.7 hypothesis is an *input*, not a *decision*. M20.4
  admits it as an `ActiveCommitment` so the M20.1 scheduler
  can settle it.
- The settle compares the hypothesis against the assistant's
  actual reply / prior turn (via a bounded excerpt). The LLM
  judge is the source of the outcome (`confirmed` / `violated`
  / `ambiguous`).
- The M20.2 dispatcher routes the `confirmed` / `violated`
  outcome to a *real* microadjust on `group_addressee_graph`,
  which appends an attribution row. The currently no-op write
  path becomes real.
- A gated feedback loop lets a high-confidence M18.7
  hypothesis flip an M18.5 `clarify_addressee` / `no_reply`
  decision to `reply_to_current_speaker`. The flip is gated
  on (a) `ambiguity_band == "high"`, (b) `confidence > 0.85`,
  (c) structural NOT explicit-addressee-of-another. The
  semantic hypothesis never overrides explicit mention /
  reply-to / quote.

Without M20.4, M18.7 is an audit-trail write only. With
M20.4 (and M18.7.1 calibration), the M20 follow-up
evaluation's 25–40% addressee-resolution band becomes
achievable. M20.4 does not promise to reach that band; it
makes the band possible.

## Hard Rules (CLAUDE.md compliance)

1. **The LLM is the only source of the LLM-judge verdict.**
   No engineering code may infer `confirmed` / `violated`
   from the M18.7 boolean alone. The settler takes the
   hypothesis AND a bounded excerpt AND `group_turn_binding`
   and calls the LLM judge. Engineering only validates
   the LLM's answer shape.

2. **No regex / keyword matching in producer or normalize.**
   The M20.4 producer reads `state["m18_7_attribution_hypotheses"]`
   and the M18.5 reply policy outcome; it does not parse
   user text, structural cues, or hypothesis text. The
   admit rule is a numerical threshold on `confidence`
   (≥ 0.4) and a presence check on `participant_id`.

3. **Bounded excerpts only.** The `observable_payload.bounded_excerpt`
   is a char-bounded slice of the relevant turn text
   (`<200` chars). It is NOT the full reply. The slice is
   taken at admission time, not at settle time, to avoid
   re-reading the assistant's text in the settler.

4. **Bounded handles in evidence_refs.** The
   `observable_payload.evidence_refs` reuses the M18.7
   evidence_refs (shape-validated, not enumerated). No
   raw text. No substring excerpts.

5. **No raw rationale text in any persisted surface.** The
   M18.7 audit envelope does not include the rationale
   text (M18.7 DECIDED 11); M20.4 inherits the same rule.
   The producer's `observable_payload` does NOT carry
   `rationale` forward; the settler does not see rationale.

6. **The semantic hypothesis never overrides structural
   signals.** The M18.5 tie-breaker is gated on
   `structural NOT explicit-addressee-of-another`. If
   `addressed_participant_ids` or `mentioned_participant_ids`
   is non-empty and the LLM hypothesis says
   `addressed_to_assistant = true`, the LLM hypothesis
   loses. M18.5 keeps its structural path. This is the
   same rule as M18.7 DECIDED 2.

7. **M18.5 reply policy itself is NOT modified.** M20.4
   writes the tie-breaker outcome to a feedback row in
   `state["m18_5_attribution_feedback"]`. M18.5 reads that
   row as a supplementary input on subsequent turns. M18.5's
   structural path and its decision logic are unchanged.

8. **M20.4 does not add a new LLM stage.** The LLM judge
   in the settler is a NEW use of the existing LLM call
   surface — it is one more bounded LLM stage registered
   in the same way as the existing `BoundaryHandledLLMJudgeSettler`
   (M20.1). The conscious loop is unchanged.

9. **Privacy parity with M18.4 and M18.7.** The producer
   filters out hypotheses with empty `participant_id`
   (M18.4 disclosure forbade the identification). The
   settler does not see the participant's text.

10. **M20.4 is a layer above M20.3 and a peer of M18.7.**
    M20.0 / M20.1 / M20.2 / M20.3 paths remain unchanged.
    M20.4 is a structural addition.

## Non-Goals

- **M20.4 does not modify the conscious loop.** M18.7
  owns the conscious-loop fields. M20.4 reads them; it
  does not write them.
- **M20.4 does not modify the M18.5 reply policy logic.**
  M18.5 keeps its structural-first path. M20.4 writes
  a feedback row; M18.5 reads it on subsequent turns.
- **M20.4 does not add a new LLM call beyond the M20.1
  settler pattern.** The LLM judges are new
  *settlers* (like `BoundaryHandledLLMJudgeSettler`);
  they reuse the existing M20.1 LLM-call surface.
- **M20.4 does not claim subjective group understanding.**
  The LLM judge is asked to confirm / violate, not to
  "know" or "feel" the group's intent.
- **M20.4 does not auto-threshold.** The producer admit
  threshold (0.4) and the tie-breaker threshold (0.85)
  are locked at the v1 values. M18.7.1 calibration may
  revise them; that is M18.7.1 territory.
- **M20.4 does not unify Path A, M10, or
  `conversation_loop.py`.**
- **M20.4 is not a "polish" milestone.** It does not
  add features beyond the bridge. The 4 pre-locked items
  (observables / producer admit / settler / tie-breaker)
  are the entire M20.4 scope; expanding requires
  M20.4.1 (a future sub-milestone).

### 2. Producer (M18.7 → M20)

The M20.4 producer reads
`state["m18_7_attribution_hypotheses"]` (bounded rolling
window, ≤ 8 entries, M18.7 DECIDED 5) and admits one
`ActiveCommitment` per matching entry. The producer is a
plain function (no LLM), called from `mvp_loop.run_turn`
in the same slot as the existing `_admit_policy_commitments`
(M20.3) and `_admit_active_commitments` (M20.0). The call
order is:

```text
1. PolicyProducer (M20.3)             — emits policy commitments
2. conscious loop (M20.0 + M18.7)     — emits state / episodic / v2 fields
3. M20.4 producer (this milestone)    — emits attribution commitments
4. LoopInvariants (M20.3)             — audit-only, runs after all
5. settle + dispatch (M20.1, M20.2)   — unchanged
```

Producer admit rule (frozen v1):

```text
for entry in state["m18_7_attribution_hypotheses"][-8:]:
    if entry.get("kind") == "addressee":
        if entry.get("participant_id", "") == "":
            continue  # M18.4 disclosure forbade
        if not (0.0 <= float(entry.get("confidence", 0.0)) <= 1.0):
            continue
        if float(entry.get("confidence", 0.0)) < 0.4:
            continue  # below producer threshold
        admit(ActiveCommitment(
            owner_id = "group_addressee_graph",
            source_kind = "state",
            source_ref = f"m18_7_hypothesis_{entry.get('commit_id', '')}",
            layer = "B_per_turn_commitment",
            horizon = "next_turn",
            observable = "addressee_target_match",
            observable_payload = {
                "hypothesis": _frozen_hypothesis_subset(entry),
                "current_turn_id": current_turn_id,
                "bounded_excerpt": bounded_excerpt,
                "group_turn_binding_snapshot": _frozen_binding_snapshot(binding),
                "ambiguity_band": binding.get("ambiguity_band", ""),
            },
            target = {"commit_id": entry.get("commit_id", "")},
            due_at = {"kind": "next_turn"},
            priority = entry.get("confidence", 0.5),
            confidence = entry.get("confidence", 0.5),
            evidence_refs = tuple(_bounded_handle_list(entry.get("evidence_refs", []))),
            created_turn = current_turn,
            created_at = now,
            reason_codes = ("m20_4_attribution",),
            engineering_proxy_label = "mvp_local_group_attribution",
        ))
```

The same pattern applies for `reaction_attribution_match`,
with `attributed_turn_id` and `attributed_bounded_excerpt`
sourced from the M18.7 entry's `reaction_to_turn_id` (looked
up in the bus for the bounded excerpt).

`_frozen_hypothesis_subset(entry)` strips rationale and

```text
{
    "addressed_to_assistant": bool,   # for addressee
```

### 3. Two LLM-judge settlers

`AddresseeTargetMatchLLMJudgeSettler` and
`ReactionAttributionMatchLLMJudgeSettler`. Both follow the
M20.1 `BoundaryHandledLLMJudgeSettler` pattern: frozen
system prompt, bounded user prompt, injected LLM call,
bounded evidence_refs, `SettledValue` return. Both fail
closed (`NoSettlement` with `settler_unavailable` if the
LLM is unavailable, response fails schema, or the
outcome is not in the frozen set).

**Addressee settler aligns the *user-perceived* question
("is this inbound message directed at the assistant?")
not the assistant-alignment question.** The bounded
excerpt is the **inbound turn** (the user's current turn,
first 200 chars), NOT the assistant's reply. The
settler answers: "is the M18.7 LLM's
`addressed_to_assistant` boolean consistent with the
inbound turn evidence + structural snapshot?" This is
the C2 design fix; the previous "settler compares
assistant's reply" was the wrong alignment.

The LLM judge's bounded system prompt
(`ADDRESSEE_TARGET_MATCH_SYSTEM_PROMPT` and
`REACTION_ATTRIBUTION_MATCH_SYSTEM_PROMPT`) is frozen at
module import time. The user prompt carries:

- For `addressee_target_match`:
  - `hypothesis: <frozen subset of M18.7 addressee_hypothesis>`
  - `current_turn_id: <id>`
  - `inbound_bounded_excerpt: <≤ 200 chars, the INBOUND turn>`
  - `ambiguity_band: "low" | "medium" | "high"`
  - `structural_addressed_to: <list>` (the M18.5 structural
    answer; informational, not authoritative)
- For `reaction_attribution_match`:
  - `hypothesis: <frozen subset of M18.7 reaction_attribution_hypothesis>`
  - `current_turn_id: <id>`
  - `attributed_turn_id: <id>` (the turn the reaction refers to)
  - `attributed_bounded_excerpt: <≤ 200 chars of the attributed turn>`
  - `ambiguity_band: "low" | "medium" | "high"`
  - `structural_addressed_to: <list>` (informational)

The LLM returns:

```text
{
    "outcome": "confirmed" | "violated" | "ambiguous",
    "rationale_span": "<= 80 chars, no quoted text>",
    "evidence_refs": ["turn_<n>_*", "bus_event_<uuid>", ...],
    "reason": "<= 200 chars, no quoted text>",
}
```

The settler maps `outcome` to M20.1 outcomes:
- `confirmed` → `confirmed` (magnitude 1.0)
- `violated` → `violated` (magnitude 1.0)
- `ambiguous` → `ambiguous` (magnitude 0.5, magnitude_defaulted)

The bounded excerpts are admitted at admission time, not
re-read at settle time, to avoid persistence-driven
discrepancy.

### 4. Real write path on `group_addressee_graph.microadjust`

The M20.2.1 `_write_paths` module gains a new branch:

```text
def apply_group_addressee_graph_microadjust(
    decision: GradedCorrectionDecision,
    commitment: ActiveCommitment,
    state: dict,
    bus: list,
) -> None:
    """`microadjust` for owner `group_addressee_graph`.

    Appends an attribution row to `state["addressee_graph"]`
    keyed by the current `turn_id`. The row carries:
      - speaker (the M18.7 hypothesis's `participant_id`)
      - addressed_to_assistant (the LLM judge's boolean)
      - confidence (the M18.7 hypothesis's confidence)
      - attributed_turn_id (for reaction_attribution_match)
      - settled_outcome (confirmed / violated / ambiguous)
      - evidence_refs (bounded handles)
    Emits a `GroupAddresseeGraphUpdated` audit event.
    """
```

The state shape is `state["addressee_graph"][turn_id] = {row}`,
where `row` is the bounded attribution row above. The cap
follows the M20.3 pattern: `[-256:]` rolling window to avoid
unbounded growth.

For `revoke` (outcome=violated, magnitude>=0.85), the write
path clears the row (sets `row = None`); for `next_turn`,
the write path queues the row for the next turn (defer).
`expire` is a no-op (no row).

### 5. Gated M18.5 tie-breaker feedback

The M20.4 dispatcher, after the M20.2 decision, writes a
bounded feedback row to `state["m18_5_attribution_feedback"]`:

```text
state["m18_5_attribution_feedback"][feedback_id] = {
    "current_turn_id": <id>,
    "m18_5_structural_decision": "clarify_addressee" | "no_reply" | ...,
    "hypothesis": <frozen subset>,
    "ambiguity_band": "low" | "medium" | "high",
    "tie_breaker_engaged": bool,
    "patched_decision": "reply_to_current_speaker" | None,
    "patched_reason": "<= 120 chars",
    "at": "<iso8601>",
    "engineering_proxy_label": "mvp_local_group_attribution",
}
```

Tie-breaker engagement rules (frozen v1) — C1 fix:

```text
engaged = (
    decision is `microadjust`
    AND outcome == "confirmed"
    AND group_turn_binding.ambiguity_band == "high"
    AND float(hypothesis.confidence) > 0.85
    AND not group_turn_binding.addressed_participant_ids
    AND not group_turn_binding.mentioned_participant_ids
    AND group_turn_binding.reply_to_turn_id is None
    AND m18_5_structural_decision in {"clarify_addressee", "no_reply"}
)
```

C1 design: the v1 OR was wrong (an explicit mention of
Alice + an empty mention list would still pass the
condition). The v1 condition requires BOTH
`addressed_participant_ids` AND `mentioned_participant_ids`
to be empty — i.e., no participant is explicitly
addressed or mentioned. M20.4.1 may add a stricter
"assistant is in addressed" check, but v1 follows the
simpler "no one is explicitly addressed" rule.

When `engaged`, the feedback row records
`patched_decision = "reply_to_current_speaker"`. M18.5 reads
the feedback row on subsequent turns and prefers
`reply_to_current_speaker` when the structural answer is
ambiguous and the feedback row is recent (≤ N turns old).

When NOT engaged, the feedback row records
`patched_decision = None` and `patched_reason` describes
why (`"structural_explicit_addressee"`,
`"explicit_mention_of_other"`,
`"explicit_reply_to_set"`,

## Engineering Phenomenology Boundary

### v1 (this milestone) — CROSS-TURN FEEDBACK ONLY

G1 design constraint: the conscious loop runs AFTER
`_decide_group_reply_policy` in `mvp_loop.run_turn` (the
existing v1 ordering). M18.5's structural decision
(`no_reply` / `clarify_addressee` / `reply_to_*`) is
made before the M18.7 hypothesis is even available. The
M20.4 tie-breaker therefore takes effect in T+1+ turns,
NOT in the current turn.

The v1 M20.4 tie-breaker:

- The current turn (T0) that triggers the ambiguous
  message: M18.5 still applies its structural decision.
  The user sees `no_reply` or `clarify_addressee` (or a
  reply) on the structural path.
- The next turn (T+1+): the M18.5 reply policy reads the
  feedback row from `state["m18_5_attribution_feedback"]`
  and prefers `reply_to_current_speaker` if the row is
  recent (≤ N turns old) and the structural answer is
  again ambiguous.
- The M20.4 feedback row's user-perceived effect is
  visible on the T+1+ turn, not the T0 turn.

The v1 M20.4 may create visible behavioral change in
two specific areas:

- On T+1+ turns, in scenarios where (a) the structural
  answer is again `clarify_addressee` or `no_reply` and
  (b) the feedback row is recent, the M18.5 reply policy
  flips to `reply_to_current_speaker`. The user sees the
  flip on T+1+, not on T0.
- M20.4 may write attribution rows to
  `state["addressee_graph"]` and emit
  `GroupAddresseeGraphUpdated` audit events. The user
  does not see these directly, but the operator running
  `diagnose` does.

### M20.4.1 (DEFERRED sub-milestone) — SAME-TURN GATE

M20.4.1 is the path to the user-perceived same-turn
"is this addressed to me?" capability. M20.4.1 owns:

- A `SameTurnAddresseeHypothesisGate` settler that runs
  AFTER the conscious loop (which produces the M18.7
  field) but BEFORE the reply commit, gated on
  `confidence > 0.85` AND `ambiguity_band == "high"` AND
  structural NOT explicit-addressee-of-another. The
  gate can flip the structural `no_reply` /
  `clarify_addressee` decision to `reply_to_current_speaker`
  in the SAME turn.
- This is the M20.4.1 acceptance gate. M20.4 acceptance
  does NOT include same-turn behavior. M20.4.1 is
  explicitly DEFERRED; the operator / acceptance
  reviewer MUST NOT expect same-turn behavior from
  M20.4 v1.

### Acceptance reviewer warning

M20.4 v1 ships cross-turn only. The user may submit a
test case like "this group turn's inbound message is
addressed to me, the assistant should reply in the
same turn". Under M20.4 v1, the test case FAILS — the
assistant replies in the next turn, not the current.
The acceptance gate is "feedback row appears in
diagnose, and T+1+ flip engages". The acceptance
gate is NOT "T0 reply changes".

M20.4 must NOT:

- Modify the M18.5 reply policy decision tree. The
  feedback row is a supplementary input, not an
  override.
- Auto-calibrate the producer admit threshold or
  the tie-breaker engagement threshold. M18.7.1
  calibration may revise them; that is M18.7.1
  territory.
- Persist the rationale text from the LLM judge.
  Engineering audits only `rationale_span` and
  `reason` (each bounded to ≤ 80 / ≤ 200 chars).
- Script visible apology or self-blame text about
  "mis-attribution".
- Claim subjective group understanding. The
  LLM judge is asked to confirm / violate, not
  to "know" or "feel" the group's intent.
- Unify Path A or M10.
- Promise same-turn behavior in v1. Same-turn is
  M20.4.1 territory.
