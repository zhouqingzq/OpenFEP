# OpenFEP M13.5 Work Prompt

## Milestone

M13.5: Idle Cognitive Refresh Tick

## Goal

Close the silence-period gap of the Path B fast loop. Today the Streamlit
implicit-idle fragment (M14.4) only polls `select_proactive_target` every 5s
and runs a full proposal check every 45s. It does **not** re-observe state,
re-run recall, re-evaluate M13.1/M13.2 drives, or refresh memory EFE on idle.
The result is that an open chat page after long silence keeps reporting
`no_traceable_proactive_target` while drive bands stay frozen at their
last-user-turn snapshot.

M13.5 turns each idle attempt into a **bounded cognitive refresh tick**:

```text
fragment fires (idle >= idle_threshold_seconds)
-> observe: state snapshot + temporal context (no new LLM call)
-> recall: bounded top-k against bound_memory_ids of eligible expectations
-> evaluate_memory_efe(phase="idle")
-> refresh M13.1 boredom / M13.2 reward bands using existing evaluators
   (no new emotion module; same deterministic updates run in run_turn)
-> select_proactive_target
-> audit: IdleCognitiveTickEvent with retrieved_ids, refreshed bands, target
   or reject_reason
-> hand to existing M13.3 proposal path if target is non-empty
```

This is **not** a new LLM loop. It is a deterministic refresh of the
state that `select_proactive_target` reads. No reply text is generated by
M13.5 itself; generation stays in `run_proactive_turn`.

## Architecture Position

M13.5 lives entirely on Path B:

```text
segmentum/dialogue/runtime/m14_4_implicit_idle.py    (entry point: fragment)
segmentum/dialogue/runtime/mvp_loop.py               (orchestrate refresh)
segmentum/dialogue/runtime/m13_memory_efe.py         (idle EFE re-eval)
segmentum/dialogue/runtime/m13_boredom.py            (idle band re-eval)
segmentum/dialogue/runtime/m13_reward.py             (idle band re-eval)
segmentum/dialogue/runtime/m14_3_proactive_alignment.py (select_proactive_target)
```

`_refresh_idle_proactive_drive_context` in `mvp_loop.py` already does part of
this (recall + memory_efe). M13.5 promotes it to a **named tick owner** that
also re-evaluates M13.1/M13.2 bands and emits a single composite audit event.

The Streamlit fragment itself remains 5s and continues to throttle full
checks to once per `DEFAULT_IMPLICIT_IDLE_ATTEMPT_INTERVAL_SECONDS` (45s).
M13.5 only changes **what happens inside one allowed attempt**.

## Dependencies

Hard:

- M9.0 `build_memory_dynamics_guidance` and existing recall helpers
- M13.0 / M13.1 / M13.2 evaluators (used in `run_turn`)
- M13.3 `evaluate_proactive_initiative`, `run_proactive_turn`
- M13.4 idle structural signals
- M13.6 `evaluate_memory_efe(phase="idle")`
- M14.3 `select_proactive_target`
- M14.4 Streamlit implicit-idle wiring

Soft:

- M14.0 reflector (reflector is **not** in the critical path of M13.5)
- M14.1 background continuity (separate process; M13.5 must not depend on it)

## Non-Goals

- Do not add a new LLM call per fragment tick. M13.5 is deterministic refresh.
- Do not introduce new drive scalars or new emotion modules. Reuse M13.1/M13.2.
- Do not let silence alone change band values. Re-evaluation must come from
  the same evaluator functions used in `run_turn`; their output may stay flat
  if no new memory recall or expectation due event fires.
- Do not bypass `run_proactive_turn` for generation.
- Do not run conscious loop or post-reply observer on the refresh path.
- Do not extend Path A or M10.
- Do not implement keyword/regex cue lists; refresh consumes structured
  state only.

## Required Work

### 1. Promote refresh helper to named tick owner

Rename / extract from `mvp_loop.py`:

```text
_refresh_idle_proactive_drive_context(state, m13_state, *, now, turn_index, ...)
-> IdleCognitiveRefreshResult
```

Add a new owner type:

```text
class IdleCognitiveTickOwner:
    def run(self, state, *, now, turn_index, idle_seconds) -> IdleCognitiveRefreshResult
```

Result fields:

```text
retrieved_ids: list[str]
memory_efe_evaluation: MemoryEfeEvaluation
m13_band_summary:
  boredom_band
  reward_band
  behavior_band
  relation_band
selected_target: ProactiveTarget | None
reject_reason: str
audit_events: list[dict]
```

State ownership rules:

```text
memory_efe snapshot           owner: M13.6 evaluator (unchanged)
boredom / reward band scalars owner: existing M13.1 / M13.2 evaluators (unchanged)
proactive target selection    owner: M14.3 select_proactive_target (unchanged)
proposal commit / delivery    owner: M13.3 (unchanged)
```

M13.5 only **orchestrates** these calls; it must not duplicate their logic.

### 2. Idle re-evaluation contract for M13.1 / M13.2

Both modules already expose evaluators that consume state + temporal context.
On idle:

- M13.1 boredom evaluator runs with `phase="idle"` and **does not increase**
  `boredom_level` from silence alone. It may update `repetition_pressure` if
  `recent_plan_terms` repetition signal warrants; it may decay
  `boredom_level` over long elapsed time only if existing decay rules say so.
- M13.2 reward evaluator runs with `phase="idle"` and **does not invent** new
  pending settlements. It may settle prior pending if the assessor (M13.6 or
  existing settlement helpers) flags an evidence change since last user turn.

Add explicit guards in code: idle-phase calls receive `user_text=""` and a
`silence_elapsed_seconds` scalar, but the evaluators must continue to ignore
`silence_elapsed_seconds` as a direct boredom or reward input.

### 3. Composite audit event

Replace today's ad-hoc `IdleProactiveDriveRefreshEvent` (or supersede it) with
a single canonical event:

```text
IdleCognitiveTickEvent
  at
  turn_index
  idle_seconds
  idle_threshold_seconds
  retrieved_ids
  memory_efe_should_outreach
  memory_efe_selected_policy
  bands:
    boredom_band
    reward_band
    behavior_band
    relation_band
  selected_target:
    trigger
    source_kind
    traceable_expectation_id
    evidence_refs
  reject_reason
  engineering_proxy_label = "mvp_local_idle_cognitive_tick"
```

`reject_reason` enum (closed):

```text
""                                # success: target selected
no_eligible_expectation
no_recall_hit_for_eligible
memory_efe_below_outreach_margin
no_high_value_target
generic_self_only_open_item
all_targets_traceability_failed
```

When `selected_target` is non-empty, the tick still routes through M13.3 for
final delivery gates. M13.3 suppression reasons (cooldown, session limit,
context_assessment_unsafe, opponent_strength_pre_block, etc.) remain
authoritative and are emitted by M13.3, not duplicated by M13.5.

### 4. Wire into M14.4 implicit-idle entry

In `m14_4_implicit_idle.py`:

```text
run_streamlit_implicit_idle_proactive(...)
  -> attempt throttle (unchanged)
  -> idle threshold gate (unchanged)
  -> NEW: chat_iface.run_idle_cognitive_tick(now, turn_index, idle_seconds)
          -> returns IdleCognitiveRefreshResult
          -> on selected_target == None: surface reject_reason as the
             implicit-idle suppression reason code; return without calling
             maybe_propose_proactive_turn
  -> if selected_target: chat_iface.maybe_propose_proactive_turn(
        implicit_idle_request=True,
        idle_seconds=...,
     )
  -> if proposal: run_proactive_turn (unchanged)
```

The Streamlit `@st.fragment(run_every="5s")` block is unchanged. Throttling
remains 45s. M13.5 only runs inside an allowed full attempt.

### 5. UI dashboard sync (minimal)

Mind / M14.3 panel must read the latest `IdleCognitiveTickEvent` for:

```text
- idle_seconds
- band summary
- reject_reason (when no target)
- selected_target.trigger / source_kind / evidence_refs (when target)
```

If panel data is older than the latest tick event, render a small "stale,
pending fragment rerun" badge. No new auto-rerun is required.

## Acceptance Criteria

M13.5 is complete when:

1. Each allowed implicit-idle attempt produces exactly one
   `IdleCognitiveTickEvent` with retrieved_ids, refreshed M13.1/M13.2 bands,
   memory-EFE outcome, and either a `selected_target` or a closed-enum
   `reject_reason`.
2. Boredom and reward bands do not increase from silence alone; their values
   match the evaluators' outputs given the same state on a user-turn path.
3. `select_proactive_target` is called with refreshed memory_efe and drive
   state, not with a stale snapshot from the last user turn.
4. The Streamlit fragment continues to run every 5s; full cognitive ticks
   are still gated by the existing 45s attempt throttle.
5. No new LLM call is introduced on the refresh path. Generation continues
   to go through `run_proactive_turn`.
6. Dashboard surfaces tick-level `reject_reason` instead of stale
   user-turn diagnostics.
7. M14.4 / M13.3 / M13.6 / M14.0 contracts remain intact; no Path A or M10
   wiring is added.
8. All listed tests pass.
