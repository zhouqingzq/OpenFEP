# OpenFEP M17.12 Work Prompt

## Milestone

M17.12: Path B Field Bridge And Unified Memory Recall Runtime

## Goal

Close the split between:

```text
Path B / mvp_loop dialogue recall
and
SegmentAgent / MemoryStore / path / local-field runtime
```

so that the product dialogue path no longer behaves like a separate
"session-JSON memory stack with some M17 side signals," but instead consumes
the same memory-credit, reconsolidation, path, and local-field substrate that
M17.5-M17.11 established in the core survival runtime.

Target contract:

```text
Path B reply turn
  -> prediction lock / settlement
  -> unified memory recall substrate
  -> active paths + local field + counterfactual audit
  -> reply planning / bundle choice
  -> verification outcome
  -> memory credit + reconsolidation + path refresh
  -> next Path B recall is changed by what just happened
```

This milestone is not "use field a little more." It is the bridge milestone
that makes the two half-loops become one operational demo path.

Hard principle:

```text
Path B must be able to exhibit a real field-required recall effect:
multiple individually insufficient memories jointly bias a decision,
while best-single and naive top-k would not have produced the same result.
```

If the bridge still leaves Path B's main recall owner as a ranked item list,
the milestone is not complete.

## Architecture Position

```text
Path B input / session turn
  -> prediction-locked dialogue state
  -> unified recall adapter
  -> MemoryStore / path neighborhood proposal
  -> local field construction
  -> bundle / response planning consumer
  -> reply execution
  -> settlement / verification
  -> memory credit + reconsolidation + path refresh
```

Recommended landing points:

```text
segmentum/mvp_loop.py
segmentum/runtime.py
segmentum/memory_store.py
segmentum/memory_field.py
segmentum/agent.py
segmentum/m14_7_memory_gate.py
segmentum/m13_memory_efe.py
```

If a bridge owner module is introduced, prefer:

```text
segmentum/m17_12_path_b_bridge.py
```

Recommended owner split:

```text
PathBRecallBridgeOwner
  -> adapts Path B recall requests onto the M17.8-M17.10 substrate

PathBFieldConsumerOwner
  -> makes bundle / reply planning consume active paths + local field

PathBSettlementWritebackOwner
  -> turns Path B settlement into M17.6 credit + M17.7 reconsolidation + M17.8 refresh

PathBDiagnosticsOwner
  -> makes field-required behavior visible in TUI/Web/audit traces
```

## Dependencies

Hard:

- M17.0-M17.4 Path B prediction-lock / settlement / gate / bundle loop
- M17.5 FE surrogate contract
- M17.6 verification-to-memory credit assignment
- M17.7 surprise-gated reconsolidation
- M17.8 path-first memory substrate
- M17.9 local field potential and counterfactual audit
- M17.10 goal priors and adaptive compute
- M17.11 held-out validation harness and fixture style

Soft:

- Existing `retrieve_memories_for_guidance` / Path B recall surfaces
- Existing session JSON persistence and long-term-memory projection
- Existing diagnostics / audit-tail surfaces in TUI/Web

Compatibility-sensitive:

- Existing Path B multi-turn scripted tests
- Existing session persistence semantics
- Existing MemoryGate / bundle decision surfaces
- Existing `long_term_memory` payload projections that may still be used by UI

## Non-Goals

- Do not revive Path A or M10.
- Do not create a third memory owner beside Path B state and `MemoryStore`.
- Do not require unbounded global field simulation in the dialogue path.
- Do not bypass prediction lock / settlement just to feed field signals faster.
- Do not replace the whole Path B reply planner with `SegmentAgent` wholesale.
- Do not claim "field in production" if Path B still only consumes ranked items.

## Required Work

### 1. Define a single Path B recall bridge contract

Introduce a Path B-facing recall object that is richer than a ranked memory list:

```text
PathBRecallBridgeResult:
  retrieved_items
  active_paths
  local_field
  counterfactual_audit
  goal_prior
  adaptive_compute
  provenance_refs
  writeback_targets
```

Rules:

- Path B may still expose `retrieved_items`, but they are no longer the sole
  decision owner.
- `active_paths` and `local_field` must be first-class fields in the main reply
  path, not diagnostics-only sidecars.
- The bridge result must be deterministic from the same input turn and state.
- The bridge must name provenance so settlement can write back into the same
  substrate later.

### 2. Make Path B main recall consume the M17.8-M17.10 substrate

Current Path B recall may start from coarse retrieval, but final recall guidance
must pass through:

```text
path neighborhood proposal
local field construction
goal prior shaping
adaptive compute budgeting
```

Requirements:

- the main Path B recall owner must read from the same `MemoryStore` / path
  substrate that M17.8-M17.10 use, or from a clearly documented projection of
  that same owner
- session JSON memory must become either:
  - a projection / persistence layer over the same substrate, or
  - a read-only compatibility shadow

It must no longer be the independent logic that actually drives recall.

### 3. Make Path B response planning consume field outputs, not only ranked items

At least one ordinary Path B decision stage must directly consume:

```text
active_paths
local_field.action_influences
counterfactual_audit
```

Recommended consumers:

```text
bundle assembly / evidence grouping
reply stance selection
clarify vs answer vs hedge choice
which memory bundle is allowed to steer the response
```

Required behavior:

- top-k remains neighborhood proposal only
- if `counterfactual_audit.status` is top-k-equivalent, Path B must not claim a
  field-required effect
- if `counterfactual_audit.status == field_required`, the actual Path B reply
  choice must be able to differ from the best-single / naive-top-k baseline

### 4. Unify Path B settlement writeback with M17.6-M17.8

Turn Path B settlement into real substrate updates:

```text
Path B prediction outcome
  -> memory credit signal
  -> surprise-gated reconsolidation
  -> path refresh
  -> next Path B recall changes
```

Rules:

- settlement must preserve linked memory/path provenance
- confirmed / violated / partial outcomes must update the same predictive
  reliability / contradiction / future-path-utility surfaces used elsewhere
- reconsolidation must remain surprise-gated; Path B must not reintroduce
  "recall implies rewrite"

### 5. Eliminate apples-to-oranges baseline comparisons in Path B diagnostics

When Path B reports:

```text
best_single
naive_topk
field_enabled
```

the comparison must hold fixed everything except the field/path decision owner.

Requirements:

- do not compare a full episodic-recall context against a stripped path-only
  baseline and call that a field win
- best-single must use the actual best single path/member, not list order
- naive-top-k must use the same bounded neighborhood, minus field-only effects
- field-enabled must use the same bounded context, with field active

This is a hard acceptance condition because it is the easiest place to fake a
field effect by accident.

### 6. Add one real Path B `field_required` scenario

There must be at least one end-to-end Path B scripted scenario where:

```text
best-single baseline does not produce the final reply behavior
naive-top-k baseline does not produce the final reply behavior
field-enabled Path B does produce that behavior
the behavior is explainable by multiple individually insufficient memories
```

The scenario must run through the ordinary Path B path:

```text
turn input
  -> main recall
  -> reply selection
  -> settlement / audit
```

not only through `memory_field.py` unit fixtures.

### 7. Preserve suppression behavior on ordinary top-k-equivalent turns

The bridge must also prove restraint:

- dominant single-path situations should remain top-k-equivalent
- field should suppress itself when it adds no unique decision value
- ordinary stable turns must not regress because "field exists"

This is as important as the positive case. A bridge that invents field effects
everywhere is a regression.

### 8. Make the field/path effect visible in product diagnostics

Path B-facing diagnostics must expose at least:

```text
retrieved_items
active_path_ids
field_selected_action_or_bundle
best_single_baseline
naive_topk_baseline
counterfactual_status
settlement_writeback_targets
```

Recommended event family:

```text
PathBRecallBridgeBuiltEvent
PathBFieldDecisionEvent
PathBFieldSuppressedEvent
PathBSettlementWritebackEvent
```

The effect must be visible in audit-tail / debug output without requiring deep
manual JSON archaeology.

## Acceptance Criteria

M17.12 is complete when:

1. Path B main recall exposes `active_paths`, `local_field`, and
   `counterfactual_audit` as first-class decision inputs.
2. Path B no longer relies on an independent ranked-item memory logic as the
   true recall owner; session JSON is only projection/persistence/shadow.
3. Path B settlement writes back into the M17.6-M17.8 substrate:
   credit, reconsolidation, and path refresh all occur on the same owner.
4. At least one ordinary Path B scripted scenario demonstrates a genuine
   `field_required` effect that best-single and naive-top-k do not reproduce.
5. Disabling the field removes that `field_required` behavior.
6. Top-k-equivalent situations are explicitly suppressed rather than mislabeled
   as field wins.
7. Best-single, naive-top-k, and field-enabled Path B diagnostics compare like
   with like; no apples-to-oranges baseline remains.
8. Path B diagnostics make the bridge observable without digging through raw
   internal dumps.
9. Existing dominant single-path turns do not regress.
10. Path A and M10 remain untouched.

## Verification Standard

Use a Path B scripted validation set with at least:

```text
one dominant single-path case
one top-k-equivalent multi-memory case
one genuine field-required case
one carry-over settlement case where next-turn recall changes
```

Expected:

```text
on the field-required case:
  Path B field-enabled reply differs from both best-single and naive-top-k
  and subsequent FE surrogate / verification outcome is better

on top-k-equivalent cases:
  counterfactual_status is suppressed_*
  and field does not claim unique value

after settlement:
  the next Path B turn sees changed recall due to credit/reconsolidation/path refresh

after restart:
  the persisted Path B state remains consistent with the shared memory substrate
```

If Path B still only uses the field as a diagnostic sidecar while the real reply
decision is driven by ranked memories alone, the milestone does not pass.
