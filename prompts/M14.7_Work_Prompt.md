# OpenFEP M14.7 Work Prompt

## Milestone

M14.7: Path B Memory Gate, Decay, And Precision-Weighted Recall

## Goal

M9.0 introduced `build_memory_dynamics_guidance` and a lightweight write
candidate channel on Path B. The full `segmentum/memory_dynamics.py` module
(retention pressure, decay, interference detection, reusable cognitive paths)
remains **unused** by `mvp_loop.py`. As a result:

- Every LLM-proposed `memory_writes` reaches the store with no surprise/
  value gate, so vague items accumulate.
- Long-term memory has no decay channel on Path B; salience never falls.
- Recall ranks by single-row lexical overlap + salience only; precision and
  recency are not used to gate eligibility for memory-EFE, and the output is
  still an item-ranked list rather than a grouped evidence surface.
- M13.6 keeps surfacing generic open items as candidates because nothing
  upstream filters low-value entries.

M14.7 wires a **deterministic memory gate** in front of every Path B write,
adds a slow decay channel readable on idle ticks, and upgrades recall scoring
with precision + recency factors. It does **not** rewrite the LLM thinking
write path; it adds a gate the existing path must pass through.

M14.7 intentionally stops at deterministic **coarse retrieval**. It may improve
which rows are eligible, but it must not be described as proving multi-memory
conjunctive behavior or "beyond top-k" policy changes by itself. Later M17.x
work may consume the scored candidate surface to assemble evidence bundles that
no single row could trigger alone.

The M9 series ends at M9.0. M14.7 is the Path B completion track for memory
gate, decay, and precision-weighted recall under the M14 idle/runtime family.

Target chain:

```text
LLM thinking writes / memory_dynamics.write_candidates / post-reply observer
-> normalize into MemoryWriteIntent
-> MemoryGate.evaluate(write_score)
-> commit if score >= threshold; else emit MemoryGateRejectedEvent
-> retention/decay updates LTM salience on idle tick
-> recall scoring uses (lexical overlap, salience, precision, recency, value)
-> downstream consumers may group scored rows, but M14.7 itself only owns the
   row-level coarse retrieval surface
```

## Architecture Position

```text
segmentum/memory_dynamics.py                          (existing; partially adopted)
segmentum/dialogue/runtime/mvp_loop.py              (apply gate before commit)
segmentum/dialogue/runtime/m14_7_memory_gate.py     (NEW: gate owner)
segmentum/dialogue/runtime/m14_7_memory_decay.py    (NEW: decay/retention owner)
segmentum/dialogue/runtime/m14_7_recall_scoring.py  (NEW: scoring helper)
```

The named owners follow the same M8.9 contract: prompt text never writes
directly; durable changes go through audited `MemoryWriteIntent` and named
patch owners.

The full Path A `memory_dynamics.py` exports are **read-only** sources for
M14.7; M14.7 wraps them in Path B owners. The Path A consumers (e.g.
`agent.py`, `m9_bus_integration.py`) are not touched.

## Dependencies

Hard:

- M8.9 state-ownership contract and `MemoryWriteIntent`
- M9.0 `build_memory_dynamics_guidance` (recall_query, write_candidates)
- M13.6 memory-EFE consumes the new eligibility scoring
- Existing MVP store schema for STM / LTM / open_items / pending_expectations

Soft:

- M14.0 idle reflector (uses gate-aware recall surface)
- M13.5 idle cognitive tick (calls decay update)

## Non-Goals

- Do not open a new M9.x milestone. M9.0 remains the integration baseline;
  M14.7 owns Path B gate/decay/recall completion.
- Do not introduce embedding-based vector recall. M14.7 stays in
  deterministic lexical + structural scoring; precision and recency add
  multiplicative factors, not a new vector index.
- Do not move write logic out of named owners. The gate is **in front of**
  the existing thinking-writes / write-candidates / observer paths.
- Do not implement keyword/regex cue lists to compute write_score; the score
  must come from structured fields (surprise, value, identity relevance,
  evidence presence, confidence). Free text content may be measured only by
  length / presence of evidence_refs, never by content keyword cues.
- Do not delete LTM rows. Decay only lowers salience and may flip a row to
  `archived` after a threshold. Archived rows remain readable for audit.
- Do not change the M13.6 eligibility schema; M14.7 only changes whether a
  row is eligible based on its post-gate, post-decay state.
- Do not claim that improved row scoring alone creates non-top-k behavior.
  M14.7 still returns scored rows, not bundle-triggered policy decisions.
- Do not extend Path A or M10.

## Required Work

### 1. MemoryWriteIntent + MemoryGate

Define / reuse:

```text
@dataclass
class MemoryWriteIntent:
    target: "short_term" | "long_term"
    kind: "episode" | "habit" | "preference" | "fact" | "expectation_bound"
    content: str
    confidence: float
    evidence_refs: list[str]
    identity_relevance: float       # 0..1; defaults 0
    value_proxy: float              # 0..1; from M13.2 reward proxy snapshot
    surprise_proxy: float           # 0..1; from M13.6 social/epistemic PE
    source: str                     # "thinking_writes" | "write_candidate" | "post_reply_observer"
    proposer: str                   # named module
    audit_reason: str
```

Gate:

```text
class MemoryGate:
    def evaluate(intent) -> MemoryGateDecision

@dataclass
class MemoryGateDecision:
    commit: bool
    write_score: float
    threshold: float
    factors: dict[str, float]
    violation_codes: list[str]
```

Write score formula (deterministic; weights configurable, default fixed):

```text
write_score =
    alpha * surprise_proxy
  + beta  * value_proxy
  + gamma * identity_relevance
  + delta * min(1.0, len(evidence_refs) / 2)
  + epsilon * confidence
```

Default weights (locked unless milestone is reopened):

```text
alpha=0.30  beta=0.25  gamma=0.15  delta=0.20  epsilon=0.10
```

Default thresholds:

```text
MEMORY_GATE_THRESHOLD_SHORT_TERM = 0.30
MEMORY_GATE_THRESHOLD_LONG_TERM  = 0.55
```

Violation codes (closed enum):

```text
missing_evidence_refs
content_too_short
content_too_long
confidence_below_floor
duplicate_of_recent_episode
gate_score_below_threshold
proposer_session_cap_reached
```

Per-session caps shared with existing owners (M14.0 sets some already):

```text
MAX_GATE_COMMITS_PER_SESSION_PER_PROPOSER = 8
```

### 2. Apply gate at every Path B write point

Wrap these existing call sites in `mvp_loop.py`:

```text
_apply_thinking_writes          -> route through MemoryGate.evaluate
_apply_memory_write_candidates  -> route through MemoryGate.evaluate
_apply_post_reply_memory_updates-> route through MemoryGate.evaluate
MemoryConsolidationOwner        -> already uses MvpMemoryWriteIntent;
                                   route through MemoryGate.evaluate
```

For each rejected intent, emit:

```text
MemoryGateRejectedEvent
  at, turn_index, source, proposer
  intent_summary (clamped)
  write_score, threshold, factors, violation_codes
```

For each committed intent:

```text
MemoryGateCommitEvent
  at, turn_index, source, proposer
  store_target, store_id
  write_score, factors
```

These events are diagnostic; the durable memory rows remain owned by the
existing store helpers.

### 3. Slow decay channel

Add `m14_7_memory_decay.py`:

```text
def apply_memory_decay_tick(state, *, now, turn_index) -> DecayResult
```

Rules:

- Only LTM rows participate.
- Each LTM row gets `last_recall_at`, `last_decay_at`, and a decay rate
  derived from `compute_retention_pressure` in `memory_dynamics.py`.
- On an idle tick (called by M13.5 / M14.0), salience drops by a bounded
  amount per elapsed unit; rows with `pin = true` or
  `identity_relevance >= IDENTITY_RELEVANCE_FLOOR` are exempt.
- When salience falls below `LTM_ARCHIVE_THRESHOLD` (default 0.05), row
  flips to `status = "archived"`. Archived rows remain readable.

Decay caps:

```text
MAX_DECAY_DELTA_PER_TICK = 0.05
MAX_ARCHIVE_FLIPS_PER_TICK = 3
```

Audit:

```text
MemoryDecayTickEvent
  rows_touched, rows_archived, rows_exempted
  engineering_proxy_label = "mvp_local_memory_decay"
```

Decay must be **side-effect free except for the listed fields**. It must
not touch open_items, pending_expectations, or M11/M12 ledgers.

### 4. Precision + recency in recall scoring

Add `m14_7_recall_scoring.py`:

```text
def score_recall_candidate(candidate, *, query, now, retrieved_context) -> float
```

Formula (deterministic, no LLM):

```text
score =
    w_lex * lexical_overlap_norm
  * w_sal * salience
  * w_prec * precision_factor      # from row.precision or default 0.5
  * w_rec * recency_factor         # exp decay over (now - last_recall_at)
  * w_val * value_proxy            # 0..1 from row or 0.5 default
```

Multiplicative, not additive, so any zero factor cancels the candidate.

`retrieve_memories_for_guidance` and `lexical_recall_short_term_candidates`
become consumers of the scoring helper. Existing call sites only swap the
scoring function.

The scoring helper is a stage-1 coarse retrieval owner. It should also expose a
compact factor breakdown for downstream diagnostics and future bundle assembly:

```text
ScoredRecallCandidate:
  memory_id
  score
  lexical_overlap_norm
  salience_factor
  precision_factor
  recency_factor
  value_factor
  evidence_refs
```

Rules:

- `score_recall_candidate` remains per-row and deterministic.
- M14.7 does not itself merge rows into hypotheses or decision bundles.
- Later consumers may group `ScoredRecallCandidate` rows, but they must not
  treat a high M14.7 row score as proof that one memory should control a
  downstream behavior.

### 5. Eligibility hook for M13.6

`normalize_expectations_for_efe` already filters vague / no-evidence rows.
M14.7 adds:

- A row is **ineligible for memory-EFE outreach** if all bound memory ids
  recall-score below `MEMORY_EFE_RECALL_FLOOR` (default 0.2).
- A row is ineligible if its `bound_memory_ids` rows are all archived.

These checks live in `m13_memory_efe.py` consuming the new scoring helper.
They emit:

```text
MemoryEfeEligibilityFilteredEvent
  expectation_id, filtered_reason_code
```

### 6. Backward compatibility

- Existing sessions without gate fields must be loaded with safe defaults
  (no panic, no migration script required for read).
- Existing tests in `test_m9_*`, `test_m13_6_*`, `test_m14_0_*` must continue
  to pass with default thresholds. When tests over-write small content
  expectations, gate weights may be tuned via a single test helper that
  patches the default thresholds; the helper must be the only path that
  bypasses gate thresholds in tests.

## Acceptance Criteria

M14.7 is complete when:

1. Every Path B memory write (thinking, write candidate, post-reply
   observer, idle consolidation) goes through `MemoryGate.evaluate`. Both
   commit and rejection emit audit events with full factor breakdowns.
2. LTM rows have salience that **can decrease** on idle ticks per the
   bounded decay rules; pinned and identity-relevant rows are exempt.
   Archived rows remain readable.
3. Recall scoring is precision- and recency-weighted; `retrieve_*` helpers
   use the new scoring function with no regression on existing tests.
4. The recall score remains a coarse per-row retrieval surface; factor
   breakdowns are exposed for diagnostics and future bundle consumers, but
   M14.7 makes no claim that row ranking alone creates bundle-level behavior.
5. M13.6 eligibility uses the new scoring helper; bound memories that fail
   the recall floor or are archived are filtered with a structured code.
6. Default gate weights and thresholds are documented in code; tuning in
   tests goes through a single helper, not ad-hoc per test.
7. No new LLM call is introduced. No keyword cue list is added.
8. No write to M11/M12 ledgers from M14.7 modules.
9. All listed tests pass; previously green M9/M13/M14 tests still pass.
