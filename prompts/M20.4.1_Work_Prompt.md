> Status: **DESIGN DRAFT — NO CODE CHANGES YET**. M20.4.1 is
> a sub-milestone of M20.4 that closes the G1 (cross-turn
> only) gap. M20.4 v1 ships cross-turn feedback; M20.4.1
> adds a same-turn addressee hypothesis gate so the user
> sees the assistant's reply (or its absence) in the SAME
> turn as the ambiguous inbound message.
>
> Open design questions are flagged `OPEN:`. Items already
> decided are flagged `DECIDED:`. Items deferred to a
> future milestone are flagged `DEFERRED:`.

## Milestone

M20.4.1: Same-Turn Addressee Hypothesis Gate — close the
G1 cross-turn-only gap by adding a deterministic, no-LLM
gate that runs after the conscious loop and before the
reply generation stages, conditionally flipping the M18.5
structural `no_reply` / `clarify_addressee` decision to
`reply_to_current_speaker`.

## Goal

Deliver the user-perceived same-turn capability for
"is this unaddressed group message directed at me?". M20.4
v1 ships cross-turn feedback only (the T0 turn that
triggers the ambiguous message still follows M18.5's
structural path; the flip shows on T+1+). M20.4.1 closes
the G1 gap by introducing a same-turn gate that runs
after the M18.7 hypothesis is produced and before the
reply is committed.

```text
M20.4 v1:                            |
   cross-turn feedback row              |
   (T+1+)                              v
+----------------------------------------------------------+
|  M20.4.1 (this sub-milestone)                            |
|  1. SameTurnAddresseeHypothesisGate                      |
|     - pure rule (no LLM)                                 |
|     - runs after conscious loop, before reply generation |
|     - gated on confidence > 0.85 + ambiguity high        |
|       + structural NOT explicit-addressee                |
|       + M18.5 decision was clarify/no_reply              |
|     - on fire: override action to reply_to_current_speaker|
|  2. Bus event: SameTurnAddresseeHypothesisGateVerdict    |
|  3. State surface: m20_4_1_same_turn_gate_outcomes       |
+----------------------------------------------------------+
                                |
                                v
T0 turn: user sees the assistant reply in the SAME turn
         (when the gate fires); otherwise the M18.5
         structural path applies unchanged
```

M20.4.1 is a thin same-turn gate. It does not invent new
vocabulary beyond one new bus event type and one new
state surface key. It does not add a new LLM stage. It
does not modify the M18.5 reply policy decision tree.
It is a peer of M20.3's `SameTurnSurfaceSettler` (which
handles `runtime_mode_state` block) but lives in a
different slot and serves a different purpose.

## Why M20.4.1 Exists

The M20.3 follow-up review + the M18.7 / M20.4 review
identified G1: the conscious loop runs AFTER
`_decide_group_reply_policy` in `mvp_loop.run_turn` (the
existing v1 ordering). M18.5's structural decision is
made before the M18.7 hypothesis is even available. M20.4
v1 ships a cross-turn feedback row in
`state["m18_5_attribution_feedback"]`; the flip shows on
T+1+.

For the user-perceived use case A ("is this inbound
message directed at me?"), the user expects the
assistant to reply in the SAME turn — not on T+1+. M20.4
v1 alone does NOT deliver this. The 15–25% same-turn band
in the M20.4 capability estimate is gated on the T+1+
flip; the user-perceived "this turn" capability is 0% on
T0 under M20.4 v1.

M20.4.1 is the same-turn path. It does NOT re-order
the conscious loop (which would be expensive: M18.7.2) or
add a new LLM stage (forbidden by the no-new-LLM-stage
constraint). Instead, M20.4.1 introduces a deterministic
gate that runs after the conscious loop and before the
reply generation stages, conditionally re-deciding the
M18.5 outcome in the same turn.

The gate is a pure rule (no LLM): it reads the M18.7
hypothesis + group_turn_binding + the M18.5 decision,
and applies the v1 conditions (matching the M20.4
cross-turn tie-breaker, per DECIDED 2 / DECIDED 6 in
`prompts/M20.4_Work_Prompt.md`). When the conditions
hold, the gate overrides the M18.5 decision to
`reply_to_current_speaker`.

## Hard Rules (CLAUDE.md compliance)

1. **No new LLM stage.** The gate is a pure rule.
   The M18.7 hypothesis is the LLM's contribution; the
   gate's logic is deterministic. This is a non-LLM
   engineering call, in line with CLAUDE.md "engineering
   may only validate fields, clamp mechanical values,
   persist state, and audit the result".

2. **No regex / keyword matching.** The gate reads
   `confidence` (numeric), `ambiguity_band` (frozen enum),
   and structural list emptiness. It does not parse
   user text, hypothesis text, or rationale.

3. **The semantic hypothesis never overrides structural
   signals.** The gate's rule requires BOTH
   `addressed_participant_ids` AND `mentioned_participant_ids`
   to be empty. An explicit mention of another
   participant means the gate stays no-op (M18.5 wins).
   This is the same rule as M20.4 v1 tie-breaker
   (DECIDED 2 / DECIDED 6 in M20.4 prompt, the C1 fix).

4. **The gate is gated on `confidence > 0.85` AND
   `ambiguity_band == "high"`.** Both conditions must
   hold; the LLM hypothesis alone is not enough.

5. **The gate does not modify the M18.5 decision tree.**
   M18.5's structural path is unchanged. The gate
   OVERRIDES the M18.5 outcome in the same turn when
   the rule fires — but M18.5 itself is not modified.
   M18.5's `_decide_group_reply_policy` returns the
   structural outcome; the gate reads that outcome and
   may override. M18.5's code path is unchanged.

6. **The gate is fast_chat safe.** The gate is a pure
   rule, no LLM. fast_chat may have a thin conscious
   that does not emit the M18.7 field (per M18.7
   DECIDED 13); in that case the gate sees an empty
   hypothesis and is silent. The gate NEVER forces
   full conscious in fast_chat.

7. **The gate does not persist rationale / participant_id
   beyond what M18.7 already persists.** The M18.7
   audit envelope does not include rationale (M18.7
   DECIDED 11); the gate inherits the same rule. The
   gate's bus event does NOT include rationale or
   `participant_id` after the M18.4 disclosure check.

8. **M20.4.1 is a sub-milestone of M20.4, not a peer.**
   M20.4.1 inherits all of M20.4's hard rules and
   adds the G1-closure constraint. M20.4 acceptance
   is independent of M20.4.1 acceptance; the
   operator can ship M20.4 v1 first and add M20.4.1
   later.

## Non-Goals

- **M20.4.1 does not modify the conscious loop.** The
  conscious loop still runs AFTER M18.5's structural
  decision (the v1 ordering). M20.4.1's gate runs after
  the conscious loop, not before.
- **M20.4.1 does not add a new LLM stage.** The gate is
  a pure rule.
- **M20.4.1 does not modify the M18.5 decision tree.**
  M18.5's structural path is unchanged. The gate
  OVERRIDES the outcome in the same turn when the
  rule fires; M18.5 itself is not modified.
- **M20.4.1 does not admit ActiveCommitment rows.** The
  gate is in-line (a function call), not a M20.1
  scheduler path. The bus event is the audit
  envelope, not an admission.
- **M20.4.1 does not auto-calibrate.** Thresholds are
  frozen at v1 values. M18.7.1 calibration may revise
  them; that is M18.7.1 territory.
- **M20.4.1 does not unify Path A, M10, or
  `conversation_loop.py`.**

## Required Work

### 1. New gate function (Tier A)

`SameTurnAddresseeHypothesisGate` is a pure function:

```text
def same_turn_addressee_hypothesis_gate(
    *,
    conscious_plan: Mapping[str, Any],
    group_turn_binding: Mapping[str, Any],
    m18_5_structural_decision: str,
    bus: list,
    state: dict,
    turn_index: int,
    now: str,
) -> SameTurnAddresseeHypothesisGateVerdict | None:
    """M20.4.1 same-turn gate.

    Returns a verdict if the rule fires (override to
    reply_to_current_speaker), or None when the rule
    doesn't fire (M18.5 structural path applies
    unchanged). The verdict is the bus envelope; the
    caller (mvp_loop.run_turn) updates the `action` in
    place to `reply_to_current_speaker` when the verdict
    is non-None.
    """
```

Inputs:

- `conscious_plan["addressee_hypothesis"]`: the M18.7
  structured field, or `{}` (empty) when the LLM
  declined / thin conscious skipped.
- `group_turn_binding`: the M18.2 v1 frozen shape;
  `ambiguity_band`, `addressed_participant_ids`,
  `mentioned_participant_ids`, `reply_to_turn_id`.
- `m18_5_structural_decision`: the M18.5 outcome
  (`reply_to_current_speaker`, `reply_to_named_third_party`,
  `reply_to_whole_group`, `clarify_addressee`,
  `defer_side_thread`, `no_reply`).

Outputs:

- `SameTurnAddresseeHypothesisGateVerdict` when the rule
  fires. The verdict carries:
  - `decision`: `"overridden_to_reply_to_current_speaker"`
  - `m18_5_structural_decision`: the original M18.5
    outcome (for audit)
  - `commit_ids`: list of the M18.7 hypothesis commit_ids
    (for cross-ref with M20.4 v1 dispatch)
  - `evidence_refs`: list of bounded handles (the M18.7
    evidence_refs)
  - `reason_codes`: tuple with `m20_4_1_same_turn_fired`
  - `engineering_proxy_label`: `mvp_local_group_attribution`
- `None` when the rule does not fire.


Emitted exactly once per `turn_index` when the rule
fires. NOT emitted when the rule does not fire.

### 3. State surface (Tier B)

A new bounded audit surface on `state`:

```text
state["m20_4_1_same_turn_gate_outcomes"]: list[dict]
  # Bounded tail, ≤ 8 entries (rolling window of the most
```

Engineering does not write to this surface directly; the
gate function writes one entry per turn that fires.

### 4. Wiring into `mvp_loop.run_turn` (Tier A)

A new step in the run_turn call order:

```text
1. _decide_group_reply_policy        <- M18.5 structural decision
                                       (existing v1; T0)
2. conscious loop (LLM)             <- M18.7 fields produced
3. <NEW> same_turn_addressee_hypothesis_gate(
       conscious_plan=conscious,
       group_turn_binding=group_turn_binding,
       m18_5_structural_decision=action,
       bus=bus, state=state, turn_index=turn_index, now=now,
   )
   if verdict is non-None:
       action = "reply_to_current_speaker"
       (in-place override; the M18.5 structural decision
        is preserved in the audit envelope)
4. PolicyProducer (M20.3)             <- emits policy commitments
5. M20.4 producer                       <- emits attribution commitments
6. LoopInvariants (M20.3)               <- audit-only
7. _admit_active_commitments, _settle, _dispatch  <- M20.0–M20.2
8. thinking, memory dynamics, recall    <- existing v1
9. M20.3 same_turn_surface pre-send gate <- runtime_mode_state block
10. validate_visible_reply
11. reply commit
```

The gate runs at step 3, IMMEDIATELY after the conscious
loop. This is the EARLIEST point where the M18.7
hypothesis is available and the M18.5 decision can be
overridden before any downstream stage consumes
`action`.

```text
        decision is again "clarify_addressee" or
        "no_reply" (the v1 cross-turn path still runs
        in parallel for T+1+)
```

The fixture asserts the user sees the assistant reply
in T0 (the same turn as the ambiguous message).

## Acceptance Criteria

M20.4.1 is complete only if:

1. `same_turn_addressee_hypothesis_gate` is implemented
   as a pure function with the v1 rule
   (confidence > 0.85 AND ambiguity_band == "high"
   AND empty addressed/mentioned/reply_to).
2. The gate runs IMMEDIATELY after the conscious loop
   in `mvp_loop.run_turn` (step 3 in §4 above) and
   BEFORE the reply generation stages.
3. When the rule fires, the gate overrides the M18.5
   structural decision to `reply_to_current_speaker` in
   place. The downstream stages (thinking, memory
   dynamics, recall, reply generation) read the
   overridden `action`.
4. When the rule does not fire, the gate is silent.
   No override. No bus event. M18.5's structural
   decision is unchanged.
5. `SameTurnAddresseeHypothesisGateVerdict` is emitted
   exactly once per `turn_index` when the rule fires;
   not emitted when the rule does not fire.
6. The M18.5 structural decision is preserved in the
   audit envelope (`m18_5_structural_decision` field)
   so the diagnose surface can show both the original
   decision and the override.
7. The 6+1+1 master fixture passes the new same-turn
   sub-scenario: T0 reply is present when the gate
   fires, T0 reply is absent when the gate doesn't
   fire, with the audit envelope matching.
8. M20.4.1 does not modify the conscious loop, the
   M18.5 decision tree, the M20.3 paths, or the M20.4
   v1 paths. All v1 / v2 / M20.3 / M20.4 v1 tests
   continue to pass.
9. The gate is fast_chat safe (no LLM, pure rule).
10. M20.4.1 is a sub-milestone of M20.4. M20.4 v1
    acceptance is INDEPENDENT of M20.4.1 acceptance.
    M20.4.1 ships after M20.4 v1 if the operator
    wants the same-turn capability.

## OPEN Design Questions

1. **OPEN: Where in the run_turn call order does the
   gate run, exactly?**
   - Step 3 (immediately after conscious loop): the
     earliest point; downstream stages read the
     overridden `action`.
   - Step 8 (after thinking / memory dynamics): the
     gate sees the reply draft and may decide based on
     the draft's content (but the gate is rule-based
     and does not read the draft, so this is moot).
   - Step 9 (in the same slot as M20.3 pre-send gate):
     unified same-turn-gate surface.
   - **Recommendation:** step 3. Earliest, simplest,
     most aligned with the user-perceived "this turn"
     framing. The gate is a pure rule; running it
     earlier does not cost anything.

2. **OPEN: Does the gate run for the reaction attribution
   (M18.7 `reaction_attribution_hypothesis`) too, or
   only for the addressee?**
   - Addressee only: the gate closes the user-perceived
     "is this directed at me?" capability. Reaction
     attribution is a T+1 path (M20.4 v1 already
     handles it).
   - Both: the same-turn gate could also re-decide
     reactions. But the reaction's user-perceived effect
     is on the NEXT assistant turn (the reaction to a
     prior turn is observed AFTER the prior turn is
     committed).
   - **Recommendation:** addressee only. M20.4.1 is
     scoped to the addressee hypothesis; reaction
     attribution stays on the M20.4 v1 T+1 path.
     M20.4.1.1 (a future sub-milestone) may extend the
     same-turn gate to reactions.

3. **OPEN: When the gate fires and overrides
   `action` to `reply_to_current_speaker`, does the
   downstream code still treat the M18.5 decision as
   authoritative for non-reply side effects (e.g.,
   memory writes, episode aggregation)?**
   - Yes: the M18.5 decision is the authoritative
     "what did the structural path decide" record;
     the override only affects the visible reply. Side
     effects (memory, episode) read M18.5's outcome.
   - No: the override changes the "decision" everywhere.
   - **Recommendation:** yes. The override is a
     visible-reply patch; side effects are recorded
     against the M18.5 structural outcome. The audit
     envelope preserves both for diagnose.

   `confidence > 0.85` AND `ambiguity_band == "high"`

   `mentioned_participant_ids is empty` AND
   `reply_to_turn_id is None` AND
   `m18_5_structural_decision in
