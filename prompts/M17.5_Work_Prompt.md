# OpenFEP M17.5 Work Prompt

## Milestone

M17.5: Free Energy Surrogate Contract And Decomposition

## Goal

Turn the current mixed free-energy vocabulary into one explicit surrogate
contract for the core survival runtime.

Target contract:

```text
observation + prediction + body pressure
  -> canonical prediction-error decomposition
  -> canonical free-energy surrogate
  -> canonical expected-free-energy surrogate
  -> the same components appear in decision, memory, verification, and sleep
```

M17.5 does not claim that the runtime has a full learned generative-model free
energy. It does the opposite: it makes the current engineering surrogate
honest, stable, and auditable so later milestones can improve it without
semantic drift.

The hard rule is:

```text
same name -> same quantity
same quantity -> one bounded owner
```

If the code currently uses `prediction_error`, `surprise`, `risk`,
`free_energy_drop`, and `expected_free_energy` with slightly different meanings
in different places, M17.5 must stop that drift.

## Architecture Position

This milestone starts a core-runtime track that targets the existing
`segmentum/agent.py` survival loop rather than the M16 Path B dialogue runtime.

```text
perception
  -> error vector
  -> FreeEnergySurrogate
  -> action projection / EFE surrogate
  -> memory write path
  -> verification linkage
  -> sleep replay and consolidation metrics
```

Recommended owner split:

```text
FreeEnergySurrogateOwner  -> canonical scalar/vector decomposition
SegmentAgent              -> perception/action call sites only
PreferenceModel           -> bounded EFE consumer, not a second FE owner
Memory / Sleep            -> read-only consumers of canonical FE fields
```

Recommended landing points:

```text
segmentum/agent.py
segmentum/preferences.py
segmentum/world_model.py
segmentum/memory.py
segmentum/memory_store.py
segmentum/tracing.py
```

If a new helper module is introduced, prefer a narrow owner such as:

```text
segmentum/fep_surrogate.py
```

## Dependencies

Hard:

- Existing `compute_free_energy(...)` and action projection path
- Existing `PreferenceModel.expected_free_energy(...)`
- Existing memory episode and sleep summary payloads

Soft:

- Existing verification / ledger signals as future downstream consumers
- Existing diagnostics and trace surfaces

Compatibility-sensitive:

- Existing artifact readers that expect `surprise`, `prediction_error`,
  `free_energy_drop`, or legacy scalar-only summaries
- Existing tests that compare old scalar fields directly

## Non-Goals

- Do not claim a true variational free-energy objective in this milestone.
- Do not introduce a learned probabilistic world model yet.
- Do not change memory write policy logic beyond renaming and decomposition
  cleanup.
- Do not add field dynamics, bundle policy, or adaptive compute here.
- Do not silently redefine old scalar names while keeping the same labels.
- Do not touch Path A or M10.

## Required Work

### 1. Define the canonical surrogate vocabulary and owner contract

Create one bounded decomposition used everywhere in the core runtime:

```text
raw_prediction_error
precision_weighted_prediction_error
body_pressure
ambiguity_cost
risk_cost
novelty_signal
free_energy_surrogate
expected_free_energy_surrogate
free_energy_delta
```

Rules:

- `raw_prediction_error` must mean observation/prediction mismatch only.
- `precision_weighted_prediction_error` must mean mismatch after precision
  weighting only.
- `body_pressure` must contain energy/stress/fatigue/temperature burden only.
- `free_energy_surrogate` must not silently include action ambiguity or future
  risk.
- `expected_free_energy_surrogate` may include action ambiguity and bounded
  future risk, but it must cite those parts explicitly.
- `surprise` may remain as a legacy compatibility alias in some payloads, but
  new logic must point to the canonical field names.

Add one canonical typed owner such as:

```text
FreeEnergySurrogate:
  raw_prediction_error
  precision_weighted_prediction_error
  body_pressure
  novelty_signal
  free_energy_surrogate
  component_errors:
    food_error
    danger_error
    novelty_error
    shelter_error
    temperature_error
    social_error
  body_components:
    energy_pressure
    stress_pressure
    fatigue_pressure
    thermal_pressure
```

And one projected shape such as:

```text
ExpectedFreeEnergySurrogate:
  predicted_error
  risk_cost
  ambiguity_cost
  expected_free_energy_surrogate
  predicted_outcome
```

The implementation may choose different names, but there must be one canonical
typed contract rather than several unrelated dict conventions.

### 2. Normalize the decision-path entry points

Update the perception/action path so:

```text
SegmentAgent.compute_free_energy(...)
PreferenceModel.expected_free_energy(...)
world-model action projection
decision diagnostics
```

all read from the same decomposition contract.

Requirements:

- The scalar currently returned by `compute_free_energy(...)` must be traceable
  to explicit subcomponents.
- The scalar currently used as `expected_free_energy` in option ranking must be
  traceable to `predicted_error + risk_cost + ambiguity_cost`.
- If a compatibility alias must remain in artifacts, it should be derived from
  the canonical owner, not recomputed ad hoc.
- The runtime must not have one FE formula in `agent.py` and a second silent
  FE-like formula in `preferences.py`.
- Precision weighting must be applied in one owner path, not manually rebuilt
  by downstream callers.

### 3. Normalize memory, verification, and sleep artifact usage

Update memory-related payloads so they can distinguish:

```text
observed present error
stored episode surprise proxy
projected future error
free-energy improvement or worsening
```

Requirements:

- `MemoryDecision`
- episodic payloads
- `MemoryEpisode`
- sleep replay summaries
- verification-side or ledger-side audit payloads, where relevant

must all reference the same canonical FE fields or explicit adapters.

`free_energy_drop` may remain as a compatibility field, but it must be defined
as a delta over the canonical surrogate rather than as an isolated local
convention.

Required distinction:

```text
present FE surrogate             -> current mismatch + body pressure
expected FE surrogate            -> projected predicted_error + risk + ambiguity
free_energy_delta / drop         -> change between two canonical FE states
legacy surprise field            -> documented alias only
```

### 4. Add migration, compatibility, and alias policy

Document which existing fields are:

```text
canonical
derived aliases
legacy compatibility only
deprecated and scheduled for removal
```

Rules:

- Legacy fields may remain in snapshots or traces, but new logic must not
  depend on them as independent sources of truth.
- If artifact readers require old names, adapters must derive them from the
  canonical surrogate owner.
- If the implementation keeps `surprise`, it must specify whether it aliases
  `precision_weighted_prediction_error` or a documented derivative. It must not
  silently drift between meanings.

### 5. Add trace-level audit and replay-facing diagnostics

Every decision-cycle trace should be able to answer:

```text
what was the raw mismatch?
what part was body pressure?
what extra part made this expected FE rather than present FE?
```

Recommended outputs:

```text
decision diagnostics
memory write audit
sleep replay audit
```

Recommended structured outputs:

```text
FreeEnergyTraceEvent
ExpectedFreeEnergyTraceEvent
FreeEnergyCompatibilityAdapter
```

Minimum trace fields:

```text
cycle_id
free_energy_surrogate
expected_free_energy_surrogate
raw_prediction_error
precision_weighted_prediction_error
body_pressure
risk_cost
ambiguity_cost
legacy_aliases_emitted
```

### 6. Add explicit decomposition tests and negative controls

M17.5 must include tests that prove:

- present FE does not silently include future ambiguity
- expected FE does not silently drop risk or ambiguity terms
- compatibility aliases are derived rather than independently recomputed
- memory and sleep payloads preserve the same meanings as decision-time traces

## Acceptance Criteria

M17.5 is complete when:

1. One canonical FE surrogate contract exists for the core runtime.
2. `compute_free_energy(...)` and projected `expected_free_energy` can each be
   decomposed into explicit bounded components.
3. Decision diagnostics, memory writes, and sleep summaries all expose the same
   FE vocabulary or a documented adapter.
4. No new code path introduces a second incompatible meaning for
   `prediction_error`, `surprise`, or `expected_free_energy`.
5. Compatibility fields such as `free_energy_drop` are explicitly derived from
   the canonical surrogate.
6. Documentation clearly states that this is still a surrogate contract, not a
   full learned generative-model free-energy objective.
7. Path A and M10 remain untouched.

## Verification Standard

Use one deterministic fixture where:

```text
the observation mismatches prediction on at least two channels
body pressure is non-zero
future action projection introduces ambiguity and bounded risk
```

Expected:

```text
FreeEnergySurrogate.free_energy_surrogate
  == precision_weighted_prediction_error + body_pressure

ExpectedFreeEnergySurrogate.expected_free_energy_surrogate
  == predicted_error + risk_cost + ambiguity_cost
```

Use the same cycle in:

```text
decision trace
memory write payload
sleep replay summary
```

Expected:

```text
the same canonical FE field names or documented adapters appear in all three
legacy aliases, if emitted, are marked compatibility-only
```
