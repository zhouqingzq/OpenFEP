# OpenFEP M18.1 Work Prompt

## Milestone

M18.1: Multi-Participant Identity Contract

## Goal

Upgrade Path B from a single `current_interlocutor` model to a bounded
multi-participant contract where each participant remains distinct across
runtime, memory writes, transcript replay, and diagnostics.

This milestone is about participant identity ownership, not yet about
full reply selection.

It defines who the participants are and how runtime state refers to them.
It does not own transcript persistence format details; those belong to M18.3.
It should be the runtime-facing participant registry layer that upstream M11/M12
cards and models attach to, rather than a second conflicting identity owner.

## Problem

Today Path B can accept `speaker_name`, but that is not the same thing as a
real participant model.

Failure mode:

```text
speaker_name changes per turn
but transcript / observer / memory / diagnostics still flatten humans into
"the interlocutor"
```

That is not group-chat ready.

## Required Work

### 1. Introduce a participant contract

Define a first-class participant object, for example:

```text
GroupParticipant:
  participant_id
  display_name
  aliases
  source_user_id
  active_in_turn
  mentionable_names
  trust_scope
```

At minimum, this milestone must also define the minimal ingress envelope that
binds a turn to participants before any reply policy runs, for example:

```text
GroupTurnEnvelope:
  speaker_participant_ref
  visible_participant_refs
  reply_to_turn_ref?
  quoted_turn_refs?
  explicit_mention_spans?
```

This envelope may be partially populated by the client, gateway, or runtime,
but the ownership contract must specify which fields are authoritative when
present.

It must also specify how `participant_id` relates to existing user-model
surfaces:

- M11/M12-style per-user or per-participant cards may be referenced through the
  participant registry
- M18.1 must not require a second divergent identity directory with its own
  truth source
- if legacy `speaker_name`-derived identities exist, the contract must state
  how they are upgraded or aliased into stable participant refs

### 2. Replace flattened turn ownership where needed

At minimum, Path B must stop losing speaker ownership in:

- short-term memory rows
- event-bus audit rows
- prompt-safe replay context

M18.1 should establish ownership references for transcript rows, but the
storage schema, persistence, and migration of those rows remain M18.3 work.

### 3. Preserve participant identity through restart

Session reload must not erase who said which previous turn.

### 4. Keep compatibility bounded

Single-user chat must still work without extra setup.

If the surface only provides `speaker_name`, the runtime may derive a bounded
participant record, but it must mark missing ownership evidence as degraded
rather than pretending full multi-party certainty.

## Acceptance

This milestone is complete only if:

- two or more participants can alternate without collapsing into one bucket
- a turn can carry more ownership structure than `speaker_name` alone when the
  surface provides it
- transcript replay preserves per-turn speaker identity
- restart preserves participant ownership
- there is at least one regression proving Alice/Bob separation beyond
  `m11_user_models`
