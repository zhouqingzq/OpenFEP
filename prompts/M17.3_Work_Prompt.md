# OpenFEP M17.3 Work Prompt

## Milestone

M17.3: Offline Calibration And Memory-Ablation Harness

## Goal

Make the M17 prediction-error memory loop falsifiable on historical logs.

M17.3 answers two questions:

```text
Calibration:
  When the system commits confidence 0.80, does it confirm about 80% of the time?

Ablation:
  Does prediction-error-driven memory selection reduce future prediction error
  more than heuristic salience or random/recency baselines?
```

If the error-driven policy does not outperform baselines on replay, this
milestone should say so clearly. The goal is not to prove the theory by prose;
the goal is to make failure visible.

## Architecture Position

```text
conversation logs + episode ledger + prediction ledger
  -> deterministic replay loader
  -> calibration metrics
  -> memory-policy ablation simulator
  -> reports/m17_3_prediction_error_replay.md
  -> artifacts/m17_3/*
```

This harness is offline. It must not mutate live persona state or require the
M16 runner to be active.

## Dependencies

Hard:

- M17.0 prediction lock rows
- M17.1 deterministic settlement/error rows
- M17.2 calibration and memory gate factors
- M15.0 episode ledger JSONL

Soft:

- Existing fixtures under `fixtures/`
- Existing report/artifact conventions

## Non-Goals

- Do not call the live LLM during replay.
- Do not mutate persona/session JSON state.
- Do not claim statistical significance when sample counts are too low.
- Do not compare policies on different input histories.
- Do not make salience baseline secretly use prediction outcomes.
- Do not replace production MemoryGate behavior based on one replay run.
- Do not touch Path A or M10.

## Required Work

### 1. Replay data loader

Add:

```text
segmentum/dialogue/runtime/m17_replay.py
scripts/run_m17_replay.py
```

The loader must read one or more session directories or explicit files:

```text
conversation_log.jsonl
memory_dynamics_episodes.jsonl
persona/session state snapshots when available
```

It should normalize:

```text
PredictionLockedEvent
PredictionSettlementAddendum
UserPredictionLedger entries
MemoryGateCommitEvent / MemoryGateRejectedEvent
NoveltySignalEvent
```

Missing optional files should produce warnings, not crashes. Missing prediction
or settlement data means calibration cannot be computed for that session.

### 2. Calibration metrics

Compute and write:

```text
overall_brier_score
brier_by_prediction_type
hit_rate_by_confidence_bin
expected_calibration_error
sample_count_by_type
unclear_rate_by_type
overconfidence_flags
```

Confidence bins should match M17.2:

```text
0.50-0.60
0.60-0.75
0.75-0.85
0.85-0.90
```

Output:

```text
artifacts/m17_3/calibration_metrics.json
artifacts/m17_3/calibration_table.csv
```

If `sample_count < 30` overall or `< 10` for a type, label results
`low_sample_warning`.

### 3. Policy ablation simulator

Implement an offline simulator that replays the same chronological events while
selecting memory candidates under three policies:

```text
A. prediction_error_driven
B. legacy_salience_proxy
C. random_or_recency_baseline
```

First-version simulator constraints:

- It may approximate memory availability by candidate ids and linked evidence,
  not by regenerating LLM responses.
- It must never peek at future settlement outcomes when deciding whether to
  retain a memory at a prior turn.
- For each policy, estimate future prediction error over subsequent settled
  predictions whose evidence could have used retained memories.
- Use the same input session order and budget for all policies.
- Random baseline must accept a seed and write it to artifacts.

Required metrics:

```text
future_prediction_error_mean
future_brier_mean
retained_memory_count
retained_memory_cost
coverage_of_future_predictions
policy_delta_vs_random
policy_delta_vs_salience
```

Output:

```text
artifacts/m17_3/ablation_metrics.json
artifacts/m17_3/policy_comparison.csv
```

### 4. Report

Add:

```text
reports/m17_3_prediction_error_replay.md
```

Sections:

```text
Data Sources
Calibration Results
Policy Ablation Results
Low-Sample / Missing-Data Warnings
Failure Cases
Recommendation
```

The recommendation must be honest:

```text
continue
continue_with_caution
revise_memory_gate
abandon_error_driven_gate_for_now
```

Include concrete next actions based on metrics, not theory preference.

### 5. CLI

Add a command:

```text
python scripts/run_m17_replay.py --session <path> --out artifacts/m17_3 --seed 17
```

Options:

```text
--session PATH          repeatable
--glob PATTERN          optional batch selection
--out PATH
--seed INT
--max-sessions INT
--fail-on-low-sample    optional CI mode
```

The script should print a short summary:

```text
sessions_loaded=...
settled_predictions=...
overall_brier=...
ece=...
prediction_error_policy_delta_vs_salience=...
recommendation=...
```

## Acceptance Criteria

M17.3 is complete when:

1. The replay harness runs without a live LLM.
2. Calibration metrics are deterministic from the same input files.
3. The ablation compares prediction-error, salience, and random/recency policies
   on the same event history and memory budget.
4. Low-sample results are labeled instead of overclaimed.
5. Artifacts and report are written under the expected paths.
6. The report can recommend continuing or abandoning the gate based on metrics.
7. New tests pass.
8. Path A and M10 remain untouched.

## Verification Standard

Use a tiny deterministic fixture where:

```text
prediction_error_driven retains the evidence memory used by later predictions
legacy_salience_proxy retains a high-salience but irrelevant memory
random retains a seed-stable mix
```

Expected:

```text
prediction_error_driven.future_prediction_error_mean
  < legacy_salience_proxy.future_prediction_error_mean

prediction_error_driven.future_prediction_error_mean
  < random_or_recency_baseline.future_prediction_error_mean
```

Also include a counter-fixture where the prediction-error policy does not win.
The harness must report that honestly rather than forcing a positive result.
