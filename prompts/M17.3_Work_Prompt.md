# OpenFEP M17.3 Work Prompt

## Milestone

M17.3: Offline Calibration And Memory-Ablation Harness

## Goal

Make the M17 prediction-error memory loop falsifiable on historical logs.

M17.3 answers two questions:

```text
Calibration:
  When the system commits confidence 0.80, does it confirm about 80% of the time?

Discrimination:
  Do higher-confidence predictions actually separate confirmations from
  violations, or are they merely easy base-rate bets?

Ablation:
  Does prediction-error-driven bundle selection reduce future prediction error
  more than best-single-memory, heuristic salience, or random/recency baselines?
```

If the error-driven policy does not outperform baselines on replay, this
milestone should say so clearly. The goal is not to prove the theory by prose;
the goal is to make failure visible.

If the policy only matches what the best single memory would already have done,
the harness must label that result as top-k-equivalent rather than treating it
as evidence of a new behavior class.

## Architecture Position

```text
conversation logs + episode ledger + prediction ledger
  -> deterministic replay loader
  -> calibration metrics
  -> memory-policy ablation simulator
  -> reports/m17_3_prediction_error_replay.md
  -> artifacts/m17_3/*
```

This harness is offline. It must not mutate live persona state or require the
M16 runner to be active.

M17.3 is allowed to run early on deterministic fixtures before production M17
data exists. Early fixture mode should report coverage and low-sample warnings
rather than pretending to validate production behavior.

## Dependencies

Hard:

- M17.0 prediction lock rows
- M17.1 deterministic settlement/error rows
- M17.2 calibration and memory gate factors
- M15.0 episode ledger JSONL

Soft:

- Existing fixtures under `fixtures/`
- Existing report/artifact conventions

## Non-Goals

- Do not call the live LLM during replay.
- Do not mutate persona/session JSON state.
- Do not claim statistical significance when sample counts are too low.
- Do not compare policies on different input histories.
- Do not make salience baseline secretly use prediction outcomes.
- Do not replace production MemoryGate behavior based on one replay run.
- Do not treat good calibration alone as evidence that predictions are useful.
- Do not claim UX improvement unless a scripted multi-turn fixture or observed
  transcript shows a downstream recall/reply-policy change.
- Do not touch Path A or M10.

Output:

```text

```

If `sample_count < 30` overall or `< 10` for a type, label results
`low_sample_warning`.

Non-triviality constraints:

- A prediction type with high hit rate but little confidence separation between
  confirmations and violations must be flagged as `weak_discrimination`.
- Repeated base-rate claims such as "user will want implementation details" may
  be calibrated but should not be treated as strong evidence for memory-policy
  value unless they improve future prediction or reply-policy outcomes.
- If `unclear_rate` is high, report calibration as coverage-limited even when
  Brier/ECE look good.

### 3. Policy ablation simulator

Implement an offline simulator that replays the same chronological events while
selecting memory candidates under these policies:

```text
A. prediction_error_bundle_policy
B. best_single_memory_baseline
C. naive_additive_topn_baseline
D. legacy_salience_proxy
E. random_or_recency_baseline
```

First-version simulator constraints:

- It may approximate memory availability by candidate ids and linked evidence,
  not by regenerating LLM responses.
- It must never peek at future settlement outcomes when deciding whether to
  retain a memory at a prior turn.
- For each policy, estimate future prediction error over subsequent settled
  predictions whose evidence could have used retained memories.
- Use the same input session order and budget for all policies.
- Random baseline must accept a seed and write it to artifacts.
- Define `could have used retained memories` before computing policy scores.
  First-version definition should be based on time-valid evidence links,
  prediction ids, episode ids, or bounded evidence refs, not raw text keyword
  overlap alone.
- Bundle-policy decisions must be auditable by member memory ids, best-single
  counterfactual score, and `synergy_margin`.
- A decision may count as `bundle_required` only when aggregated support meets
  the bundle threshold while every member remains below the single trigger
  threshold under the same scoring regime.
- The naive additive baseline must see the same top-N candidates and budget as
  the bundle policy but may ignore structured grouping, redundancy penalties,
  and contradiction penalties. If bundle-policy gains disappear against this
  baseline, the report must classify the result as weak evidence for genuine
  conjunctive behavior.
- If the bundle policy never produces `bundle_required` decisions on a fixture,
  report `top_k_equivalent_behavior` instead of overclaiming a bundle advantage.
- If the evidence-link definition is too sparse to compare policies, emit
  `insufficient_evidence_linkage` rather than forcing a policy delta.
- Run ablation only after reporting calibration quality. If settlement
  calibration is poor or coverage is too low, the report must say that ablation
  conclusions are not actionable.
- Run a small parameter sensitivity sweep over `SINGLE_TRIGGER_THRESHOLD`,
  `BUNDLE_TRIGGER_THRESHOLD`, `MIN_SYNERGY_MARGIN`, and redundancy penalty
  strength. If the bundle advantage exists only in a knife-edge setting, the
  report must say so.

## Acceptance Criteria

M17.3 is complete when:

1. The replay harness runs without a live LLM.
2. Calibration metrics are deterministic from the same input files.
3. Coverage, unclear, expiration, and episode-linkage diagnostics are reported.
4. Discrimination / non-triviality metrics are reported alongside calibration.
5. The ablation compares bundle, best-single, naive-additive, salience, and random/recency
   policies on the same event history and memory budget.
6. The report labels top-k-equivalent outcomes when the bundle policy does not
   produce bundle-required decisions or cannot beat the best-single baseline.
7. The report labels weak-conjunctive outcomes when bundle gains disappear
   against the naive additive baseline or exist only at knife-edge parameters.
8. Low-sample and insufficient-linkage results are labeled instead of
   overclaimed.
9. The report separates measurement validity, memory-policy validity, and UX
   validity.
10. Artifacts and report are written under the expected paths.
11. The report can recommend continuing or abandoning the gate based on metrics.
12. New tests pass.
13. Path A and M10 remain untouched.

## Verification Standard

Use a tiny deterministic fixture where:

```text
prediction_error_bundle_policy retains a bundle of weak memories used by later predictions
best_single_memory_baseline sees the same members but none alone cross the trigger
naive_additive_topn_baseline sees the same candidates but ignores structured penalties
legacy_salience_proxy retains a high-salience but irrelevant memory
random retains a seed-stable mix
```

Expected:

```text
prediction_error_bundle_policy.future_prediction_error_mean
  < best_single_memory_baseline.future_prediction_error_mean

prediction_error_bundle_policy.future_prediction_error_mean
  < naive_additive_topn_baseline.future_prediction_error_mean

prediction_error_bundle_policy.future_prediction_error_mean
  < legacy_salience_proxy.future_prediction_error_mean

prediction_error_bundle_policy.future_prediction_error_mean
  < random_or_recency_baseline.future_prediction_error_mean

bundle_required_decision_rate > 0
single_memory_counterfactual_pass_rate == 1.0
structured_linkage_coverage >= 0.80 in the deterministic fixture
```

Also include a counter-fixture where the prediction-error policy does not win.
The harness must report that honestly rather than forcing a positive result.

Include one fixture with calibrated but trivial predictions. Expected: Brier/ECE
may look acceptable, but discrimination or non-triviality metrics flag the
predictions as weak evidence for memory-policy value.

Include one small UX fixture where a settled violation changes later recall or
reply policy through recorded M17 factors. Expected: the report labels this as
fixture-level UX evidence only, not statistical proof.
