# OpenFEP M16.3 Work Prompt

## Milestone

M16.3: TypeScript Web Thin Frontend

## Goal

Replace Streamlit as the primary Hu Tao chat surface with a browser client that
is strictly I/O:

```text
Web UI -> consciousness-client SDK -> M16.1 gateway -> runner
```

The page renders conversation, streams actuation events, sends user input, and
shows compact operator diagnostics. It does **not** schedule idle ticks,
introspection, proactive attempts, or delivery retries outside SDK ack/resync.

## Architecture Position

```text
ui/web/
  Vite + TypeScript
  imports @segments/consciousness-client
  optional minimal CSS (no heavy component library required)

segmentum/dialogue/runtime/m16_api.py
  serves static build in dev proxy or separate `npm run dev` with Vite proxy
```

Recommended dev flow:

```text
terminal A: consciousness serve (M16.1)
terminal B: cd ui/web && npm run dev  (proxy /v1 and /ws to gateway)
```

Production-local flow may serve `ui/web/dist` from FastAPI static mount; keep
optional for this milestone.

## Dependencies

Hard:

- M16.1 gateway + runner
- M16.2 TypeScript SDK

Soft:

- existing mind debug bundle format (read-only panel)

## Non-Goals

- Do not port Streamlit admin/persona management wholesale in M16.3.
- Do not reimplement M13/M14 diagnostics logic in TS.
- Do not add keyword-based proactive hints in the browser.
- Do not require login/OAuth; localhost demo is sufficient.
- Do not remove Streamlit yet (M16.4 documents deprecation).

## Required Work


Use plain TypeScript DOM or a single lightweight view helper; avoid React unless
already standardized elsewhere in repo.

### 2. Chat Experience

Minimum UX:

- persona + session selector (session id in query string or localStorage),
- message list (user/assistant/proactive labeled),
- composer with send on Enter,
- connection badge (`connecting | live | resyncing | offline`),
- typing indicator optional,
- auto-scroll on new assistant/proactive messages.

Data rules:

- render just from SDK events + REST snapshot resync,
- assistant/proactive bubbles use server-provided text only,
- show suppression toasts using `RunnerSuppression` payload
  (`reason_code` display-only),
- never compute "idle duration" as a trigger for server cognition; client-side
  timers may only update visual connection state or debounce local input.

### 3. Runner Controls (Operator)

Sidebar controls:

```text
Start runner
Stop runner
Runner status (pid, last_health_at, budgets summary if present)
Copy mind debug bundle (link to REST snapshot endpoint or preformatted text)
```

These buttons call SDK HTTP helpers only.

### 4. Diagnostics Panel (Read-Only)

Compact panel fed by:

- WS `AuditEvent` stream (bounded ring buffer in memory),
- periodic REST `getSnapshot()` for hints such as boredom band, last skip
  reason, proactive count.

Do not scrape `conversation_log.jsonl` directly from browser filesystem.

Optional: "Copy Path B Mind Debug Bundle" button that calls a new gateway route
only if M16.1 exposes a bounded diagnostic snapshot; otherwise render snapshot
JSON.

### 5. Delivery Ack Discipline

When the UI renders an assistant or proactive message with server message id:

- send `DeliveryAck` through SDK,
- do not ack before text is actually shown.
- if reconnect replays an already rendered message id, do not render or ack it
  twice.

This supports M14.2 delivery idempotency tracing.

## Acceptance Criteria

M16.3 is complete when:

1. Web client chats through M16.1 with Streamlit closed.
2. User input only reaches Python through gateway HTTP/WS perception routes.
3. Proactive messages appear when runner + delivery surface conditions are met.
4. Suppression codes render without client-side semantic inference.
5. Refresh/reconnect resyncs transcript without duplicating messages.
6. Parity checklist documents remaining Streamlit-only gaps.
7. Web bundle contains no cognition scheduling logic.
8. Browser visibility, focus, and repaint cadence do not alter runner behavior.

## Roadmap Note

After M16.3, new Path B product features must land in the runner/gateway first;
Streamlit receives no new orchestration hooks.
