# OpenFEP M19.3 Work Prompt

## Milestone

M19.3: Slow Self-Cognition Consolidation, Downgrade, And Revocation

## Goal

Allow repeatedly validated self-repair patterns to slowly shape
`self_cognition`, while keeping the fast issue layer separate, reversible, and
less authoritative.

This milestone owns the slow bridge:

```text
repeated self-issue observations
+ repeated repair expectations
+ repeated natural settlements
-> calibrated self_cognition update
```

M19.3 is where the system may finally say, internally, not "I am flawed", but
something like:

```text
in context X, I reliably drift toward failure mode Y unless I prefer repair
strategy Z
```

## Required Work

### 1. Add slow promotion criteria

A self-cognition update may occur only when all of the following are true:

- the source issue has stable repeated support across multiple observations
- at least one repair expectation was created from it
- settlement history contains repeated natural confirmations or informative
  violations
- the resulting conclusion is context-bounded and operational, not globalized
- all supporting artifacts retain non-empty `evidence_refs`

Promotion must be slower and stricter than fast issue accumulation.

### 2. Restrict the form of slow conclusions

Slow self-cognition writes must target bounded fields equivalent to:

- `known_limits`
- `calibrated_tendencies`
- `repair_priors`

They must be phrased as context-conditioned constraints, not personality
absolutes.

Good shape:

```text
When group privacy boundaries trigger, visible phrasing tends to become
template-like unless semantic-only repair is preferred.
```

Bad shape:

```text
I am always robotic.
```

### 3. Add downgrade and revocation rules

Slow conclusions must be revisable.

Later contrary evidence may:

- lower confidence
- downgrade a prior
- mark a conclusion as stale
- revoke it if the pattern no longer holds

Do not let one promotion become permanent dogma.

### 4. Preserve fast/slow layering

`self_issue_memory_fast` remains the fast revocable layer.
`self_cognition` remains the slow conservative layer.

Fast issue cooling or contradiction should not instantly wipe slow cognition,
but it must be able to lower promotion confidence over time.

### 5. Keep auditability end-to-end

Every slow promotion, downgrade, or revocation must point back to the
supporting:

- issue keys
- expectation ids
- settlement ids
- evidence refs

No untraceable self-cognition patch is allowed.

### 6. Ensure slow writes stay owner-validated

M19.3 may recommend self-cognition updates, but all final writes must still go
through named-owner validation rather than bypassing the existing ownership
contract.

This milestone owns promotion logic, not an unsafe direct mutation path.

## Acceptance Criteria

M19.3 is complete only if:

- slow self-cognition updates require more evidence than fast issue memory
- promoted conclusions are context-bounded rather than global labels
- later contrary evidence can downgrade or revoke slow conclusions
- fast and slow layers remain distinct in state and behavior
- every slow self-cognition change is traceable back through expectation and
  settlement history
