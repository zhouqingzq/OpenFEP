# OpenFEP M19.3 Work Prompt

## Milestone

M19.3: Slow Self-Cognition Consolidation, Downgrade, And Revocation

## Goal

Allow repeatedly validated self-expectation repair patterns to slowly shape
`self_cognition`, while keeping the fast mismatch layer separate, reversible,
and less authoritative.

This milestone owns the slow bridge:

```text
repeated self_response_expectations
+ repeated self_expectation_mismatches
+ repeated self_repair_expectations
+ repeated natural settlements with prediction-error writeback
-> calibrated self_cognition update
```

M19.3 is where the system may finally say, internally, not "I am flawed", but
something like:

```text
in context X, my default reply tendency creates prediction error Y unless I
prefer lower-FE repair strategy Z
```

Slow conclusions describe **context-conditioned self-expectation calibration**,
not externally imposed correction.

## Architecture Position

M19.3 connects the M19 active-inference loop to the existing M14 self-cognition
owner path:

```text
self_expectation_state + settlement history + M13 traction history
-> slow promotion proposal
-> SelfCognitionPatchOwner / M14 idle reflector validation
-> self_cognition.known_limits / calibrated_tendencies / repair_priors
```

Promotion must remain slower and stricter than M19.1 traction updates.

## Non-Goals

- Do not promote from user correction alone.
- Do not promote from one `reply_validation` event.
- Do not write global personality absolutes.
- Do not bypass named-owner validation.
- Do not erase fast mismatch memory when promoting a slow conclusion.

## Required Work

### 1. Add slow promotion criteria

A self-cognition update may occur only when all of the following are true:

- the source mismatch has stable repeated support across multiple indirect
  observations
- at least one `self_response_expectation` and one `self_repair_expectation`
  were created from it
- settlement history contains repeated natural `confirmed` outcomes or
  informative `violated` outcomes with traceable `prediction_error_delta`
- repeated settlement writeback shows the preferred intervention actually
  changed traction or reduced prediction error when confirmed
- the resulting conclusion is context-bounded and operational, not globalized
- all supporting artifacts retain non-empty `evidence_refs`

Promotion must be slower and stricter than fast mismatch accumulation and
stricter than M19.1 traction proposals.

### 2. Restrict the form of slow conclusions

Slow self-cognition writes must target bounded fields equivalent to:

- `known_limits`
- `calibrated_tendencies`
- `repair_priors`

They must be phrased as context-conditioned self-expectation constraints, not
personality absolutes or externally assigned fault labels.

Good shape:

```text
When group privacy boundaries trigger, my default surface reply tends to create
prediction error unless semantic-only repair is preferred.
```

Bad shape:

```text
I am always robotic.
```

Bad shape:

```text
The user keeps correcting me, so I am bad at chatting.
```

### 3. Add downgrade and revocation rules

Slow conclusions must be revisable.

Later contrary evidence may:

- lower confidence
- downgrade a prior
- mark a conclusion as stale
- revoke it if the pattern no longer holds

Contrary evidence includes:

- repeated `violated` settlements after promotion
- renewed fast mismatch support for the same recurrence key
- restored prediction error in the same `target_context` despite the promoted
  repair prior

Do not let one promotion become permanent dogma.

### 4. Preserve fast/slow layering

`self_expectation_state.mismatch_memory_fast` remains the fast revocable layer.
`self_cognition` remains the slow conservative layer.

Fast mismatch cooling or contradiction should not instantly wipe slow cognition,
but it must be able to lower promotion confidence over time and trigger downgrade
review.

Confirmed fast-layer reinforcement must not automatically promote to slow
cognition without meeting the stricter promotion criteria.

### 5. Keep auditability end-to-end

Every slow promotion, downgrade, or revocation must point back to the
supporting:

- mismatch keys
- self-response expectation ids
- self-repair expectation ids
- settlement ids
- prediction-error deltas
- evidence refs

No untraceable self-cognition patch is allowed.

### 6. Integrate with idle reflection without external correction dependency

M19.3 promotion proposals may be surfaced to M14 idle reflector as
`reflection_focus` candidates, but the reflector must rank them using:

- repeated settlement quality
- prediction-error reduction
- traction stability

not user complaint frequency.

### 7. Ensure slow writes stay owner-validated

M19.3 may recommend self-cognition updates, but all final writes must still go
through named-owner validation rather than bypassing the existing ownership
contract.

This milestone owns promotion logic, not an unsafe direct mutation path.

## Acceptance Criteria

M19.3 is complete only if:

- slow self-cognition updates require more evidence than fast mismatch memory
- promotion does not depend on user correction as a primary evidence source
- promoted conclusions are context-bounded rather than global labels
- later contrary evidence can downgrade or revoke slow conclusions
- fast and slow layers remain distinct in state and behavior
- every slow self-cognition change is traceable back through self-expectation,
  repair-expectation, and settlement history including `prediction_error_delta`
- promoted `repair_priors` describe lower-FE strategies, not externally imposed
  compliance rules
