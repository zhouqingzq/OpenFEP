# OpenFEP M18.5 Work Prompt

## Milestone

M18.5: Multi-Party Reply Policy, Turn-Taking, And Social Continuity

## Goal

Teach Path B to behave like it understands a live group thread rather than a
sequence of isolated private chats.

This milestone owns reply-addressing policy and unresolved-thread continuity.
It does not own participant identity, transcript schema, or memory privacy
classification, but it must consume those upstream structures explicitly.

## Required Work

### 1. Add a reply-addressing policy owner

Before generating a reply, Path B must decide:

```text
reply_to_current_speaker
reply_to_named_third_party
reply_to_whole_group
clarify_addressee
defer_side_thread
```

The policy must define a deterministic precedence order. At minimum:

1. privacy / safety / non-shareability constraints from M18.4
2. explicit reply-to or quote linkage when available
3. explicit named addressee evidence
4. unresolved assistant obligation that is still active and visible
5. current-speaker default only when the above do not decide
6. clarify when top candidates remain too close
7. defer side-thread when the runtime intentionally keeps the main thread active

If the policy chooses to continue without clarification, diagnostics must show
why ambiguity was considered acceptable.

### 2. Track unresolved group threads

At minimum:

- pending answer to Bob
- Alice corrected Bob
- Carol's question still open
- Hu Tao explicitly deferred one sub-thread

### 3. Preserve continuity across turns and restart

This social state must survive settlement and reload.

### 4. Keep reply generation bounded

Do not build a free-form social simulator. Keep the policy structured and
auditable.

At minimum, the policy should declare:

- what ambiguity band forces `clarify_addressee`
- when `reply_to_whole_group` is preferred over current-speaker reply
- when a deferred side thread remains pending vs expires
- how many unresolved group-thread slots can stay active

## Acceptance

This milestone is complete only if:

- the runtime can choose between current-speaker reply, whole-group reply, and
  clarify-addressee
- explicit policy precedence determines the same choice on replay for the same
  structured inputs
- unresolved multi-party threads can persist across turns
- at least one regression shows Alice/Bob conflict continuity preserved into the
  next turn
- restart preserves pending group-thread state
