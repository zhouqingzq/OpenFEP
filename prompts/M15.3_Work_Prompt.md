# OpenFEP M15.3 Work Prompt

## Milestone

M15.3: Open-Item And Pending-Expectation Cleanup Meta-Control

## Goal

M15.2 currently detects repeated failure paths, self-consistency tension,
and idle stalls. Real Path B sessions now show another repeated failure
mode:

```text
open_items / pending_expectations accumulate across turns
-> many rows have duplicate local ids, no evidence_refs, no bound_memory_ids
-> M13.5 recall keeps retrieving them
-> M13.6 / M14.3 can diagnose them but cannot clean them
-> idle tick repeatedly ends with no_high_value_target
-> DeltaF for idle_wait drifts upward
```

M15.3 adds a bounded meta-control cleanup layer for this specific  
failure mode. It detects stale, duplicate, low-traceability open items and  
pending expectations, emits structured cleanup intents, and routes all  
state mutation through an explicit cleanup owner. It must make forgetting  
observable as **expire / merge / mark diagnostic-only / deprioritize**, never as silent
deletion.

Target behavior:

```text
PATTERN: many open_items have missing evidence_refs / bound_memory_ids,
         duplicate local ids, or repeated vague next_user_turn rows
-> emit OpenItemBacklogDetectedEvent
-> issue CleanupInterventionIntent(kind="cleanup_open_items")
-> CleanupOwner marks stale rows diagnostic_only or merged_into, and keeps
   canonical rows with evidence unions

PATTERN: pending_expectations stay unresolved after their verification
         window, or repeat the same local id/content stance without
         traceable evidence
-> emit PendingExpectationBacklogDetectedEvent
-> issue CleanupInterventionIntent(kind="cleanup_pending_expectations")
-> CleanupOwner expires / merges / downgrades rows through structural rules

PATTERN: M13.5 keeps retrieving low-traceability open/pending rows and then
         returns no_high_value_target
-> emit LowTraceabilityRecallBurdenDetectedEvent
-> issue CleanupInterventionIntent(kind="deprioritize_low_traceability_recall")
-> recall scoring treats diagnostic_only / expired / merged_into rows as
   ineligible for proactive target selection, while preserving them for audit
```

The intended product effect is not "the persona forgets arbitrarily." The effect
is: outdated unresolved scaffolding stops crowding recall, while concrete
evidence-backed paths remain available for proactive topic formation.

## Architecture Position

```text
M15.2 meta-control detectors
  -> detect cleanup pressure over open_items / pending_expectations
  -> emit CleanupInterventionIntent rows

M15.3 CleanupOwner
  -> consumes cleanup intents on idle/background only
  -> mutates open_items / pending_expectations with explicit status changes
  -> never deletes rows

M14.7 recall scoring
  -> reads cleanup status fields
  -> deprioritizes diagnostic_only / expired / merged_into rows

M13.5 / M13.6 / M14.3
  -> continue to use traceability gates
  -> become less polluted by stale low-evidence scaffolding

M15.3 companion alignment (same milestone, not optional)
  -> strict traceability helpers shared with M13.6 (no id self-reference)
  -> idle bound-memory recall seeding for strictly traceable expectations
  -> active-session-only queued outreach for debug/delivery defaults
```

Suggested module layout:

```text
segmentum/dialogue/runtime/m15_3_cleanup_control.py     (new)
segmentum/dialogue/runtime/m15_meta_control.py          (extend orchestration)
segmentum/dialogue/runtime/m15_consolidation.py         (optional shared helpers)
segmentum/dialogue/runtime/m14_7_recall_scoring.py      (read cleanup status)
segmentum/dialogue/runtime/m13_memory_efe.py            (filter expired/merged)
segmentum/dialogue/runtime/m14_3_proactive_alignment.py (filter diagnostic-only)
segmentum/dialogue/runtime/mvp_loop.py                  (idle/background hook)
segmentum/dialogue/runtime/app.py / chat.py             (diagnostics)
```

M15.3 must not introduce a new scheduler. It runs only from:

- M13.5 idle cognitive tick, after the normal tick event is computed.
- M14.1 background tick, after M15.1 consolidation.

It must never run during a user turn or while `m13_ui_turn_in_progress` is
true.

## Non-Goals

- Do not delete rows from `open_items` or `pending_expectations`.
- Do not infer semantic sameness by keyword, regex, substring, or LLM.
- Do not introduce Path A, M10, `MetaObserver`, `SelfThoughtProducer`, or a
new autonomous scheduler.
- Do not generate user-visible prose.
- Do not write to M11, M12.0, M12.1, M12.2, or self_cognition.
- Do not hide cleanup actions. Every state mutation needs an audit event.
- Do not clean rows that have active `scheduled_intent_id`, high
identity relevance, pinned status, or recent concrete evidence.
- Do not rewrite `short_term_memory` / `long_term_memory` rows in this
milestone. STM/LTM garbage remains M15.1 consolidation scope.
- Do not fix M14.1 background daemon scheduling itself. Cleanup may run on
idle ticks even when `background_ticks_today=0`.

### 2. Structural row normalization

```text

normalize_pending_expectation_row(row) -> CleanupCandidate
```

Each candidate exposes:


Rules:

- `local_id_collision_key` is the raw `id` only; duplicate local ids are

  - next_check / verify_on family
  - evidence_refs set
  - bound_memory_ids set
  - source

- It must not use free-text content similarity.

#### 2.1 Strict traceability contract (required companion fix)

Add shared helpers in cleanup module (and reuse from M13.6 / M14.3):

```text
STRICT_EVIDENCE_PREFIXES = ("stm_", "mem_", "ltm_", "exp_", "turn_", "evt_")

def strict_evidence_refs(row) -> list[str]:
    # Only explicit evidence_refs / evidence_ref / source_event_id fields.
    # MUST NOT fall back to row id, open_item id, or expectation id.

def strict_bound_memory_ids(row) -> list[str]:
    # Only explicit bound_memory_ids / memory_id / source_memory_id fields.

def is_strictly_traceable(row) -> bool:
    refs = strict_evidence_refs(row)
    bound = strict_bound_memory_ids(row)
    if not refs and not bound:
        return False
    # Reject self-reference: evidence/bound id equals row local id
    local_id = str(row.get("id") or row.get("open_item_id") or "").strip()
    if local_id and (local_id in refs or local_id in bound):
        return False
    # Require at least one external anchor id
    external = [x for x in (*refs, *bound) if x != local_id]
    return bool(external)
```

Cleanup detectors, mind-panel traceability summaries, and backlog ratio math
**must** use `is_strictly_traceable()`.

`STRICT_EVIDENCE_PREFIXES` is a conservative default, not the only possible
source of truth. Implementers may accept additional structural anchors only
when they come from explicit anchor fields or a future anchor registry. They
must not infer anchors from free-text content.

`exp_` ids require special care: an expectation id can be a durable external
anchor for another row, but `evidence_refs=["<this row's exp id>"]` is still
self-reference and must be rejected.

`scheduled_intent_id` protects a row from cleanup, but it is not ordinary
evidence. It should not by itself make a row eligible for proactive target
selection unless the scheduled-intent row has its own external evidence.

Align M13.6 memory-EFE eligibility with the same strict rule:

```text
segmentum/dialogue/runtime/m13_memory_efe.py
  - replace cleanup-sensitive traceability checks to use strict_evidence_refs /
    is_strictly_traceable
  - stop treating row "id" as implicit evidence for open_items and
    pending_expectations
  - retain id fallback ONLY for scheduled_intent rows where intent id is the
    durable anchor (document in code comment)
```

Add closed ineligibility / diagnostic reason:

```text
self_referential_evidence_only
```

Expected effect on field session: 17 open_items with empty explicit evidence
become low-traceability; duplicate `item_001` backlog detector fires; M13.6
stops treating them as traceable proactive targets.

### 3. OpenItemBacklogDetector

Thresholds:

```text
OPEN_ITEM_BACKLOG_MIN_ROWS = 8
LOW_TRACEABILITY_RATIO     = 0.50
DUPLICATE_LOCAL_ID_MIN     = 2
STALE_OPEN_ITEM_SECONDS    = 14 days
MAX_CLEANUP_CANDIDATES     = 8
```

Pattern fires when any of:

- open item count >= `OPEN_ITEM_BACKLOG_MIN_ROWS` and low-traceability
ratio >= `LOW_TRACEABILITY_RATIO`
- the same local id appears >= `DUPLICATE_LOCAL_ID_MIN` times and at least
one row is low-traceability
- old low-traceability rows exceed `STALE_OPEN_ITEM_SECONDS`

Emit:

```text
OpenItemBacklogDetectedEvent
  open_item_count
  low_traceability_count
  duplicate_local_id_count
  stale_count
  candidate_ids
  emitted_intent_id
```

Do not clean rows with:

- `scheduled_intent_id`
- `pin=true`
- `status` in `active`, `in_progress`
- recent `created_at` within grace window
- `is_strictly_traceable(row)` is true (external `stm_*` / `mem_*` / etc.)

### 4. PendingExpectationBacklogDetector

Thresholds:

```text
PENDING_EXPECTATION_BACKLOG_MIN_ROWS = 8
EXPIRED_NEXT_USER_TURN_GRACE_TURNS   = 2
EXPIRED_IDLE_EXPECTATION_SECONDS     = 24 hours
LOW_CONFIDENCE_FLOOR                 = 0.35
MAX_CLEANUP_CANDIDATES               = 8
```

Pattern fires when any of:

- pending expectation count >= min rows and low-traceability ratio >= 0.5
- `verify_on="next_user_turn"` rows survive more than
`EXPIRED_NEXT_USER_TURN_GRACE_TURNS` user turns after `created_turn_index`
- `verify_on="memory_dynamics_idle"` rows remain unresolved after
`EXPIRED_IDLE_EXPECTATION_SECONDS` and have low expected value
- duplicate local ids appear without shared evidence refs

Emit:

```text
PendingExpectationBacklogDetectedEvent
  pending_count
  expired_count
  low_traceability_count
  duplicate_local_id_count
  candidate_ids
  emitted_intent_id
```

Rows with high confidence and **strictly** traceable evidence are not expired;
they may be retained for M13.6.

Expire rule clarification for duplicate local ids:

- When the same `id` (for example `exp_001`) appears many times, expire or
merge rows that fail `is_strictly_traceable()` or are past their verify
window.
- Keep the newest strictly traceable row for that local id when it has
external evidence (for example `evidence_refs=["stm_turn_1779704612"]`).

### 5. LowTraceabilityRecallBurdenDetector

Inputs:

- latest `IdleCognitiveTickEvent`
- recent M15.0 ledger rows for `idle_wait`
- retrieved ids from the tick
- open/pending candidate status

Threshold:

```text
RECALL_BURDEN_WINDOW = 5
NO_TARGET_RATIO      = 0.8
LOW_TRACE_RETRIEVAL_RATIO = 0.5
```

Pattern fires if recent idle ticks repeatedly return
`reject_reason="no_high_value_target"` and at least half of retrieved ids

Emit:

```text

  window
  no_target_ratio
  low_traceability_retrieval_ratio
  retrieved_candidate_ids
  emitted_intent_id
```

Intent kind: `deprioritize_low_traceability_recall`.

### 6. CleanupOwner

Single mutation entry:

```text
class CleanupOwner:
    def apply_intents(state, *, now, turn_index, intents, budget)
        -> CleanupRunResult
```

Fixed op order:

```text
1. merge_structural_duplicates
2. expire_stale_pending_expectations
3. mark_stale_open_items_diagnostic_only
4. mark_low_traceability_recall_deprioritized
```

Per-run caps:

```text
MAX_CLEANUP_ROWS_PER_RUN = 8
MAX_MERGES_PER_RUN       = 4
MAX_EXPIRES_PER_RUN      = 6
MAX_DIAGNOSTIC_MARKS     = 6
```

Mutation semantics:

- Merge:
  - canonical row is the oldest `created_at`
  - noncanonical row gets `status="merged_into:<canonical_id>"`
  - canonical row gets unioned `evidence_refs`, `bound_memory_ids`,
  `merged_from`
  - no deletion
- Expire pending expectation:
  - `status="expired"`
  - `expired_at`
  - `expired_reason_code`
  - keep row in file
- Diagnostic-only open item:
  - `status="diagnostic_only"`
  - `diagnostic_only_reason_code`
  - exclude from proactive target selection
  - still visible in diagnostics
- Recall deprioritize:
  - `recall_deprioritized_until`
  - `recall_deprioritized_reason_code`
  - M14.7 recall scoring returns 0 for proactive recall while the mark is
  active, but general diagnostic views can still show the row.

### 7. Recall and eligibility integration

M14.7 recall scoring:

```text
score_recall_candidate(row, ...)
  if status in {"expired", "diagnostic_only"} and recall_context.phase in
     {"idle", "proactive", "memory_efe"}:
       return 0.0
  if status startswith "merged_into:":
       return 0.0
  if recall_deprioritized_until > now and phase is idle/proactive:
       return 0.0
```

`diagnostic_only` means "kept for diagnostics and migration review, excluded
from proactive target selection and idle/proactive recall." It does not mean
the row disappears from debug surfaces, and it does not imply that the row is
resolved.

- pending expectations with `status in {"expired", "merged_into:*"}` are
diagnostic-only and ineligible.
- add closed ineligibility reasons:
  - `expectation_expired`
  - `expectation_merged`
  - `low_traceability_cleanup_deprioritized`

become proactive targets.
- emit closed reject reason if all candidates are filtered:
  - `cleanup_filtered_low_traceability_candidates`

## Acceptance Criteria

M15.3 is complete when:

1. Open item and pending expectation backlog detectors run only on idle or
  background ticks, never during user turns.
2. Detectors emit structured events and cleanup intents, capped to one
  active cleanup intent per kind.
3. All mutations go through `CleanupOwner.apply_intents`; detectors never
  mutate state directly.
4. Cleanup never deletes rows. It only merges, expires, marks
  diagnostic-only, or deprioritizes recall with explicit status fields.
5. Duplicate detection is structural only. No keyword/regex/substring
  similarity over free text content.
6. Rows with scheduled outreach, pins, **strict** traceability, or recent
  external evidence are protected. Scheduled intent presence alone is a
  protection signal, not ordinary evidence for proactive selection.
7. M14.7 recall, M13.6 memory-EFE, and M14.3 proactive selection all
  respect cleanup status fields and strict traceability (no open_item id
  self-reference).
8. All cleanup actions are auditable with closed reason codes and no raw
  content.
9. `bounded_default` emits detection audits only unless
  `SEGMENTUM_META_CONTROL_APPLY=1`, or a cleanup-specific safe toggle such as
  `SEGMENTUM_CLEANUP_CONTROL_APPLY=1` is enabled. The cleanup-specific toggle
  must not enable unrelated M15.2 suppress/focus/recall-breadth intents.
  `streamlit_open_chat` may apply within caps for local demo.
10. No Path A / M10 wiring is added. No `MetaObserver` or
  `SelfThoughtProducer`.
11. **Strict traceability** helpers are shared; cleanup detectors and M13.6
  eligibility agree on `is_strictly_traceable()`. Open items with only
  implicit id evidence count as low-traceability and are cleanup-eligible.
12. **Bound recall seeding** prevents strictly traceable expectations from
  failing idle eligibility solely because generic recall omitted bound
  `stm_turn_`* ids (within per-tick cap).
13. **Queued outreach** debug and delivery default to the active session;
  foreign-session rows are excluded or explicitly labeled, never silently
  mixed into the active session bundle.
14. New tests pass, and existing M13.5 / M14.3 / M14.7 / M15.0 / M15.1 /
  M15.2 tests remain green.

## Out of Scope (explicit)

M15.3 does **not** claim to fix these remaining field-session issues:

- Persona-level `short_term_memory` merge noise across historical sessions
(M15.1 consolidation scope).
- M14.1 daemon alive but `background_ticks_today=0` (scheduler / runner
scope).
- M13.6 choosing `reflect` over `outreach` immediately after a user turn
when `f_memory` is low (expected policy behavior).
- M14.4 implicit idle suppression when `idle_seconds < idle_threshold_seconds`.

Cleanup reduces scaffolding pollution so those remaining gates operate on
cleaner candidate sets, not on 13x generic `item_001` rows.
