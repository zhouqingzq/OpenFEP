## Milestone

M18.7: Group Turn Semantic Attribution Contract — conscious-loop
fields for addressee hypothesis and reaction attribution hypothesis

## Goal

Close the semantic-attribution gap that M18.2 / M18.5 structural
signals cannot fill, by adding two structured bounded fields to
the conscious-loop JSON output. The fields are the **only
legitimate bridge** between LLM semantic judgment and the M20
commitment framework. M18.7 does not implement any new settler,
write path, or commitment admission — that is M20.4's job.
M18.7 owns the schema, the prompt template, the normalization
contract, and the bus-level audit surface.

```text
external group turn
   |
   v
conscious loop (LLM)  -- now also produces -->
   addressee_hypothesis + reaction_attribution_hypothesis
   |
   v
mvp_loop.run_turn
   |
   +-- normalize_conscious_turn_plan_v18_7  (clamp + validate)
   |
   +-- emit AddresseeHypothesisAdmitted
   +-- emit ReactionAttributionHypothesisAdmitted
   |
   v
state["m18_7_attribution_hypotheses"]  (audit surface)
   |
   v
M20.4 (next milestone) reads these and admits:
   - ActiveCommitment(observable="addressee_target_match",
       source_kind="state", owner_id="group_addressee_graph")
   - ActiveCommitment(observable="reaction_attribution_match",
       source_kind="state", owner_id="...")
```

## Why M18.7 Exists

M18.2 / M18.5 handle the structural half of group-chat addressee
resolution. They consume:

- `reply_to_turn_id` (explicit reply-to linkage)
- `addressed_participant_ids` (mentions / name call-outs)
- `quoted_turn_ids` (quoted-message refs)
- `mentioned_participant_ids` (third-party references)
- `surface_intent` (chat / bot_command / roleplay / abstaining)
- recent-ownership structure from the LLM self-audit

These structural signals answer ~70% of group-chat addressee
cases correctly. The remaining ~30% need **semantic judgment
over the actual turn text in context** — exactly the kind of
interpretation that CLAUDE.md assigns to the LLM, not to
engineering.

Concrete cases M18.5 cannot resolve from structure alone
(described as semantic categories, not as a keyword list):

- **Implicit continuation**: a turn that paraphrases or
  follows up on the assistant's prior turn, with no
  mention, no reply-to, and no quote. The LLM is the only
  judge of whether the inbound turn is a continuation of
  the assistant's prior claim.
- **General acknowledgement**: a brief interjection without
  an explicit recipient. The LLM is the only judge of
  whether the acknowledgement is directed at the
  assistant, at another participant, or at nobody.
  participant, or at nobody in particular.
- **Reaction to a chain**: `那个问题可以再说明一下吗` — the
  question may refer to one of N prior turns; only the LLM can
  attribute it.
- **Cross-user callback**: `Alice 你说过的那个店` — Alice may
  have said something 5 turns ago that the LLM can locate in
  the conversation history; the structural addressee graph only
  sees the current turn.

M18.7 owns the structured fields that capture this judgment.
Without M18.7, the M20.4 bridge has no structured input to
admit; with M18.7, M20.4 can route the hypothesis into a
deterministic `addressee_target_match` / `reaction_attribution_match`
settler, and the existing M20.2 dispatcher can route corrections
through the `group_addressee_graph` write path (currently
no-op, per M20.3 follow-up review).

## Hard Rules (CLAUDE.md compliance)

The following rules are non-negotiable. Violations in M18.7
acceptance are blocker bugs, not style nits.

1. **The LLM is the only source of the new fields.** No
   engineering code may infer `addressee_to_assistant` or
   `reaction_to_turn_id` from user text, structural signals, or
   heuristic rules. The LLM weighs structural signals (already
   passed via `group_turn_binding`) and returns the structured
   field. Engineering only validates the shape of the LLM's
   answer.

2. **No regex / keyword matching.** The conscious-loop prompt
   must not contain instructions in the form "if the user text
   contains X, then Y" where X is a fixed string or a regular
   expression. The forbidden shape is a *matching rule*. The
   prompt MAY include **semantic-category descriptions**
   ("short acknowledgement without explicit recipient",
   "side-thread interjection", "room-level comment") and MAY
   use illustrative *negative examples* in a parenthetical
   inside a category description, as long as the category
   itself is described semantically, not by a string match.
   The prompt instructs the LLM to use its own semantic
   judgment over the conversation context, not pattern
   matching against user text. Engineering-layer tests
   (`test_prompt_template_forbids_keyword_or_regex_matching`)
   scan the prompt for the *rule shape* `if text contains /
   matches / regex / cue list`, not for the presence of any
   specific Chinese character or word.

3. **No raw user text in `evidence_refs`.** `evidence_refs`
   entries are bounded turn-local handles like
   `turn_<n>_user_utterance`, `turn_<n>_reply_to_turn_id`,
   `bus_event_<uuid>`, `participant_<id>`. They never contain
   quoted text, even short quoted text.

4. **Bounded enums and confidence intervals.** Every numeric
   field has a frozen interval (e.g., `confidence: 0.0–1.0`).
   Engineering clamps; the LLM is the source of the unclamped
   value.

5. **Empty fields are valid.** When the conscious loop cannot
   produce a high-confidence hypothesis, the field is empty
   (or null, depending on the field) and engineering treats it
   as "no hypothesis". The M18.5 reply policy falls back to its
   structural-only path. Empty MUST NOT crash the run_turn.

6. **No new LLM stages.** M18.7 does not add a new LLM call.
   The two fields are produced by the existing conscious loop
   call, with the system prompt extended to describe them. The
   fast_chat / full-conscious distinction is unchanged.

7. **Privacy parity with M18.4.** The `addressee_hypothesis`
   reveals which participant the LLM believes is the addressee.
   If M18.4 has a `source-audience-disclosure` policy that
   forbids a specific user from being identified to the
   assistant, M18.7 must respect it: the LLM is instructed to
   return `participant_id = ""` and `addressed_to_assistant =
   false` when the disclosure is forbidden, and engineering
   does not log the original `group_turn_binding` reference for
   that case.

## Non-Goals

- **M18.7 does not admit ActiveCommitment rows.** That is M20.4.
  M18.7 emits the structured fields and the bus events; M20.4
  reads them and admits commitments.
- **M18.7 does not modify M18.5 reply policy.** M18.5 keeps its
  structural-only path. M20.4 may, in a future milestone, add
  a feedback path that lets the M18.7 hypothesis inform the
  M18.5 policy at high confidence (>0.85) — but that is M20.4
  territory.
- **M18.7 does not implement a settler or a write path.** No
  M20.1 settler is added; no M20.2 dispatcher path is wired.
  M18.7 only produces the input that M20.4 will consume.
- **M18.7 does not retroactively label prior turns.** Only the
  current conscious loop's output carries the new fields. Prior
  turns in the bus / state are not re-labeled.
- **M18.7 does not claim subjective group understanding.** The
  field names use the neutral term "hypothesis" with an explicit
  confidence; the LLM is never asked to "know" or "feel" the
  group's intent.
- **M18.7.1 calibration is a separate sub-milestone.** M18.7
  ships the schema + prompt + normalize + audit. M18.7.1 (in a
  future prompt) runs the held-out calibration on M18.6
  fixtures. M18.7 acceptance does NOT depend on M18.7.1.
- **M18.7 does not touch Path A, M10, or `conversation_loop.py`.**

Add two optional fields to the existing
`normalize_conscious_turn_plan` output. Both are `{}` (empty

when it can produce a high-enough-confidence hypothesis.

addressee_hypothesis: {
  "participant_id": str,           # who said the current turn
                                   # (must match the speaker
                                   # in group_turn_binding.
                                   # Empty if you cannot
                                   # determine or the M18.4
                                   # disclosure policy forbids
                                   # the identification.)
  "addressed_to_assistant": bool,  # is the message addressed
                                   # to the assistant? false
                                   # means addressed to another
                                   # participant or to nobody.
  "confidence": float,             # 0.0–1.0, your self-rated
                                   # confidence in the boolean
                                   # above. Engineering clamps
                                   # outside the interval.
  "rationale": str,                # ≤ 200 chars. Why you
                                   # believe this. NO quoted
                                   # user text. NO quoted
                                   # assistant text.
  "evidence_refs": list[str],      # bounded turn-local refs
                                   # only. No raw text. No
                                   # substring excerpts.
  "alternative_hypotheses": list[{ # optional, ≤ 2 entries

```

reaction_attribution_hypothesis: {

                                   # reaction referring to?
                                   # Empty if you cannot
                                   # determine or no prior
                                   # turn is a plausible
                                   # referent.
  "reaction_to_participant_id": str,  # whose prior turn is
                                       # the referent? Empty
                                       # if you cannot tell.
  "is_about_assistant_claim": bool,    # is the reaction
                                       # targeting the
                                       # assistant's own claim
                                       # in the referent turn?
                                       # (Only meaningful when
                                       # reaction_to_participant_id
                                       # = the assistant's
                                       # participant_id.)
  "confidence": float,             # 0.0–1.0
  "rationale": str,                # ≤ 200 chars
  "evidence_refs": list[str],
  "alternative_attributions": list[{  # optional, ≤ 2 entries
    "reaction_to_turn_id": str,
    "reaction_to_participant_id": str,
    "is_about_assistant_claim": bool,
    "confidence": float,
    "rationale": str,
    "evidence_refs": list[str]
  }]
}
```

Frozen enums / shapes:

- `participant_id` is the v1 frozen form from M18.1 (a
  bounded participant identifier; not a free-form string).
  Engineering validates the shape; the LLM fills the value.
- `confidence` is `float` in `[0.0, 1.0]`. Engineering clamps.
- `rationale` is `str` with `len(rationale) <= 200` after
  `.strip()`. Engineering truncates; the LLM is the source of
  the unclamped value.
- `evidence_refs` is a list of bounded handles (no raw text,
  no substring excerpts). Engineering validates each entry
  matches a known turn-local ref pattern.
- `alternative_hypotheses` / `alternative_attributions` are
  lists of at most 2 entries. Engineering truncates longer
  lists; the LLM is the source of the unclamped count.

When the conscious loop returns no value for either field
(LLM declined, or the LLM call did not produce the field),
engineering defaults to `{}` (empty mapping). Empty fields
never block the run_turn and never crash the normalize step.

`DEFERRED:` multi-attribution (one reaction referring to N
prior turns) is a v2 stretch. M18.7 v1 is single-attribution
with up to 2 alternatives.

### 2. Conscious-loop prompt template (Tier A)

The existing `build_conscious_loop_prompt` is extended with a
new section. The new section sits AFTER the existing
`surface_commitment` block (which is the M18.7 closest
precedent in the prompt) and BEFORE the existing M19 fields
block. The new section:

```text
For group-chat turns (when group_turn_binding is non-empty),
also include the following two fields in the same JSON object:

- "addressee_hypothesis": bounded object describing whether
  the current turn is addressed to the assistant.
  - "participant_id" must equal the speaker's id from
    group_turn_binding.current_speaker_participant_id. Use ""
    if M18.4 disclosure policy forbids the identification or
    you cannot determine it.
  - "addressed_to_assistant" is a boolean. Use false when
    the message falls into one of these **semantic categories**:
    (a) **short acknowledgement without explicit recipient**
    — a brief interjection that is not directed at any
    specific participant; (b) **side-thread interjection** — a
    comment directed at another participant, identifiable
    from context or `addressed_participant_ids` / mention
    structure; (c) **room-level comment** — a statement about
    the group's state, not targeting the assistant. The
    prompt must describe these as categories, not as a
    keyword cue list. Specific words in your training data
    are fine to use as illustrative descriptions inside a
    *negative example* parenthetical (e.g., "an utterance that
    is a short, content-free interjection" — note: this is
    a category, not a keyword). The forbidden pattern is
    "if user text contains X then...", where X is a fixed
    string or regex.
  - "confidence" is your self-rated 0.0–1.0 probability that
    the boolean is correct. 0.5 means "I genuinely cannot tell".
    Below 0.4, you SHOULD leave the field empty ({}) so
    engineering treats it as "no hypothesis".
  - "rationale" is a one-sentence justification, ≤ 200 chars.
    DO NOT paste the user text, the assistant's prior text,
    or any substring of either into the rationale. Reference
    structural signals by name (e.g., "explicit reply-to to
    the assistant's turn_3", "no structural addressee signal,
    implicit continuation of the assistant's prior turn") or
    by turn id.
  - "evidence_refs" is a list of bounded turn-local handles:
    "turn_<n>_user_utterance", "turn_<n>_reply_to_turn_id",
    "turn_<n>_addressed_participant_ids", "bus_event_<uuid>",
    "participant_<id>". DO NOT include raw text.
  - "alternative_hypotheses" is optional, ≤ 2 entries. Each
    entry has the same shape as the primary fields, with a
    different (addressed_to_assistant, confidence, rationale)
    tuple. Engineering uses the alternative's confidence to
    surface the LLM's uncertainty to the M20.4 settler.

- "reaction_attribution_hypothesis": bounded object describing
  which prior turn a reaction refers to.
  - "participant_id" must equal the reaction-speaker's id.
    Use "" if you cannot determine it.
  - "reaction_to_turn_id" is the prior turn id the reaction
    most likely refers to. Use "" if no prior turn is a
    plausible referent (e.g., the reaction is to a state of
    affairs, not a message).
  - "reaction_to_participant_id" is whose prior turn is the
    referent. Use "" if you cannot tell.
  - "is_about_assistant_claim" is true only when
    `reaction_to_participant_id` equals the assistant's id
    AND the reaction is targeting the assistant's own
    claim. False otherwise. The "targeting the
    assistant's own claim" semantic category covers
    reactions like (a) confirming the assistant's prior
    statement, (b) denying the assistant's prior
    statement, (c) asking the assistant to re-state or
    justify a prior claim. The prompt describes the
    category, not a specific user-text cue.
  - "confidence" is your self-rated 0.0–1.0 probability.
    Below 0.4, you SHOULD leave the field empty.
  - "rationale" is a one-sentence justification, ≤ 200 chars,
    no quoted text.
  - "evidence_refs" is bounded handles, no raw text.
  - "alternative_attributions" is optional, ≤ 2 entries.

Use your own semantic judgment of the conversation. Do not
match keywords, regex, or text-pattern cues. The structural
signals from group_turn_binding are inputs to your reasoning,
not a lookup table.

When the conscious plan is for a non-group turn (group_turn_binding
is empty or absent), you MAY omit both fields entirely. The
empty default ({}) is acceptable.
```

### 3. Normalize contract (Tier A)

`normalize_conscious_turn_plan_v18_7` (a thin wrapper around
the existing normalize) does the following:

- **Clamp `confidence` to `[0.0, 1.0]`.** Out-of-range values
  are clamped, NOT rejected. The LLM is the source of the
  unclamped value; engineering only enforces the interval.
- **Truncate `rationale` to 200 chars** after `.strip()`.
- **Validate `participant_id` shape.** It must be either `""`
  or match a v1 participant-id pattern (M18.1 frozen).
  Free-form strings are rejected with a
  `MalformedAddresseeHypothesis` audit event; the field is
  defaulted to `{}` for the rejection.
- **Validate `evidence_refs` shape.** Each entry must be a
  bounded handle matching the prompt-defined patterns
  (`turn_<n>_*`, `bus_event_<uuid>`, `participant_<id>`).
  Free-form text entries are rejected; the field is
  defaulted to `{}` for the rejection.
- **Truncate `alternative_hypotheses` / `alternative_attributions`
  to 2 entries.** Longer lists lose the tail; engineering does
  not reorder.
- **Default to `{}` for missing / empty / malformed fields.**
  Empty fields are valid and never block the run_turn.
- **Reuse existing `correcting_assistant_identity` v2 attribute
  pattern (M20.3 §3.1):** the new fields are v2 additions to
  the conscious plan. The existing v1 normalize output shape
  is preserved; the v2 fields are added alongside.

the engineering surface makes the skip observable.

Audit envelope rules (mirroring M20.3 §1.4 / §3.4):

- The envelope shares `turn_index` with the conscious plan's
  `turn_index` (deterministic).
- The envelope does NOT include the rationale text. Rationale
  is recorded as `rationale_chars` (length only) to avoid
  persisting the LLM's free-form justification in the audit
  tail. The LLM is the source of the rationale; engineering
  audits only the shape.
- The envelope's `participant_id` and `reaction_to_turn_id`
  are validated to match the v1 M18.1 / M18.3 frozen shapes.
- The envelope is NOT emitted when the field is `{}` (no
  hypothesis). A missing field is silent; engineering does
  not emit a `FieldOmitted` event.
- The envelope is emitted exactly once per `turn_index`
  (matching the M20.3 horizon dedup pattern).

### 5. State surface (Tier B)

A new bounded audit surface on `state`:

```text
state["m18_7_attribution_hypotheses"]: list[dict]
  # Bounded tail, ≤ 8 entries (rolling window of the most
  # recent 8 hypotheses). Each entry is the validated, clamped
  # shape from §1, NOT the bus envelope.
```

**Frozen state-entry schema** (the M20.4 hand-off contract — M18.7
acceptance is locked on this shape):

```text
{
  "kind": "addressee" | "reaction",   # which hypothesis this is
  "turn_index": int,                  # the turn that produced the field
  "commit_id": str,                   # stable id (sha1 of
                                      # (turn_index, kind, source_ref))
                                      # M20.4 uses this as source_ref
  "addressee": {                      # present iff kind == "addressee"
    "participant_id": str,
    "addressed_to_assistant": bool,
    "confidence": float,              # clamped to [0.0, 1.0]
    "alternative_hypothesis_count": int,
  },
  "reaction": {                      # present iff kind == "reaction"
    "participant_id": str,
    "reaction_to_turn_id": str,
    "reaction_to_participant_id": str,
    "is_about_assistant_claim": bool,
    "confidence": float,              # clamped to [0.0, 1.0]
    "alternative_attribution_count": int,
  },
  "evidence_refs": list[str],         # bounded handles, shape-validated
  "at": "<iso8601>",
  "engineering_proxy_label": "mvp_local_group_attribution",
}
```

Each turn produces at most 2 entries (one `addressee` and
one `reaction`). The shape above is the M20.4 hand-off
contract: M18.7 acceptance is locked on this exact shape;
M20.4 producer reads `kind` and `commit_id` from this entry
to admit the `ActiveCommitment`.

Engineering does not write to this surface directly; the
normalize step writes one entry per turn that produces a
non-empty hypothesis. Empty fields → no entry (silent).

The `commit_id` is the deterministic sha1 of
`(turn_index, kind, source_ref)` where `source_ref` is
`f"m18_7_{kind}_{turn_index}"`. M20.4 reuses this
`commit_id` as the `ActiveCommitment.source_ref` to keep

## DECIDED Design Questions (locked 2026-06-07)

1. **DECIDED: `addressee_hypothesis` is OPTIONAL.** The LLM
   may omit the field for low-confidence cases. Empty (`{}`)
   is a first-class answer, not an error. The M18.5 reply
   policy falls back to its structural-only path when the
   field is empty, and the M20.4 settler sees a sparser
   signal. This matches the M20.3 `correcting_assistant_identity`
   pattern (DECIDED 6) and avoids forcing the LLM to fabricate
   a low-confidence guess for the brief-interjection class
   of turns (see §Hard Rules §2 for the semantic-category
   description; the M18.7 prompt does NOT use any specific
   Chinese character or word as a cue).

2. **DECIDED: M18.5 reply policy does NOT consume the new
   fields in M18.7.** M18.5 keeps its structural-only path
   and zero behavior change. The tie-breaker behavior is
   M20.4 territory, not M18.7. If a future M18.5.1 / M18.7.2
   patch adds a high-confidence (>0.85) tie-breaker path
   (only when structural is ambiguous), it is gated on
   M18.7.1 calibration success. The semantic hypothesis
   NEVER overrides explicit mention / reply-to / quote
   structure, regardless of confidence.

3. **DECIDED: `alternative_hypotheses` /
   `alternative_attributions` carry ABSOLUTE confidence**
   (independent intervals per alternative). The LLM is the
   source of the unclamped value; engineering clamps each
   alternative to `[0.0, 1.0]` and does NOT renormalize. If
   M18.7.1 calibration shows the absolute scale is unreliable,
   M18.7.1 may add a renormalization pass; that is a
   calibration-time concern, not a v1 schema concern.

4. **DECIDED: `evidence_refs` is SHAPE-VALIDATED, NOT
   ENUMERATED.** Engineering validates the prefix pattern
   (`turn_<digits>_*`, `bus_event_<uuid>`,
   `participant_<id>`) but does not enumerate the suffix
   values. The M18.6 acceptance harness verifies the LLM
   does not invent nonsense handles. Shape validation is
   consistent with the M20 turn-local-ref convention and
   avoids brittle suffix-locks.

5. **DECIDED: `state["m18_7_attribution_hypotheses"]` is
   FIXED at 8 entries** (rolling window). Rationale: 8 is
   conservative for group-chat attribution (the underlying
   `recent_action_trace` cap is 32; 8 covers the LLM's
   plausible attribution horizon). A future M18.7.1 may
   revise the cap based on calibration data, but v1 ships
   fixed at 8 for predictability with the rest of the
   bounded audit surface.
