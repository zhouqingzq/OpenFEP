# M18.7.2 — M18.7 Minimal-Prompt Call Site (Fix 2)

## Status

**landed** (commit on `feature/m18-7-2-minimal-prompt` branch).
Acceptance: real-LLM replay of `tests/fixtures/m18_7_1_held_out_calibration.json`
via `scripts/run_m18_7_1_real_llm_calibration.py` produces
non-empty `m18_7_attribution_hypotheses` surface and real (non-degenerate)
ECE / Brier values.

## Why this milestone exists

M18.7.1 P0 real-LLM replay (commits `b13f07f` / `b969d8e`,
`reports/m18_7_1_calibration_summary.md`,
`tmp_m18_7_1_model_swap_findings.md` on
`report/m18-7-1-model-swap-findings`) confirmed a hard blocker:
in the 7.7KB-26KB conscious-loop user prompt, the M18.7 v2 attrs
segment sits at char 2914 (37.7%), after the main 60+ field JSON
schema. Real LLM (v4-flash AND v4-pro, both 12/12 attempts)
emits 0 non-empty M18.7 fills. The M20.4 producer returns `[]`
because the surface is empty (m20_4_attribution.py:503), so the
downstream M20.4.1 same-turn gate / settler / grader is a
**dead path** end-to-end.

M18.7.1 is the calibration analysis layer. It correctly stayed
out of the conscious-loop prompt — moving / removing the v2 attrs
segment is M18.7 territory. **M18.7.2 is that fix**: a dedicated
minimal-prompt LLM call site for M18.7 addressee / reaction
attribution, decoupled from the conscious loop, with the
conscious-loop's M18.7 v2 attrs segment removed. The M18.7.1
calibration runner reads the same
`state["m18_7_attribution_hypotheses"]` surface and produces
real ECE / Brier for the first time after M18.7.2 lands.

## Scope (FROZEN — D1–D11 in plan)

### 1. New minimal-prompt builder

`build_m18_7_minimal_prompt(...)` lives in
`m18_7_attribution.py`. Pure function, no I/O. ~1.5-2.0k char
system+user prompt; 4-key JSON spec
(`addressee_hypothesis`, `reaction_attribution_hypothesis`,
`reasoning_notes`, `_m18_7_2_source`).

Inputs (small subset of state):

- `state["self_basic_facts"]` (persona name only)
- last 2-3 `UserUtteranceEvent` entries from the bus (structural
  fields only — no raw text)
- `entity_binding` (current_interlocutor, aliases)
- `group_turn_binding` (current_speaker, addressed_participant_ids,
  mentioned_participant_ids, ambiguity_band)
- `m18_5_structural_decision`

Conscious-loop coupling (M13 / M19 / pending_expectations /
open_items / etc.) is intentionally absent.

### 2. New LLM call site in `run_turn`

Inserted between the M18.5 reply-policy decision and the
conscious loop. Stage string `"m18_7_2_minimal"`, registered
in `_AUXILIARY_LLM_STAGES` (12s timeout, 0 retries). Skipped
when `bounded_group_turn` is empty (non-group turns don't
need addressee / reaction attribution).

### 3. Conscious-loop prompt cleanup

The M18.7 v2 attrs segment is removed from
`build_conscious_loop_prompt` (~1.5KB removed). The
conscious loop no longer requests the M18.7 fields. M18.7.2
is the sole source.

### 4. State surface: REUSE `state["m18_7_attribution_hypotheses"]`

The M18.7.2 minimal fill writes to the **same** surface via
a new orchestrator `emit_m18_7_2_attribution_for_turn` that
reuses `normalize_addressee_hypothesis` /
`normalize_reaction_attribution_hypothesis` /
`build_state_entry` / `record_m18_7_attribution_hypotheses`
unchanged and stamps `source: "m18_7_2_minimal"` on every
entry.

The M20.4 producer, M20.4.1 same-turn gate, and M18.7.1
calibration runner read the same surface and "just work"
once M18.7.2 populates it. The dead path comes alive
end-to-end.

`commit_id` is the same SHA-1 of (kind, turn_index, source_ref)
that the conscious-loop path would produce
(`source_ref = f"m18_7_{kind}_{turn_index}"`); the
`source: "m18_7_2_minimal"` field on the state entry is
the new distinguishability lever.

### 5. Error handling: M12-pre pattern

`try` / `except` fallback to empty `{}` for both M18.7
fields; emit `M18_7_2_MinimalDegraded` bus event with the
failure reason. `run_turn` does NOT crash on M18.7.2
failures (this is the same pattern M12-pre uses for
degraded LLM calls).

### 6. Bus event types

Three new bus event builders, all sharing
`M18_7_ENGINEERING_PROXY_LABEL`:

- `M18_7_2_AddresseeHypothesisAdmitted` (envelope shape
  mirrors M18.7's `AddresseeHypothesisAdmitted` + a
  `source: "m18_7_2_minimal"` stamp)
- `M18_7_2_ReactionAttributionHypothesisAdmitted` (same
  pattern for the reaction field)
- `M18_7_2_MinimalDegraded` (failure envelope, no payload
  field, carries the `reason` string + the frozen
  `m18_7_2_minimal_llm_failure` reason_code)

  M20.4 reads `m18_7_attribution_hypotheses`; M18.7.2 writes
  into it; no M20.4 code changes.

  / report**. The calibration runner stays unchanged —
  M18.7.2's success is that it can produce real numbers.
- **Does not revise M18.6 attribution held-out acceptance**.
  M18.6 acceptance depends on M18.7 producing non-empty
  hypotheses; M18.7.2 enables that. M18.6 follow-up is M18.6
  territory.
- **Does not run the full test suite**. Per CLAUDE.md red
  line, only targeted subsets are run.
- **Does not touch Path A / M10 / `conversation_loop.py`**.

## Acceptance Criteria

M18.7.2 is complete when:

1. `build_m18_7_minimal_prompt` exists, returns `<=2k char`
   system+user prompt combined, includes only the M18.7 v1
   schema + the 4-key JSON spec.
2. `run_turn` calls the new stage `"m18_7_2_minimal"` between
   the M18.5 decision and the conscious loop, with try/except
   fallback that does not crash `run_turn`.
3. `state["m18_7_attribution_hypotheses"]` is populated by
   the M18.7.2 minimal call on >50% of fixture turns
   (real-LLM replay verification step 3).
4. `build_conscious_loop_prompt` no longer contains the M18.7
   v2 attrs segment. Conscious-loop LLM receives no M18.7
   request.
5. M18.7.1 calibration runner produces real (non-zero) ECE /
   Brier / accuracy on the held-out fixture.
6. M20.4 producer, M20.4.1 same-turn gate, settler all see
   the M18.7.2 fill end-to-end.
7. All existing tests pass (zero regression on M18.7 /
   M18.7.1 / M20.3 / M20.4 / M20.4.1 / M18.6).
8. New work prompt at `prompts/M18.7.2_Work_Prompt.md`
   exists; `prompts/README.md` references M18.7.2.
