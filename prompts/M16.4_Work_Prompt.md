# OpenFEP M16.4 Work Prompt

## Milestone

M16.4: TypeScript TUI Client And Streamlit Deprecation

## Goal

Add an operator-facing terminal client on the same SDK and formally retire
Streamlit as a cognition scheduler for Path B.

After M16.4:

```text
Engineers use ui/tui for daily debugging and scripted sessions.
Demo users use ui/web.
Streamlit app.py remains optional legacy surface only.
New Path B orchestration work targets M16 runner/gateway, not app.py reruns.
```

## Architecture Position

```text
ui/tui/
  Node or Bun CLI using @segments/consciousness-client
  ink or plain stdout UI (project choice; prefer minimal deps)

segmentum/dialogue/runtime/app.py
  frozen for orchestration; banner: legacy I/O only

CLAUDE.md + prompts/README.md
  mark Streamlit scheduler paths deprecated
```

TUI responsibilities:

- connect to runner/gateway,
- print live audit tail and suppression codes,
- send user lines from stdin,
- show runner health and band summaries,
- optional commands: `/status`, `/snapshot`, `/debug`, `/quit`.

TUI must not:

- call `run_idle_cognitive_tick` via hidden Python imports,
- spawn its own cognition loop,
- bypass gateway to mutate MVP JSON state files directly except through documented
  API routes.

## Dependencies

Hard:

- M16.1 gateway + runner
- M16.2 SDK
- M16.3 web parity checklist (for feature comparison)

Soft:

- existing `diagnose_idle_reflection.py` output shape (display only)

## Non-Goals

- Do not delete Streamlit in M16.4; deprecate and freeze orchestration hooks.
- Do not rebuild persona manager UI in TUI.
- Do not add ncurses-level complexity unless needed for basic usability.
- Do not implement remote deployment/auth.

### 2. Streamlit Deprecation Pass

Update:

```text
segmentum/dialogue/runtime/app.py
segmentum/dialogue/runtime/m14_4_implicit_idle.py (comments + guard)
prompts/M14.4_Work_Prompt.md (add deprecation note at top, do not rewrite history)
CLAUDE.md
prompts/README.md
```

Required code changes in `app.py`:

- remove or gate implicit idle proactive scheduling behind explicit legacy flag
  default **off**; it may run only when
  `SEGMENTS_LEGACY_STREAMLIT_SCHEDULER=1` and runner mode is not active,
- show startup banner pointing to `ui/web` and `ui/tui`,
- stop calling `maybe_run_idle_introspection` on rerun when runner mode enabled,
- keep chat send path available as legacy adapter that appends environment events
  if dual-run period is needed; document the dual-run window.

Add env contract:

```text
SEGMENTS_CONSCIOUSNESS_GATEWAY_URL=http://127.0.0.1:8765
SEGMENTS_LEGACY_STREAMLIT_SCHEDULER=0   # default after M16.4
M16_RUNNER=1                            # disables Streamlit scheduling
```

If both `M16_RUNNER=1` and `SEGMENTS_LEGACY_STREAMLIT_SCHEDULER=1` are set,
runner mode wins and Streamlit must not schedule cognition. This prevents
accidental dual loops.

## Acceptance Criteria

M16.4 is complete when:

1. TUI can operate a session end-to-end via M16 gateway with Streamlit closed.
2. TUI displays audit/suppression streams without local cognition code.
3. Streamlit no longer schedules idle/proactive ticks by default.
4. Migration guide and parity matrix exist.
5. CLAUDE.md states Streamlit is legacy I/O, not Path B orchestrator.
6. All new tests pass.
7. Dual-run scheduler conflicts are guarded by tests.
8. Path A and M10 remain untouched.

## Roadmap Note

Post-M16 work should treat these as stable seams:

```text
Perception: M16 HTTP/WS + M14.2 event store
Orchestration: ConsciousnessRunner
Actuation: WS actuation events + M13.3 delivery
Legacy UI: Streamlit adapter only
```

Future milestones (M17+) may add hosted deployment, auth, and persona admin UI
without moving cognition back into the frontend.
