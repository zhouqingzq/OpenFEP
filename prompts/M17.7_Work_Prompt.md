# OpenFEP M17.7 Work Prompt

## Milestone

M17.7: Surprise-Gated Reconsolidation

## Goal

Make reconsolidation depend on reuse-time surprise rather than on recall alone.

Target contract:

```text
memory is retrieved and reused
  -> compare recalled prior with current observation / later outcome
  -> low surprise: reinforce access only
  -> medium surprise: rebind context
  -> high surprise or contradiction: reconstruct or mark conflict
```

The milestone principle is:

```text
recall is not enough
surprising reuse is the gate
```

This moves the runtime closer to the idea that memory is a reusable adaptive
path, not just a stored past event that is rewritten whenever touched.

## Architecture Position

```text
retrieval / recall artifact
  -> reuse event
  -> reuse surprise assessment
  -> bounded reconsolidation gate
  -> reinforcement / contextual rebinding / structural reconstruction
```

Recommended landing points:

```text
segmentum/memory_consolidation.py
segmentum/memory_store.py
segmentum/memory_retrieval.py
segmentum/agent.py
```

Recommended owner split:

```text
RecallOwner                 -> retrieval and recall artifact
ReuseSurpriseOwner          -> computes reuse mismatch
ReconsolidationOwner        -> chooses update type
MemoryStore                 -> persists versioned update and audit
```

## Dependencies

Hard:

- M17.5 canonical FE / error vocabulary
- M17.6 verification-to-memory credit linkage
- Existing reconsolidation and recall artifact surfaces

Soft:

- Existing contradiction and confidence metadata
- Existing sleep consolidation outputs

## Non-Goals

- Do not make every retrieval mutate content.
- Do not let context rebinding silently overwrite source conflicts.
- Do not use free-form LLM rewriting as the first-line reconsolidation path.
- Do not collapse reinforcement, rebinding, and reconstruction into one score.
- Do not touch Path A or M10.

## Required Work

### 1. Add a reuse-event contract

Define a bounded reuse payload such as:

```text
MemoryReuseEvent:
  memory_id
  path_id
  prediction_before_reuse
  observation_after_reuse
  reuse_prediction_error
  reuse_free_energy_delta
  recall_confidence
  contradiction_detected
```

Rules:

- This event is about reuse in a live task or replayed task, not mere
  background access.
- It must be computable without an LLM.
- The same reuse event must not trigger multiple structural rewrites.

### 2. Add bounded reconsolidation gates

Introduce explicit bands such as:

```text
low surprise       -> reinforcement_only
medium surprise    -> contextual_rebinding
high surprise      -> structural_reconstruction
explicit conflict  -> conflict_marking
```

Thresholds must be constants, documented, and tested.

Requirements:

- Low surprise retrieval increases accessibility / trace strength but does not
  rewrite core content.
- Medium surprise may update context tags, mood tags, or bounded execution
  context.
- High surprise or contradiction may create a new version, shadow entry, or
  explicit conflict record.

### 3. Protect identity-critical and source-critical memories

Reconstruction must be harder, not easier, when memory is:

```text
identity-critical
commitment-critical
high source-conflict sensitivity
```

Low-trust evidence must not casually rewrite such entries.

### 4. Version and audit structural change

If content or structural anchors change, the system must preserve:

```text
previous_version_id
triggering reuse event
reuse surprise level
changed fields
reason code
```

Silent in-place rewriting is not acceptable for structural changes.

### 5. Feed surprise-gated reconsolidation into later retrieval

The updated entry must affect later use in bounded ways:

- reinforced memories become more accessible
- context-rebound memories become easier to retrieve in the new context
- conflict-marked memories stop dominating as if nothing happened

### 6. Add negative controls

Tests must prove:

- repeated low-surprise retrieval does not rewrite content
- context-only shifts do not get treated as deep contradiction
- high-surprise contradiction does trigger a stronger update path

## Acceptance Criteria

M17.7 is complete when:

1. Reconsolidation is gated by reuse-time surprise or contradiction, not by
   recall alone.
2. The runtime distinguishes reinforcement-only, contextual rebinding,
   structural reconstruction, and conflict marking.
3. Low-surprise repeated use strengthens access without rewriting content.
4. High-surprise or contradicted reuse produces a versioned or explicitly
   audited stronger update path.
5. Identity-critical or source-sensitive memories are harder to rewrite than
   ordinary entries.
6. Later retrieval behavior reflects the reconsolidation outcome.
7. Path A and M10 remain untouched.
