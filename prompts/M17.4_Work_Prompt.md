# OpenFEP M17.4 Work Prompt

## Milestone

M17.4: Bundle Evidence Aggregation And Anti-TopK Decision Policy

## Goal

Make at least one bounded Path B decision class genuinely depend on the
conjunction of multiple weak memories rather than on a better-ranked single
memory.

Target contract:

```text
coarse recall produces several individually sub-threshold memories
-> deterministic bundle assembler groups a bounded subset by shared target/evidence
-> bundle support crosses threshold only in combination
-> best single member remains below single-trigger threshold
-> downstream memory/reply policy may change
```

If the same decision can be explained by one dominant memory, the system must
audit it as top-k-equivalent rather than claiming new behavior.

The purpose of M17.4 is not to add more weights to row ranking. It is to add a
named owner for bundle-level evidence aggregation, counterfactual best-single
comparison, and bounded downstream use.

## Architecture Position

```text
M14.7 scored recall candidates
  -> M17.4 bundle assembler
  -> bundle decision gate
  -> bounded downstream consumers
     - memory retention / revision candidate
     - consolidation candidate
     - reply-policy bias input
  -> counterfactual audit event with best-single comparison
  -> M17.3 replay verifies that bundle-required decisions are real
```

Recommended new modules:

```text
segmentum/dialogue/runtime/m17_bundle_policy.py
segmentum/dialogue/runtime/m17_bundle_features.py
```

State ownership:

```text
M14.7 recall scoring owner         -> per-row coarse retrieval only
M17.4 bundle policy owner          -> grouping, bundle scoring, counterfactual tests
M17.2 calibration owner            -> measured signals and bundle sidecar factors
M13/M14/M15 downstream owners      -> consume bounded bundle summaries, not raw bundle internals
```

## Dependencies

Hard:

- M14.7 scored recall candidate surface
- M17.2 bundle-ready support factors and linked prediction ids
- M17.3 replay harness with best-single baseline
- M13.6 / M14.0 / M14.7 / M15.x downstream policy hooks

Soft:

- Existing episode/evidence linkage
- Existing reply-policy bias channels

First-version constants must be explicit rather than left entirely to
implementation taste. Recommended conservative defaults:

```text
SINGLE_TRIGGER_THRESHOLD = 0.60
BUNDLE_TRIGGER_THRESHOLD = 0.74
MIN_SYNERGY_MARGIN = 0.12
MAX_BUNDLE_SIZE = 4
REDUNDANCY_PENALTY_FLOOR = 0.10
```

If implementation chooses different defaults, it must document them and M17.3
must include them in the parameter sensitivity summary.

## Non-Goals

- Do not perform unbounded graph search or free-form semantic clustering.
- Do not let the LLM invent bundle membership or bundle scores.
- Do not claim a bundle win when duplicate evidence or near-duplicate memories
  are the only reason the aggregate crossed threshold.
- Do not bypass M13.3 safety, M13.6 gating, M14.7 MemoryGate ownership, or
  M15 consolidation ownership.
- Do not treat "more retrieved rows" as proof of a bundle decision.
- Do not introduce Path A or M10 dependencies.

## Required Work

### 1. Add bundle input surface

Consume bounded `ScoredRecallCandidate` rows and M17.2 sidecar factors:

```text
ScoredMemoryEvidence:
  memory_id
  prediction_ids
  expectation_ids
  episode_ids
  evidence_refs
  item_support
  factor_breakdown
  contradiction_risk
```

Rules:

- Input is limited to a bounded top-N coarse retrieval set.
- The bundle owner may only use structured linkage fields plus deterministic
  factor math; no raw-text keyword heuristics.
- Input rows without concrete linkage may remain available for ordinary recall
  but are ineligible for bundle-required decisions.
- First-version implementation should expose a small diagnostic count of rows
  that were retrieval-eligible but not bundle-linkable so replay can measure
  whether linkage density is the real blocker.

### 2. Build deterministic bundles

Add:

```text
assemble_memory_evidence_bundles(...)
```

Output shape:

```text
MemoryEvidenceBundle:
  bundle_id
  member_memory_ids
  member_evidence_refs
  shared_target_kind
  aggregated_support
  max_single_support
  synergy_margin
  redundancy_penalty
  contradiction_penalty
  unique_memory_count
  unique_evidence_ref_count
  bundle_required
```

Assembly rules:

- Bundle size is bounded, for example 2-4 members.
- Members must share a structured target such as prediction id, expectation id,
  episode lineage, or bounded reply-policy target.
- Duplicate evidence refs and near-duplicate content incur a redundancy penalty.
- Contradictory members cannot silently average out; contradiction penalty must
  suppress or reject the bundle.
- `synergy_margin` must remain positive after redundancy and contradiction
  penalties, not before them.
- `bundle_required = true` only when:

```text
aggregated_support >= BUNDLE_TRIGGER_THRESHOLD
max_single_support < SINGLE_TRIGGER_THRESHOLD
synergy_margin >= MIN_SYNERGY_MARGIN
unique_memory_count >= 2
unique_evidence_ref_count >= 2
```

### 3. Add a bundle decision gate

Add:

```text
evaluate_bundle_decision(bundle, consumer_kind) -> BundleDecision
```

Output:

```text
BundleDecision:
  commit: bool
  consumer_kind
  bundle_id
  bundle_required
  aggregated_support
  max_single_support
  synergy_margin
  trigger_threshold
  best_single_counterfactual_would_trigger: bool
  violation_codes
```

Allowed consumer kinds in first version:

```text
memory_revision_candidate
memory_consolidation_candidate
reply_policy_bias
```

No consumer may fire a bundle-required path unless
`best_single_counterfactual_would_trigger == false`.

The first implementation must make `reply_policy_bias` the default reachable
consumer on the ordinary M16 runner path. A hidden test-only or debug-only
bundle consumer is not enough to claim that the product gained this behavior.

### 4. Emit counterfactual audit events

Required events:

```text
BundleDecisionEvent
BundleDecisionSuppressedEvent
```

Fields:

```text
bundle_id
member_memory_ids
aggregated_support
max_single_support
synergy_margin
best_single_memory_id
best_single_support
best_single_counterfactual_would_trigger
consumer_kind
reason_codes
engineering_proxy_label = "mvp_local_bundle_policy"
```

If a decision would still happen under the best-single counterfactual, emit a
suppressed/top-k-equivalent audit event rather than silently counting it as a
bundle success.

### 5. Wire bounded downstream consumers

First-version integrations:

- M14.7/M13.6 may read bundle summaries for eligibility and reply-angle bias,
  but only through compact bundle ids and factor fields.
- M15 consolidation may consume `memory_consolidation_candidate` bundle
  decisions.
- M17.2/M15 episode addenda record the chosen bundle ids and member ids.

First shipped order:

1. `reply_policy_bias`
2. `memory_consolidation_candidate`
3. `memory_revision_candidate`

The prompt-safe / diagnostic boundary stays strict: downstream prompts may see a
compact bundle summary, not arbitrary raw member text dumps.

## Acceptance Criteria

M17.4 is complete when:

1. There is a named bundle policy owner separate from M14.7 row scoring.
2. A bounded deterministic bundle can trigger a downstream decision even when
   every single member remains below the single-trigger threshold.
3. Duplicate evidence and near-duplicate memories cannot fake a bundle win.
4. Every bundle-triggered decision emits best-single counterfactual audit data.
5. Top-k-equivalent cases are explicitly suppressed or labeled rather than
   counted as bundle-required behavior.
6. `reply_policy_bias` uses bundle-required decisions in the ordinary runner
   path without a debug-only switch.
7. At least one additional downstream consumer is specified or stubbed behind a
   bounded owner contract, even if not enabled by default yet.
8. New tests pass and existing M14.7/M17.x tests continue to pass.
9. Path A and M10 remain untouched.

## Verification Standard

Use one fixture where:

```text
three weak memories each support the same repair bias
each item_support < SINGLE_TRIGGER_THRESHOLD
the bundle crosses BUNDLE_TRIGGER_THRESHOLD
best single counterfactual would not trigger
```

Expected:

```text
bundle_required == true
commit == true
best_single_counterfactual_would_trigger == false
```

Use a second fixture where one memory alone is already strong enough.

Expected:

```text
bundle_required == false
top-k-equivalent suppression/audit is emitted
```
