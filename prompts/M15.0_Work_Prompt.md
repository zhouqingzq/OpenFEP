# OpenFEP M15.0 Work Prompt

## Milestone

M15.0: Episode Ledger And Free-Energy Proxy Trajectory

## Goal

The Path B runtime today computes several local free-energy and
prediction-error proxies (sharing `net_free_energy_reduction`, M13.6
`f_memory` and `efe_by_policy`, M13.2 `prediction_error_proxy`,
expectation `confirmed/violated/uncertain`). None of them are persisted
as a **per-turn trajectory** that downstream modules can read. As a
result:

- The system cannot answer "has this `(state_fingerprint, action)`
  path historically lowered free energy?"
- M13 action pull and habit precision update from immediate post-turn
  signals only; they do not learn from longer-horizon proxy changes.
- Memory-EFE selection is recomputed each turn but its history is not
  searchable by later milestones (M15.1 consolidation, M15.2 meta).

M15.0 adds a small, append-only **episode ledger** that stores the
state-action-outcome path with its free-energy proxy before/after and
the resulting ΔF proxy, plus the gate factors that decided whether any
memory write happened.

Target structure per record:

```text
MemoryDynamicsEpisode
  episode_id
  at, turn_index, phase           # "user_turn" | "proactive_turn" | "idle_tick"
  state_fingerprint               # compact deterministic hash of selected fields
  action                          # "answer" | "ask_question" | "clarify" | "empathize"
                                  # | "proactive_outreach" | "idle_reflect" | "idle_wait"
  action_trigger                  # e.g. "memory_efe_outreach", "user_message", ...
  evidence_refs                   # bound memory ids used this episode
  fe_proxy_before                 # aggregate scalar from local proxies
  fe_proxy_after                  # same aggregation post-outcome
  delta_fe_proxy                  # after - before; negative = improved
  components_before / after:
    sharing_fe
    memory_efe_f_memory
    reward_net_proxy
    expectation_prediction_error_proxy
    self_consistency_proxy
  memory_gate_decision            # commit/rejected + write_score + factors (M14.7)
  outcome_summary                 # short stance string ("confirmed" | "violated" |
                                  #   "uncertain" | "settled" | "ignored")
  engineering_proxy_label = "mvp_local_episode_ledger"
```

The ledger is the **single canonical place** later milestones go to ask
"what happened" — not the conversation log alone.

## Architecture Position

```text
run_turn (user / proactive)        ──► writes 1 episode
run_idle_cognitive_tick (M13.5)    ──► writes 1 episode (action="idle_wait" or "idle_reflect")
post-turn settlement (M13.2)       ──► updates outcome_summary on prior episode

segmentum/dialogue/runtime/m15_episode_ledger.py     (NEW: ledger owner)
segmentum/dialogue/runtime/mvp_loop.py               (write episode records)
segmentum/dialogue/runtime/m13_drive.py              (read ledger for action pull)
segmentum/dialogue/runtime/m13_memory_efe.py         (read ledger for outreach margin)
```

State persistence: append-only `memory_dynamics_episodes.jsonl` per session.
A rolling in-memory cache holds the last N episodes (default 64) for fast
read by M13 owners. Long-tail reads go to the JSONL file.

## Dependencies

Hard:

- M14.7 memory gate + recall scoring (factors must be inspectable per write)
- M13.2 reward proxy + `prediction_error_proxy`
- M13.6 memory EFE (`f_memory`, `efe_by_policy`)
- Existing sharing FE (`build_memory_dynamics_guidance`)
- M13.5 idle cognitive tick (provides idle episode hook)

Soft:

- M14.0 reflector (read-only consumer; later milestone)
- M14.6 alignment events (read-only consumer)

## Non-Goals

- Do not implement a unified variational free-energy engine. The ledger
  aggregates **existing proxies**. New proxy sources may be added later
  via M15.x sub-milestones; M15.0 ships with the listed five components.
- Do not introduce subjective wording. ΔF is an engineering scalar; it
  must not be rendered as "胡桃 felt better/worse". Diagnostics may say
  "free-energy proxy decreased / increased".
- Do not change how M14.7 gate computes write_score. M15.0 only records
  the decision the gate returned.
- Do not retro-fill historical sessions. The ledger starts empty per
  session created post-M15.0; old sessions read empty and remain valid.
- Do not store full memory content or full reply text in episodes; use
  ids, short stance fields, and bounded summaries.
- Do not extend Path A or M10.

## Required Work

### 1. State fingerprint

`state_fingerprint` is a deterministic compact hash over a fixed field set,
**not** the full state JSON. Fields:

```text
last_user_turn_index
last_assistant_turn_index
open_items_concrete_count
unsettled_pending_settlement_count
boredom_band
reward_band
behavior_band
relation_band
memory_efe.should_outreach
memory_efe.selected_policy
top_3_traction_actions (sorted)
top_3_bound_memory_ids (sorted)
```

Serialize, sort keys, sha256 first 16 chars. This is a fingerprint, not a
state snapshot. Two episodes with identical fingerprints describe the same
structural situation (drives + outstanding state).

### 2. Component aggregation

`fe_proxy_before` / `fe_proxy_after` are weighted sums (default weights
fixed; weights live with M15.0 constants, not configurable per session):

```text
sharing_fe                          weight 0.20
memory_efe_f_memory                 weight 0.25
reward_net_proxy (sign inverted)    weight 0.20   # higher reward = lower F
expectation_prediction_error_proxy  weight 0.20
self_consistency_proxy              weight 0.15
```

`self_consistency_proxy` is a small new scalar derived **only** from existing
M12.0/M12.1 outputs (identity tension count, known-limit overlap), exposed
read-only via a helper. If the consumer can't compute it, default to 0; do
not block M15.0 on M12.1 completeness.

ΔF = after - before. Negative ΔF = improved.

### 3. Episode write hooks

In `run_turn` (user turn):

```text
before generation:
  fe_before = aggregate(components_at_pre_act)
emit reply / patches
after settlement helpers:
  fe_after = aggregate(components_at_post_act)
  episode = build_episode(...)
  ledger.append(episode)
  emit MemoryDynamicsEpisodeEvent
```

In `run_proactive_turn`:

```text
fe_before captured from idle tick snapshot
fe_after captured after delivery / suppression decision
ledger.append (action = "proactive_outreach"; outcome_summary uses
  "settled" only if delivered or "ignored" if suppressed pre-generation;
  "violated" reserved for assessor reject after generation)
```

In `run_idle_cognitive_tick` (M13.5):

```text
fe_before captured at start of tick
fe_after captured at end of tick
action = "idle_wait" (default) or "idle_reflect" if M14.0 plan ran
outcome_summary = "settled" if select_proactive_target returned a target,
                   else "ignored"
```

Cross-turn settlement (M13.2): when the assessor settles a prior pending
on the next user turn, the runtime must **update the prior episode's
`outcome_summary` and `fe_proxy_after`**, then re-emit a delta event:

```text
MemoryDynamicsEpisodeSettledEvent
  episode_id
  new_outcome_summary
  delta_fe_proxy_revised
```

Episodes themselves remain append-only; the settled event is an addendum.

### 4. Ledger storage

```text
artifacts/<persona>/sessions/<session>/memory_dynamics_episodes.jsonl
```

Append-only, one JSON object per line. Rolling in-memory cache:

```text
EpisodeLedger:
  append(episode)
  recent(n) -> list[Episode]
  by_fingerprint(state_fingerprint) -> list[Episode]   # latest first, capped
  by_action(action, *, limit=16) -> list[Episode]
  search(action_trigger, *, limit=16) -> list[Episode]
```

File reads stream line by line and stop at `limit`. No global index file
required; a small in-memory tail cache + on-demand stream is enough at
this milestone.

### 5. Consumers (read-only in M15.0)

**M13 action pull (m13_drive.py):**

```text
For each candidate action a, look up recent episodes where
  state_fingerprint matches current and action == a (or near-match).
Apply small adjustment to behavioral_pull:
  bonus = clamp(-0.1, mean(-delta_fe_proxy) * 0.2, +0.1)
This bonus is **additive on top of existing pull**, not a replacement.
```

**M13.6 outreach margin (m13_memory_efe.py):**

```text
For action_trigger == "memory_efe_outreach", look up last K episodes
with the same action_trigger. If mean delta_fe_proxy > 0 (outreach made
things worse on average), raise outreach margin by a small bounded delta
so future outreach must show stronger F_memory pressure.
```

Both consumers are bounded adjustments; they must not override safety,
delivery assessor, or session caps.

### 6. UI surface (diagnostics only)

In the mind panel, add a compact "ΔF trail" block showing the last 5
episodes:

```text
turn 28  proactive_outreach     ΔF = +0.04  outcome = violated
turn 27  idle_wait              ΔF = +0.00  outcome = ignored
turn 26  answer                 ΔF = -0.12  outcome = confirmed
...
```

No subjective wording. No raw reply text in this block.

## Acceptance Criteria

M15.0 is complete when:

1. Every user turn, proactive turn, and idle cognitive tick produces
   exactly one `MemoryDynamicsEpisode` record with the listed components,
   action, evidence_refs, gate decision, and ΔF proxy.
2. Cross-turn settlement emits an addendum event that revises the prior
   episode's `outcome_summary` and `fe_proxy_after`; the jsonl record
   itself is not mutated.
3. `state_fingerprint` is deterministic and changes only when the listed
   structural fields change.
4. M13 action pull and M13.6 outreach margin read ledger history with
   bounded, clamped adjustments; safety/cooldown/assessor gates remain
   authoritative.
5. The ledger file is append-only JSONL; in-memory cache returns recent
   episodes without scanning the whole file.
6. Diagnostics block renders a compact ΔF trail without subjective
   wording or raw reply text.
7. No new LLM call is introduced. No variational engine is implemented.
8. No write to M11/M12 ledgers from M15.0 modules.
9. All listed tests pass; previously green M9/M13/M14 tests still pass.
