## Milestone

M18.7.1: Held-Out Calibration For LLM Confidence — runs the
new semantic fixture through the M18.7 conscious-loop pipeline,
computes reliability bins / ECE / Brier / accuracy, surfaces
`state["m18_7_1_calibration"]` with drift signals + threshold
recommendation, and reports the LLM's calibration drift.

## Goal

Close the calibration gap that M18.7's structured fields
opened. M18.7 ships a schema + prompt + normalize + audit +
state surface, but says nothing about whether the LLM's
self-rated `confidence` actually tracks accuracy. M20.4 v1
locks `M20_4_PRODUCER_ADMIT_CONFIDENCE_MIN = 0.4` and
`M20_4_TIE_BREAKER_CONFIDENCE_MIN = 0.85` with the explicit
caveat:

> Frozen at 0.4 in v1; M18.7.1 calibration may revise.
> Strict inequality; M18.7.1 may revise.

M18.7.1 is the step that resolves whether the v1 thresholds
are well-calibrated or systematically miscalibrated. It
**does not** revise the thresholds; it **does** surface a
recommendation and the diagnostic evidence to support a
revision.

## Why M18.7.1 Exists

The M18.7 prompt instructs the LLM to produce a
self-rated `confidence` per hypothesis. The M20.4 producer
uses that confidence to admit / reject:
`M20_4_PRODUCER_ADMIT_CONFIDENCE_MIN = 0.4` and
`M20_4_TIE_BREAKER_CONFIDENCE_MIN = 0.85`. If the LLM is
systematically over- or under-confident, those thresholds
encode a miscalibration. M18.7 alone (the schema / prompt /
normalize milestone) does not surface the calibration
quality. M18.7.1 does.

Three concrete reasons:

1. **M18.6 fixture is structural-only.** The existing
   `tests/fixtures/m18_held_out_group_chat.json` asserts
   `expected_group_reply_action` and `expected_visible_action`
   for the M18.5 reply policy. It does NOT carry ground
   truth for `addressed_to_assistant` /
   `reaction_to_turn_id`. M18.7.1 must introduce a new
   fixture with semantic ground truth.

2. **M20.4 explicitly reserves the threshold revision hook.**
   The `M20_4_PRODUCER_ADMIT_CONFIDENCE_MIN` /
   `M20_4_TIE_BREAKER_CONFIDENCE_MIN` constants are frozen
   in v1 with the comment "M18.7.1 calibration may revise."
   M18.7.1 is the gating step. Without it, the v1
   thresholds are uncorroborated.

3. **Calibration drift is a diagnosable engineering signal.**
   If the LLM reports `confidence = 0.85` and is right
   60% of the time, the diagnose surface should show that.
   Today, the surface shows only the raw `confidence` —
   no comparison to ground truth, no ECE, no Brier.

## Architecture Position

M18.7.1 is a thin analysis layer. It reads the M18.7
state surface, replays a fixture, and writes a new
calibration surface. It does **not** modify M18.5 / M18.7
/ M20.4 / M20.4.1.

```text
+--------------------------------------------------------+
|  M18.7.1 (this milestone)                             |
|  Tier A: held-out semantic fixture + schema            |
|  Tier B: pure calibration functions + field reports    |
|  Tier C: top-level runner + state surface writer       |
+--------------------------------------------------------+

external group turn (from fixture)
   |
   v
MVPDialogueRuntime.run_turn
   (the LLM is faked in tests; production path is unchanged)
   |

calibrate_addressee_field  (pure)
calibrate_reaction_field   (pure)
   |
   v
CalibrationHarnessReport
   |
   v
record_m18_7_1_calibration

   v
state["m18_7_1_calibration"]
   {
     addressee:   { bins, ECE, Brier, accuracy, drift_signals },
     reaction:    { bins, ECE, Brier, accuracy, drift_signals },
     drift_signals: union of both fields,
     threshold_recommendation: { current_*, candidate_*, caveat }

```

The order matters. The LLM is called once per `run_turn`
(unchanged from M18.7). M18.7.1 only reads the M18.7
state surface after each `run_turn` and feeds the
prediction / ground-truth pair into the pure calibration
functions. Engineering does not call the LLM again. M20.4
is not modified.

## Hard Rules (CLAUDE.md compliance)

1. **The LLM is the only source of `confidence`.** M18.7.1
   does not invent confidences, does not parse rationale
   text, and does not match keywords / regexes in user
   text. The M18.7 prompt is the only legitimate source
   of `confidence`; M18.7.1 reads it from the M18.7 state
   surface.

2. **No regex / keyword matching in the harness.** The
   calibration harness may not parse user text, structural
   cues, or hypothesis rationale. It may match
   `ground_truth` field values to `prediction` field
   values via strict string equality only.

3. **No new LLM call.** M18.7.1 reads the M18.7 state
   surface. It does not add a new LLM stage. The
   `run_m18_7_1_calibration_harness` runner is a thin
   loop over `runtime.run_turn`, identical in spirit to
   the M18.6 acceptance harness loop in
   `tests/test_m18_group_chat_acceptance.py`.

4. **No modification of M20.4 constants.** M18.7.1
   surfaces `candidate_admit_min` and
   `candidate_tie_breaker_min` as data-driven
   recommendations. It NEVER mutates
   `M20_4_PRODUCER_ADMIT_CONFIDENCE_MIN` or
   `M20_4_TIE_BREAKER_CONFIDENCE_MIN`. Decision belongs
   to M20.4.

5. **No modification of M18.5 / M18.7 / M20.4 / M20.4.1
   code paths.** M18.7.1 is additive; it writes only to
   `state["m18_7_1_calibration"]`.

6. **Empty / null / `"unknown"` ground truth is a
   first-class answer, not an error.** The calibration
   harness skips `"unknown"`-marked ground truth without
   penalizing the LLM. A prediction that is empty
   alongside a non-`"unknown"` ground truth IS scored as
   `incorrect` (LLM should have produced a hypothesis).

7. **No user text in the calibration surface.** The
   calibration report persists only:
   - aggregate counts and metrics
   - per-bin mean confidence + accuracy + gap
   - drift signal enum values
   - threshold recommendation (numerical)
   The surface does NOT persist user text, rationale
   text, or the actual hypothesis payload. The state
   surface is observable; free-form LLM text is not.

8. **Path A / M10 / `conversation_loop.py` remain
   untouched.**

## Non-Goals

- **M18.7.1 does not revise M20.4 thresholds.** M18.7.1
  surfaces a candidate threshold; M20.4 owns the decision
  to mutate the constants.
- **M18.7.1 does not modify M18.5 reply policy.** M18.5
  keeps its structural path.
- **M18.7.1 does not modify the M18.7 prompt template or
  normalize contract.** Calibration is an analysis layer,
  not a schema layer. If M18.7.1 finds the LLM is
  systematically miscalibrated, the **prompt** revision is
  M18.7 territory (a future M18.7.x), not M18.7.1.
- **M18.7.1 does not call the LLM.** It reads
  `state["m18_7_attribution_hypotheses"]` after each
  `run_turn`.
- **M18.7.1 does not run a real LLM in acceptance tests.**
  The acceptance gate is the engineering layer (pure
  functions, fixture shape, runner with FakeJSONLLM).
  Real-LLM replay is an extension action, not a gate.
- **M18.7.1 does not touch Path A, M10, or
  `conversation_loop.py`.**
- **M18.7.1 does not retroactively label prior turns.**
  It only analyzes the fixture; it does not write

## Required Work

### 1. Held-out semantic fixture (Tier A)

Create `tests/fixtures/m18_7_1_held_out_calibration.json`.
The fixture is **separate** from
`tests/fixtures/m18_held_out_group_chat.json` (M18.6). M18.6
is structural; M18.7.1 is semantic. They have different
roles and must remain independent per the M18.6 prompt's
§3 "Do not rely only on fixtures tuned during
implementation" rule.

Each step:

```text
{
  "turn_index": 0,                     # int; matches M18.6 fixture style
  "text": "<inbound turn text>",       # str
  "speaker_name": "Carol",             # str
  "group_turn_envelope": { ... },      # dict; same shape as M18.6 fixture
  "expected_group_reply_action": "reply_to_current_speaker",  # optional
  "assertion_kind": "addressee_only|reaction_only|both|neither|probe",
  "ground_truth": {
    "addressed_to_assistant": true | false | "unknown",
    "addressee_participant_id": "<id>" | "unknown" | "",
    "reaction_to_turn_id": "turn_<n>" | "" | "unknown",
    "reaction_to_participant_id": "<id>" | "" | "unknown",
    "is_about_assistant_claim": true | false | "unknown"
  },
  "expected_confidence_band": "low|medium|high",  # design hint
  "note": "<human annotation rationale; not parsed>"
}
```

The `"unknown"` sentinel is explicit: the field is not
applicable / not decidable for this turn. The calibration
harness skips `"unknown"`-marked ground truth fields
without scoring the prediction.

The fixture must include, at minimum:

- 3–4 `addressee_only` turns spanning
  explicit reply-to, implicit continuation,
  general acknowledgement, and side-thread
  interjection
- 1 addressee turn with M18.4 disclosure-forbid
  (LLM should set `participant_id = ""`)
- 2–3 `reaction_only` turns spanning
  reaction to assistant's prior claim,
  reaction to third-party's prior turn, and
  no clear referent
- 1–2 `both` turns (a single turn that is both
  addressed-to-assistant AND a reaction)
- 1 `probe` turn (adversarial: the LLM should leave
  the field empty or report very low confidence)
- Coverage across `low` / `medium` / `high`
  `expected_confidence_band` (so the calibration
  curve has data in at least 4–5 of the 10 bins)

Ground truth is hand-annotated based on the
**semantic categories** described in M18.7 DECIDED 1
(short acknowledgement, side-thread interjection,
implicit continuation, etc.). The `note` field
records the human's reasoning, not the LLM's
text. The engineering layer does not parse the
`note` field — it is documentation only.

#### 2b. Frozen dataclasses

```text
@dataclass(frozen=True)
class BinStats:
    label: str
    count: int
    mean_confidence: float  # 0.0 if count == 0
    accuracy: float         # 0.0 if count == 0
    gap: float              # |accuracy - mean_confidence|; 0.0 if count == 0

@dataclass(frozen=True)
class CalibrationFieldReport:
    n_total: int
    n_present: int
    n_unknown: int
    n_correct: int
    n_incorrect: int
    accuracy: float
    brier: float
    ece: float
    reliability_bins: list[BinStats]
    drift_signals: list[str]
    threshold_recommendation: dict[str, object]

@dataclass(frozen=True)
class CalibrationHarnessReport:
    fixture_name: str
    n_fixtures: int
    addressee: CalibrationFieldReport
    reaction: CalibrationFieldReport
    drift_signals: list[str]   # union of both fields
```

#### 2c. Pure functions

```text
def compute_reliability_bins(
    confidences: list[float], correct_flags: list[bool]
) -> list[BinStats]: ...

def compute_ece(bins: list[BinStats]) -> float: ...

def compute_brier(confidences: list[float], correct_flags: list[bool]) -> float: ...

def compute_accuracy(correct_flags: list[bool]) -> float: ...

def derive_drift_signals(
    bins: list[BinStats], n_present: int,
    *, min_present: int = M18_7_1_MIN_PRESENT_FOR_DRIFT_SIGNAL,
) -> list[str]: ...

def recommend_thresholds(
    bins: list[BinStats],
    *, current_admit_min: float = 0.4,
    current_tie_breaker_min: float = 0.85,
    min_present: int = M18_7_1_MIN_PRESENT_FOR_DRIFT_SIGNAL,
) -> dict[str, object]: ...
```

`compute_ece` follows Guo et al. 2017:

```text
ECE = sum_b (|bin_b| / N) * |acc_b - conf_b|
```

`compute_brier` follows the standard mean squared error
between confidence and 0/1 outcome:

```text
Brier = (1/N) * sum_i (confidence_i - correct_i)^2
```

`derive_drift_signals` returns a list (possibly empty) of
frozen-enum strings:

- `insufficient_data`: `n_present < min_present`
- `overconfidence_at_high_band`: highest-confidence bin
  (≥ 0.80) has `gap > 0.15` AND `accuracy < mean_confidence`
  (LLM claims high confidence but is wrong more often than
  it claims)
- `underconfidence_at_low_band`: lowest-confidence bin
  (≤ 0.40) has `gap > 0.15` AND `accuracy > mean_confidence`
  (LLM is too cautious; predictions are more right than
  they claim)
- `bimodal`: the highest and lowest bins both have
  `count > 0` AND the middle bins are sparse
  (`count == 0` for ≥ 4 of 6 middle bins)
- `flat_curve`: every populated bin has
  `|gap| < 0.10` AND accuracies are similar across bins
  (LLM's confidence is uninformative)

`recommend_thresholds` does not modify any constant. It
returns:

```text
{
  "current_admit_min": 0.4,
  "current_tie_breaker_min": 0.85,
  "candidate_admit_min": float | None,        # None when insufficient_data
  "candidate_tie_breaker_min": float | None,  # None when insufficient_data
  "caveat": "decision belongs to M20.4; M18.7.1 only surfaces"
}
```

The candidate is the **bin boundary** (`{0.1, 0.2, ..., 0.9}`)
closest to the M20.4 threshold that has the smallest
`gap` among populated bins in the same confidence
**neighborhood** (± 0.15 of the threshold). If no
populated bin falls in the neighborhood, the candidate
is `None` (and `insufficient_data` is added to
drift_signals).

#### 2d. Field-specific calibrators

```text
def calibrate_addressee_field(
    predictions: list[AddresseePrediction],
    ground_truth: list[AddresseeGroundTruth],
) -> CalibrationFieldReport: ...

def calibrate_reaction_field(
    predictions: list[ReactionPrediction],
    ground_truth: list[ReactionGroundTruth],
) -> CalibrationFieldReport: ...
```

Outcome rules:

- `addressee`: prediction.addressed_to_assistant ==
  ground_truth.addressed_to_assistant is `correct`.
  prediction is empty AND ground_truth is `"unknown"`
  → skip (n_unknown++).
  prediction is empty AND ground_truth is not `"unknown"`
  → `incorrect` (confidence = 0.0 for Brier / ECE).
  prediction is non-empty AND ground_truth is `"unknown"`
  → skip (n_unknown++).
- `reaction`: prediction.reaction_to_turn_id ==
  ground_truth.reaction_to_turn_id is `correct`.
  Same empty / unknown handling.

String equality is strict. No fuzzy matching, no
normalization beyond the M18.7 normalize contract
(`turn_<digits>_*` shape).

#### 2e. Top-level runner

```text
def run_m18_7_1_calibration_harness(
    *,
    runtime: MVPDialogueRuntime,
    fixture: list[dict],
    fixture_name: str = "<inline>",
    now_base: int = 100000,
    time_step: int = 60,
    at: str = "<iso8601>",
) -> CalibrationHarnessReport: ...
```

The runner:

1. For each step in the fixture, call
   `runtime.run_turn(step["text"], speaker_name=step["speaker_name"],
   turn_index=step["turn_index"], now=now_base + i*time_step,
   group_turn_envelope=step["group_turn_envelope"])`.
2. After each `run_turn`, read
   `runtime.store.load()["m18_7_attribution_hypotheses"][-2:]`
   (the addressee + reaction entries for the most recent
   turn; M18.7 may emit 0, 1, or 2 entries per turn).
3. Build `(AddresseePrediction, AddresseeGroundTruth)` and
   `(ReactionPrediction, ReactionGroundTruth)` pairs.
4. Call `calibrate_addressee_field` and
   `calibrate_reaction_field`.
5. Assemble `CalibrationHarnessReport`.
6. **Do not** write to state; the caller decides.

The runner does not call the LLM. The M18.7 conscious
loop calls the LLM; the runner only observes.

#### 2f. State surface writer

```text
def record_m18_7_1_calibration(
    state: dict, harness_report: CalibrationHarnessReport, *, at: str
) -> None: ...
```

Writes a single dict to
`state["m18_7_1_calibration"]` (overwriting any prior
value). The surface is a one-shot analysis, not a
rolling list. Frozen shape:

```text
{
  "last_run_at": "<iso8601>",
  "fixture_name": str,
  "n_fixtures": int,
  "addressee": CalibrationFieldReport.to_dict(),
  "reaction": CalibrationFieldReport.to_dict(),
  "drift_signals": list[str],   # union of both fields
  "threshold_recommendation": {
    "current_admit_min": 0.4,
    "current_tie_breaker_min": 0.85,
    "candidate_admit_min": float | None,
    "candidate_tie_breaker_min": float | None,
    "caveat": "decision belongs to M20.4; M18.7.1 only surfaces"
  },
  "engineering_proxy_label": "mvp_local_group_attribution_calibration"
}
```

The `caveat` string is **frozen**. M20.4 acceptance
must read this string and not mutate M18.7.1's
recommendation.

### 3. Tests (Tier C)

`tests/test_m18_7_1_calibration.py` covers:

#### Pure-function tests (synthetic data, no LLM)

- Bin assignment correctness across 10 bins
- Boundary handling (`confidence = 1.0` → last bin;
  `confidence = 0.0` → first bin)
- Empty input → all-zero bins
- ECE = 0 for perfectly calibrated
- ECE > 0 for systematic overconfidence
- Brier symmetry (under- and over-confidence at the
  same magnitude give the same Brier)
- Drift signal generation:
  - overconfidence_at_high_band
  - underconfidence_at_low_band
  - bimodal
  - flat_curve
  - insufficient_data
- `recommend_thresholds` returns `None` for both
  candidates when `n_present < min_present`
- `recommend_thresholds` picks the bin boundary
  with the smallest gap in the threshold's
  neighborhood
- `calibrate_addressee_field` skips `"unknown"`
  ground truth
- `calibrate_addressee_field` counts empty prediction
  as `incorrect` (confidence = 0.0) when ground truth
  is non-`"unknown"`
- `calibrate_reaction_field` uses strict string
  equality

#### Fixture shape tests (no LLM)

- Fixture loads, has the required `ground_truth` keys
- Fixture covers `low` / `medium` / `high`
  `expected_confidence_band`
- Fixture includes at least one `probe` turn
- Fixture's `assertion_kind` is one of the frozen enum

#### Integration tests (FakeJSONLLM, no real LLM)

- Runner replays the fixture and returns a
  per-field report
- State surface is written with the frozen shape
- Runner handles the case where M18.7 returns empty
  hypotheses (no crash, `n_present = 0`, drift_signals
  includes `insufficient_data`)
- Threshold recommendation's `caveat` mentions M20.4
- Runner does **not** mutate M20.4 constants
  (sanity: the constants are unchanged after the
  runner returns)
- Drift signals are `insufficient_data` when the
  fixture is too small to fill the bins

## DECIDED Design Questions (locked 2026-06-07)

1. **DECIDED: 10 equal-width bins, width 0.10.** Each bin
   is labeled `0.NN-0.(N+1)0` except the last, which is
   `0.90-1.00`. The bin width is frozen in v1; future
   revisions require a v2 constant. Rationale: ECE is
   most commonly reported with 10–15 bins (Guo et al.
   2017); 10 matches the convention.

2. **DECIDED: M18.7.1 surfaces candidate thresholds;
   M20.4 owns the decision.** M18.7.1 writes
   `candidate_admit_min` and `candidate_tie_breaker_min`
   to the state surface, with the frozen caveat
   `"decision belongs to M20.4; M18.7.1 only surfaces"`.
   M20.4 v1 thresholds are not mutated. Future M20.4
   work may read the candidate and decide; that is
   M20.4's territory.

3. **DECIDED: single dict state surface, NOT a rolling
   list.** The M18.7 surface is a rolling list of ≤ 8
   entries (per-turn audit trail). The M18.7.1 surface
   is a one-shot dict (per-calibration-run analysis).
   The M18.7.1 surface is overwritten on each
   `record_m18_7_1_calibration` call.

4. **DECIDED: ground truth uses `"unknown"` sentinel.**
   The sentinel is a string literal `"unknown"`, not
   `None` and not `""`. The calibration harness skips
   `"unknown"`-marked ground truth fields without
   scoring the prediction. A prediction that is empty
   alongside a non-`"unknown"` ground truth IS scored
   as `incorrect` (LLM should have produced a
   hypothesis).

5. **DECIDED: empty prediction + non-`"unknown"` ground
   truth is `incorrect` with confidence = 0.0.** This
   penalizes the LLM for declining to produce a
   hypothesis when one was decidable. The penalty is
   the same as a confidently-wrong prediction in
   Brier terms (`(0 - 1)^2 = 1.0`).

6. **DECIDED: outcome judgment is strict string
   equality, no fuzzy matching.** `addressed_to_assistant`
   is `bool` equality. `reaction_to_turn_id` is exact
   string equality against the M18.7-normalized shape
   (`turn_<digits>_*`).

7. **DECIDED: ECE follows Guo et al. 2017 definition
   (weighted by bin size, absolute gap).** This is the
   most common ECE definition in the literature; matches
   the segmentum/M17 calibration precedent.

8. **DECIDED: drift signals are a frozen 5-value enum.**
   `overconfidence_at_high_band`,
   `underconfidence_at_low_band`, `bimodal`,
   `flat_curve`, `insufficient_data`. No free-form
   notes. The enum is closed; adding a new signal
   requires a v2 constant.

9. **DECIDED: `M18_7_1_MIN_PRESENT_FOR_DRIFT_SIGNAL = 5`.**
   Below this, all drift signals collapse to
   `insufficient_data`. The number is conservative for
   a fixture of 10–15 turns and matches the M20.4
   "minimum sample for confidence" precedent.
